## 1. 直接回答

1. 可以继续写的 Java，只限已经单独批准且尚未越界的维护。当前没有新的业务 Java 授权。
2. 已有代码是启动核对、契约版本唯一性计数、确认键原文解析、虚构来源与进程内存储、Admin 静态演示清单。新行为不在此列。
3. 从当前 POM 和模块依赖关系静态判断，十个模块都具备对应的 Maven 构建路径。本轮没有执行 Maven，因此不将其记为已验证的编译或测试结果。messaging、transform、quality、writer、pipeline 没有自己的业务实现，不能把空模块写成可运行骨架已经具备业务能力。
4. 已经落地的模拟只有 C1-02 和 C1-08 的 A11-1。它们不是生产能力，也没有运行时许可。
5. 决策调查、物理模型设计和代码实现是三件事。持久化专项设计可以继续，包括已有逻辑身份到物理约束的比较、已有任务与尝试等实体的承载比较，以及事务边界和失败后读取依据的设计准备。未批准模型的 DDL、MySQL 驱动、持久化 Java、Create-or-Get 的生产实现、领取与终态、Pipeline 业务和端到端仍然禁止。任务表和错误记录的定稿必须使用已经正式接受的决策。设计做完也不自动开始实现，更不是 Stage C 已经局部启动。
6. 真实端到端处理链路现在不能启动。IR-19 仍是未执行。06-04-01 第 9 节仍禁止 Pipeline 业务、持久化、Worker 执行和端到端 Java。
7. 最短且仍安全的路径不要求所有物理约束设计都等 IR-03、IR-04 关闭后才开始。R15、P-03、P-06 的决策工作可以并行。IR-03 不能靠设计人员发明通用键来关闭。IR-04 不能靠实现自行选择“失败后跳过快照”。物理模型可以在这些约束下继续调查和比较。任务表、错误记录和物理唯一约束的最终定稿必须使用已经正式接受的决策。实现仍要单独准入。不把三项 C1 接成链路。Pipeline Java 还要另有一份不改写第 9 节的准入。没有日期预测。

Stage B 总结第 8 节写明不再追加 Stage B 实现，Stage C 不能整体启动，也不能做局部代码准备。C1-01、C1-02、C1-08 是后来的独立工程授权，不推翻这两句，也不等于 Stage C 准入。

## 4. 专项

### 工程骨架

十模块、Admin 与 Worker 分离、启动名和角色核对、本地 `./mvnw -B clean verify` 约定，都已经在代码或构建文档中。配置只绑定 `mtx.rdp.role`。没有 profile 时环境标签是未命名，既不是生产，也不是本地模拟许可。

可运行但不接真实业务的模拟，目前只有测试里直接构造的 C1-02，以及不启动应用就能检查的 A11-1。应用进程本身不会创建这些对象。

### 无持久化业务逻辑

Stage B 不再盘点。可以继续维护的是唯一性计数和启动核对。没有新的纯逻辑授权。金额二十项在 06-03-03-11 仍是 `PENDING`，确认之后才可能回到纯逻辑，而不是直接进入 Stage C。

### 消息与来源

Kafka 仍是基线方向，客户端不在模块依赖里。虚构来源只产测试字节。原文保存只存在于 C1-02 对象生命周期内。IR-03 仍是部分确认、待决策：没有稳定事件身份的来源不能建任务，也不能为了继续消费而提交 offset。本评估不设计唯一键。

### Task 与 Worker 执行权

创建、Create-or-Get、领取、接管、行锁、代次、取消、重试和恢复都没有 Java。其中领取规则在 06-04-11 已写明，但仍待验证，且 ADR 未接受。纯逻辑不能代替物理身份、事务和持久化约束。IR-21 的取消发起者未定义，不能把取消写成 Worker 本地标记。

### Pipeline

ADR-0004 已接受方案 C，范围是固定快照内、金额提取之前的版本解析。它不包含表、事务和 Java。`resolve` 只覆盖“唯一或不能解析”，调用方必须已经读完该快照。IR-04 仍待决策：它阻断新任务第一次选择快照，以及显式重放的第一次快照选择。已经带有 `snapshotId` 的原任务重试不改挂快照，这一条不受 IR-04 阻断。失败快照能否跳过，仍不得由实现选定。

字段提取、金额观察、标准化、质量、Doris 写入、失败恢复都没有代码。06-04-01 第 9 节继续阻断这些 Java。P-03 与 P-06 仍是未关闭的错误码归类决策，决定前不落码、不新造错误码。

### Admin 与本地模拟

A11-1 已由静态清单实现。A11-2 与 A13 继续 BLOCKED。C1-01、C1-02、C1-08 独立验收通过。不得把解析结果、内存存储和清单接成运行时链路，也不得用测试夹具绕过这个限制。

### 可观测性与运维

启动日志只记录应用名、角色、环境标签和健康状态。IR-16 未选定指标和追踪。IR-10 未选定审计的物理存储。技术日志不是业务审计。本评估不新增审计实体，也不把日志写成可恢复的审计。

## 7. 与 06-04-01 的差异

[06-04-01](../investigation/round-01/06-04-01%20MTX%20Data%20Platform%20V2%20工程实施就绪度评估报告.md) 第 9 节仍然有效：不能开始金额领域、Pipeline 业务或持久化 Java，不能开始 Worker 领取和执行，不能开始端到端。本文件不宣布该节失效。
