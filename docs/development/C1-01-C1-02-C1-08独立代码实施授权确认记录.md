## 1. C1-01 显式确认键解析

- 授权状态：`APPROVED`
- 授权人：Wayne
- 授权日期：2026-11-28

授权范围：只在 `platform-common` 实现两个确认键的纯文本解析。输入是每个键是否存在，以及存在时未经转换的原始文本。不得先转成 Java `Boolean`、枚举或其他会丢掉原文差异的类型，也不得预先 trim、忽略大小写或做宽松布尔转换。

`mtx.rdp.runtime-mode` 只精确接受 `local-simulation` 与 `production`。键不存在为 `NOT_SET`。空字符串、纯空白、前后空格、大小写变化和别名都是 `INVALID`。

`mtx.rdp.dev-only-acknowledged` 只精确接受 `true` 与 `false`。键不存在按未确认处理。空字符串、纯空白，以及原始文本 `TRUE`、`1`、`yes`、`no`、`0` 和大小写变化都是 `INVALID`。`true` 与 `TRUE` 不是同一个结果。

两个键都合法时，组合结果只按申请第 4 节的表，取 `NOT_CONFIRMED`、`INCOMPLETE`、`ACKNOWLEDGED`、`PRODUCTION_SELF_DECLARED` 或 `CONFLICT`。任一键非法时组合结果是 `INVALID`。只有一个键非法时保留该键的原因。两个键都非法时同时保留两份原因，不能只留下先发现的那一个。`ACKNOWLEDGED` 不是非生产证明，也不是 `DEV_ONLY` 创建许可。本项不实现生产安全门，不增加生产识别信号。

允许修改的文件或模块：只限 `platform-common`。可以改 `StartupChecklist`，或在已有包 `com.mtx.rdp.common` 增加解析类型。新类名仍待实施前确认，本记录不起名。同包测试放在 `StartupChecklistTest` 或同包的新测试里。

允许新增的类和职责：一个不依赖 Spring 的纯解析。输出保留每个键的单键结果和组合结果。

禁止修改范围：不引入 Spring 依赖。不改两个应用的启动行为，因此不改 `AdminProcessStartup`、`WorkerProcessStartup`、`AdminRuntimeProperties`、`WorkerRuntimeProperties`。不改两个 `application.yml`。不改 `platform-common` 以外的模块。不创建或装配 `DEV_ONLY` 对象。不改 `ModuleArchitectureTest` 的依赖预期。

必须完成的单元测试：申请第 4 节的单键规则和全部合法组合。覆盖空字符串、纯空白、前后空格、大小写，以及原始文本 `true`、`false`、`TRUE`、`1`、`yes`。一个键非法时原因仍在。两个键都非法时两份原因都在。测试不启动 Spring，名称写明这不是生产识别，也不是创建许可。

架构测试要求：`platform-common` 仍不依赖 Spring 或其他内部模块。依赖方向不变。

验收证据：单元测试断言上述结果。证据只证明解析行为。

明确不包含：生产安全门、A13、两个应用的配置绑定、C1-02 的存储、C1-08 的清单，以及 C1-03 至 C1-09。

## 2. C1-02 虚构来源与进程内原文模拟存储

- 授权状态：`APPROVED`
- 授权人：Wayne
- 授权日期：2026-11-28

授权范围：只在 `platform-connector` 实现虚构来源和进程内原文模拟存储。来源只产生标明虚构的测试数据。存储保存完整虚构报文字节，按本次对象生命周期内的引用读取，并区分命中、引用不存在、存储关闭或不可用。关闭后引用失效。不实现恢复、Replay、持久化、Task 或 Pipeline。这些字节不是 IR-15 的介质，也不是审计。

类型出现在运行时 classpath 上，不等于获得运行时使用许可。构造、写入、读取和关闭只允许出现在本模块单元测试中。

允许修改的文件或模块：`platform-connector/src/main/java` 与 `platform-connector/src/test/java`。该模块目前没有 Java 包，包名待实施前确认，本记录不起类名。为了让单元测试能够编译，允许只增加测试范围的 `org.junit.jupiter:junit-jupiter`，不写版本，并只把 `ModuleArchitectureTest` 里 connector 的预期依赖补上这一条。不增加其他依赖，不改变依赖方向。本项批准包含这条测试范围依赖。

允许新增的类和职责：虚构来源，以及一个可由测试代码直接构造的内存存储。不注册 Spring Bean，不提供运行时工厂、启动装配器或生产调用入口。

禁止修改范围：不在 `app-admin`、`app-worker`、`platform-pipeline` 或其他模块增加调用点。不改 `WorkerProcessStartup` 或 `WorkerApplication`。Worker 启动路径不创建、不装配、不使用该存储。不增加数据库、文件、网络、Kafka 或跨进程通信。配置键和测试专用的生产入口都不能绕过这些限制。不调用 `resolve`。

必须完成的单元测试：测试代码直接构造对象，读回同一份完整报文，并覆盖引用不存在和关闭后不可用。不启动 Spring。

架构测试要求：除上述测试依赖外，connector 仍只依赖 `platform-common` 和 `platform-core`。

验收证据：单元测试证明存储行为。主源码搜索还要证明四件事：`platform-connector/src/main/java` 中没有应用运行时调用者；`app-admin` 和 `app-worker` 没有该存储的引用或装配；Spring Bean 定义中没有该存储；行为验证发生在直接构造的单元测试里。不声称这个 Java 类型在技术上无法被其他代码构造。

明确不包含：运行时装配、生产安全门、A13、IR-15 的介质选定、Pipeline、Worker 执行，以及 C1-01、C1-08 和 C1-03 至 C1-09。06-04-01 第 9 节的持久化禁令没有被本项放开。本项批准只覆盖上述进程内、不恢复的模拟存储。
