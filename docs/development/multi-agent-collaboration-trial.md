## 3. 角色

### 3.1 主 Agent

主 Agent 是架构统筹与集成负责人。只允许有一个主 Agent。

职责：

- 宣布基线提交，并在基线变化时停止受影响的工作包。
- 分配工作包和文件所有权。
- 维护依赖。强依赖的实现任务不拆成并行修改。
- 判断一项结论属于业务确认、架构决策还是工程验证。
- 复核子 Agent 的证据和推理。结论没有文件、代码、测试或实验出处时，不采纳。
- 处理冲突。冲突未复核前，两边都保持未采纳。
- 集成验收，并安排下一阶段。

主 Agent 独占修改：

- 本方案、工作包登记表和试运行总结。
- [06-04-02](../investigation/round-01/06-04-02%20MTX%20Data%20Platform%20V2%20工程实施未决设计决策台账.md) 的状态格。
- `docs/decisions/` 与决策索引。
- 根 POM、模块名单和模块依赖。
- 任一已经存在、且被两个以上工作包引用的调查文件。

### 3.2 子 Agent

四个子 Agent 在第一轮只读调查，各自只新增自己的报告。它们不修改调查原文、ADR、Java、POM、DDL、SQL 和配置，不把 `PENDING`、待填写或待决策改成已接受，不推送。

发现范围外的问题时，写入报告的“对其他工作包的依赖”，交给主 Agent。不自行扩大修改范围。

## 5. 并行边界

可以并行的，只有第一轮四份只读审查。它们的新增文件互不相同。阅读范围允许重叠。

必须串行的：

1. `WP-MA-INT` 等四份报告都出现，并且都声明同一基线。
2. 对已有调查文件、台账、ADR、POM 的任何修改。先由主 Agent 指定唯一修改者。
3. 金额设计稿修订。它等对应决策变成 `CONFIRMED`，并且只改 06-03-03-11 第 10 节点名的文件。
4. 金额 Java。它等设计稿已经按该选择改完。
5. IR-10 的实现。它等 06-04-59 的对应栏由评审人填写，并且按该文件第 4 节处理。填写本身不是子 Agent 的工作。
6. 物理唯一约束和 Create-or-Get 的实现。它们等 IR-02 离开阶段 A，并有该编号实验的执行记录。
7. Kafka 消费实现。它等 IR-03 的身份规则可执行，且 IR-09 的跨系统提交规则不再只是待验证建议。
8. 删除和归档。它们等 IR-15 的实体条件被接受。

不允许为了增加并行数，把上面 3 至 8 拆给多个 Agent 同时改。

独立 Worktree 适合第一轮：每个子 Agent 一个工作树，只允许新增自己的报告。主 Agent 不合并会改同一调查文件的工作树。

独立 Worktree 不适合后续对台账、ADR、根 POM、06-03-03-11、06-04-59 的修改。这些文件只在主工作区由主 Agent 或其指定的唯一修改者更改。

## 6. 报告格式

每份子报告固定十二节，顺序不改：

1. 调查范围和基线 Commit。
2. 检查过的文件清单。
3. 已确认事实及对应证据。
4. 发现的问题及严重级别。
5. 问题之间的依赖关系。
6. 需要业务确认的事项。
7. 需要架构决策的事项。
8. 需要工程实验的事项。
9. 可以立即进入代码实现的事项。
10. 尚不能进入代码实现的事项。
11. 对其他工作包的依赖。
12. 明确的未验证事项。

严重级别只用：阻断实现、阻断决策、文档冲突、待验证。没有证据的推断写进第 12 节，不写进第 3 节。

第 9 节可以是“无”。不得用“建议实现”填满第 9 节。

## 7. 冲突处理

子 Agent 之间的结论不一致时：

1. 主 Agent 列出双方引用的文件、章节和原句。
2. 另一次只读复核，不由得出结论的那个 Agent 复核自己。
3. 复核前不修改被引用的原文，不选择一边覆盖另一边。
4. 若冲突已经写在现有文档里，集成总结只复述该冲突和它当前的处理句子。
5. 需要新 ADR 或改已接受 ADR 时，停止实现，另写变更方案，等待人工批准。
