## 2. C1 交付与非交付

C1 只准备 Level 1 的本地模拟。任务拆开不等于已经授权实施。能准备的范围和仍被阻断的范围以第 6 节为准。

业务数据只允许走到契约计数阻断为止：

```text
模拟来源 → 接入模拟 → 原文模拟存储 → Task 壳 → 契约版本计数阻断
→ 停止传递业务数据
```

契约计数阻断之后，字段提取、金额、转换、质量和 Writer 不再接收业务输入，也不执行业务处理。诊断上可以逐行列出这些阶段，状态是「未执行：上游契约计数阻断，没有有效业务输入」。这个状态不是未配置，也不是成功。

输入必须是标明虚构的数据。原文保存完整虚构报文，并按引用读取。引用只在当前 Worker JVM 有效，进程停止后报文和引用都失效。上述业务停点目前还不能编码，因为对应任务是 BLOCKED。

Admin 独立启动。它的交付是本进程诊断输出，不是浏览器页面。清单来自 Admin 自己的虚构数据，不读取 Worker 的内存、原文或阶段记录，也不依赖 Worker 才能启动。C1 完成时不得写成管理页面已经交付。

C1 不做：

- 不连接 MySQL、Kafka、Doris、Quartz，不提交 offset，不领取真实任务，不消费真实消息。
- 不生成生产 `taskId`、稳定来源身份、正式契约版本、正式规则版本或正式审计。
- 不选择或创建快照，不调用 `resolve` 处理虚构条目。
- 不设计正式字段映射，不生成 `NormalizedAmount`，不把 `NO_CONVERT` 写成算法，不返回质量通过。
- 不建表，不用内存写入代替生产写入验收。
- 不在 Admin 与 Worker 之间使用 HTTP、数据库、文件、Kafka 或其他进程间通信。
- 不新增模块，不改变 ADR-0002 的依赖方向。
- 不关闭任何 IR 或 INT。

契约版本计数阶段的结果是阻断，不是一次成功的解析。原因见第 4.2 节。阻断之后没有有效契约版本，后面的阶段不得继续处理这份数据。字段提取、金额、转换和质量各自在「已经拿到有效业务输入、但没有已批准规则」时才是未配置。C1 的这条链路拿不到该输入，所以它们是未执行，不是未配置。未配置和未执行都不是成功，也不能变成可写入的业务结果。

## 4. 必须先定清的行为

### 4.1 DEV_ONLY 显式确认，以及尚未确定的生产识别

现有启动只核对进程名、`mtx.rdp.role` 和健康状态。`StartupChecklist` 把空 profile 报成「未激活配置环境」，不判断生产。配置盘点写明：环境变量名没有项目约定；没有配置中心；已有测试能用启动参数覆盖 yml 里的角色。06-04-01 第 7 节把部署与运行准备标为 `NOT_READY`。因此仓库里没有可信的生产环境识别。

下面两个键只表示操作者显式确认「这次想跑本地模拟」。它们不能证明进程不在生产环境。

| 键 | 允许取值 | 缺省 |
| --- | --- | --- |
| `mtx.rdp.runtime-mode` | `local-simulation` 或 `production` | 不设置。不解释成其中任何一个 |
| `mtx.rdp.dev-only-acknowledged` | `true` 或 `false` | `false` |

显式确认的组合：

| `runtime-mode` | `dev-only-acknowledged` | 只表示 |
| --- | --- | --- |
| 不设置 | `false` 或缺省 | 不确认模拟。不创建 `DEV_ONLY` 对象。这也不是生产许可 |
| 不设置 | `true` | 确认不完整。拒绝创建 `DEV_ONLY` 对象 |
| `local-simulation` | `false` 或缺省 | 确认不完整。拒绝创建 |
| `local-simulation` | `true` | 显式确认成立。仍不证明当前不是生产 |
| `production` | `false` 或缺省 | 自己声明为 production。这个声明本身不是可信环境信号 |
| `production` | `true` | 确认冲突。拒绝创建 |
| 其他字符串 | 任意 | 无法识别。拒绝创建 |

生产安全识别要单独确定，本文件不选来源，也不排优先级：

1. 真实生产环境如何识别：尚未确定。进程名、角色、profile 和上面两个键都不是。
2. 标识由谁提供：尚未确定。仓库里没有部署系统、配置中心或已约定的环境变量承担这件事。
3. 启动参数、环境变量、Spring 配置文件和外部配置中心哪个权威：尚未确定。配置中心不存在。启动参数能够覆盖 yml，所以写在文件里的 `local-simulation` 可以被同一次启动改掉。在权威来源确定之前，任何一层上的自我声明都只是声明。
4. 生产部署若被覆盖成 `local-simulation` 且确认值为 `true`：只按双条件就会允许创建 `DEV_ONLY` 对象。所以双条件挡不住这种误配置。
5. 生产识别缺失或互相冲突：默认拒绝创建 `DEV_ONLY` 对象。未命名启动继续允许，但它只是今天的骨架，不是生产许可，也不是模拟许可。
6. 配置覆盖、profile 切换和生产误配置的测试：要等可信信号确定之后才能作为生产安全验收。在那之前，测试只能证明双条件的确认行为。

可信信号确定之后，创建 `DEV_ONLY` 对象必须同时满足：信号明确不是生产、信号内部不冲突、并且上表的显式确认成立。缺信号、信号冲突，或信号说是生产而键写成模拟，都拒绝创建。这个最终验收现在是 BLOCKED。

默认 `application.yml` 不写这两个键。模拟确认不靠单独一个 profile 名字完成。这组设计不修改当前配置文件。

### 4.2 契约版本计数

`resolve` 可以继续留在已有单元测试里。那些测试使用的是函数输入，不是一份已经从存储读完的正式快照。

C1 的 Worker 链路不调用它。Worker 没有已完成的快照读取，也没有被授权去实现 Task、Worker 或 Pipeline。用虚构 `snapshotId`、虚构家族和虚构条目调用，会把测试输入说成一次契约解析。C1 不这样做。

该阶段的本地结果固定为阻断。诊断写明：没有已完成的快照读取，所以没有调用 `resolve`。不传入空列表，不生成快照，不生成契约版本。阻断不是可继续处理的业务结果。已固定快照上的重试规则也不在这里实现。IR-04 继续只阻断新任务和显式重放的第一次快照选择；C1 没有这次选择。本阶段的编码随 C1-04 保持 BLOCKED。

### 4.3 字段提取

没有已批准的提取规则，也没有 POS、京东、美团、淘宝闪购或饿了么的正式字段映射。

在本条链路里，契约计数已经阻断，字段提取不接收这份数据，不生成任何字段结果。诊断写「未执行：上游契约计数阻断，没有有效业务输入」。

只有在另一次、上游已经给出有效契约版本的调用里，没有批准规则才返回未配置。那种调用不是这条被阻断的链路，也不在 C1 里制造。以后某条规则要接入，必须另有批准和仓库里的证据。

### 4.4 金额、转换与质量

契约计数阻断后，这三段都不接收业务输入。诊断都是未执行，原因与第 4.3 节相同。不得把未配置或未执行解释成转换成功、质量通过或金额已经观察完成。

若将来某次调用确实带着有效业务输入进入这些阶段，仍然不得生成 `NormalizedAmount`，不得做未批准的计算，`CONFLICT` 不得进入计算，不得决定精度、舍入、正负号或指数，不得把 `NO_CONVERT` 写成算法，没有质量规则时只能是未配置。那种调用不属于当前这条阻断链路。IR-13、IR-14、IR-17 保持原状态。这三段的编码随 C1-05 保持 BLOCKED。

### 4.5 Writer 与原文存储

原文存储是 `platform-connector` 里的普通 Java 对象。它保存完整虚构报文字节，用本次运行产生的引用读取。读取要能分开三种结果：命中、引用不存在、存储不可用。进程停止或存储被关闭后，引用失效。存储不实现恢复和 Replay。这些记录不是 IR-10 的审计，日志也不是审计。IR-15 仍是待决策，本存储不代表已经选定介质。这段可以按 C1-02 准备，它不组成 Pipeline 编排。

Writer 不因为链路要「走到最后」就执行。上游契约计数阻断时，Writer 不接收这份数据，不把阻断结果写成一份模拟写入。诊断只记「未执行：上游契约计数阻断，没有有效业务输入」。不得把 Writer 模拟成功当成整条处理链路成功。

Writer 对象若在将来的单独测试里接受一份明确不是业务结果的夹具，那个测试只证明对象本身没有打开 JDBC。它不证明被阻断的链路已经写入。Writer 不建表，不写正式账本，不宣称幂等或恢复。该任务仍是 BLOCKED。

Task 壳只产生本次运行的本地运行号。这个号码不是 `taskId`，也不能用来源单号代替稳定事件身份。IR-03 仍是部分确认 / 待决策。Task 壳属于 Worker 执行，编码 BLOCKED。

接入模拟停在「虚构报文已经交给本进程存储」为止。它不连接 Kafka，不提交 offset。INT-05、INT-20、INT-21 不因此改变。把接入编进 Pipeline 阶段同样 BLOCKED。
