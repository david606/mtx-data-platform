## 2. C1 交付与非交付

C1 只准备 Level 1 的本地模拟。审查接受本文件之后，才能按第 6 节逐项开工。

Worker 在自己的 JVM 内走完这条受控链路：

```text
模拟来源 → 接入模拟 → 原文模拟存储 → Task 壳
→ 契约版本计数阶段 → 字段提取占位 → 金额观察壳
→ 转换占位 → 质量占位 → Writer 模拟 → 本进程阶段结果
```

输入必须是标明虚构的数据。原文保存完整虚构报文，并按引用读取。引用只在当前 Worker JVM 有效，进程停止后报文和引用都失效。阶段结果只通过 Worker 的本地日志或同进程诊断输出查看。

Admin 独立启动。它展示的清单来自 Admin 进程内的虚构数据，不读取 Worker 的内存、原文或阶段记录，也不依赖 Worker 才能启动。

C1 不做：

- 不连接 MySQL、Kafka、Doris、Quartz，不提交 offset，不领取真实任务，不消费真实消息。
- 不生成生产 `taskId`、稳定来源身份、正式契约版本、正式规则版本或正式审计。
- 不选择或创建快照，不调用 `resolve` 处理虚构条目。
- 不设计正式字段映射，不生成 `NormalizedAmount`，不把 `NO_CONVERT` 写成算法，不返回质量通过。
- 不建表，不用内存写入代替生产写入验收。
- 不在 Admin 与 Worker 之间使用 HTTP、数据库、文件、Kafka 或其他进程间通信。
- 不新增模块，不改变 ADR-0002 的依赖方向。
- 不关闭任何 IR 或 INT。

契约版本计数阶段在 C1 的结果是阻断，不是一次成功的解析。原因见第 4.2 节。字段提取、金额、转换和质量在没有已批准规则时是未配置。这四类都算链路走到了该阶段，不算正式业务结果。

阶段诊断使用四个本地标签：成功、失败、未配置、阻断。它们不是 Pipeline 里的任务状态，也不是新的生产错误码。IR-12 仍是待决策。C1 不新增可持久化的通用阶段实体，诊断对象随进程消失。仓库里没有 `NOT_CONFIGURED`。未配置只作为本地标签，不进入生产错误码表。

## 4. 必须先定清的行为

### 4.1 DEV_ONLY 与生产启动

现有启动只识别进程名和职责，不识别生产或模拟。C1 增加一组启动约束。默认的 `application.yml` 仍不写这些键，因此今天的未命名启动保持可用，并且不会装上模拟组件。

配置键：

| 键 | 允许取值 | 缺省 |
| --- | --- | --- |
| `mtx.rdp.runtime-mode` | `local-simulation` 或 `production` | 不设置。不解释成其中任何一个 |
| `mtx.rdp.dev-only-acknowledged` | `true` 或 `false` | `false` |

同时满足下面两条，才允许创建带 `DEV_ONLY` 标记的对象：

1. `runtime-mode` 等于 `local-simulation`。
2. `dev-only-acknowledged` 等于 `true`。

其他组合按下表处理。半套配置拒绝启动，不能只改一个键就进入模拟，也不能在生产模式里靠一个键打开模拟。

| `runtime-mode` | `dev-only-acknowledged` | 启动结果 |
| --- | --- | --- |
| 不设置 | `false` 或缺省 | 允许启动。这是现有骨架。不创建 `DEV_ONLY` 对象。它不是生产许可 |
| 不设置 | `true` | 拒绝启动 |
| `local-simulation` | `false` 或缺省 | 拒绝启动 |
| `local-simulation` | `true` | 允许启动，并允许创建 `DEV_ONLY` 对象 |
| `production` | `false` 或缺省 | 允许启动。进程中不得存在 `DEV_ONLY` 对象 |
| `production` | `true` | 拒绝启动 |
| 其他字符串 | 任意 | 拒绝启动 |

判断放在 `StartupChecklist` 的新方法里，由两个应用现有的启动器调用。`platform-common` 不扫描 Spring 容器。两个启动器额外确认：生产模式和未命名启动的上下文里没有 `DEV_ONLY` 标记；`local-simulation` 启动时，本应用声明要装配的标记必须都能见到。标记缺失或越界都拒绝启动。

模拟对象的构造器要求调用方传入已通过上述判断的许可。只给类起一个模拟名字、或只激活某个 Spring profile，都不能创建它。`local-simulation` 的键放在该模式自己的配置文件，不写进默认 `application.yml`。生产模式的配置文件不得出现 `dev-only-acknowledged: true`。

验收测试：

| 场景 | 方式 |
| --- | --- |
| 六个组合的判断 | `StartupChecklistTest` 直接调用纯方法 |
| 未命名启动仍成功且没有模拟对象 | 现有 `AdminApplicationTest`、`WorkerApplicationTest`，不增加 profile |
| `local-simulation` 且已确认时两个应用都能启动 | 测试里用参数启动上下文，不改默认 yml |
| `production` 且确认值为 true 时两个应用都拒绝启动 | 同上，断言根因是启动配置异常 |
| 生产配置文件没有打开确认值 | 测试读取将要新增的生产配置；默认 yml 也不得写入 `true` |

这组测试证明启动门能挡住半套配置和生产模式。它不证明模拟链路的业务结果正确。

### 4.2 契约版本计数

`resolve` 可以继续留在已有单元测试里。那些测试使用的是函数输入，不是一份已经从存储读完的正式快照。

C1 的 Worker 链路不调用它。Worker 没有已完成的快照读取，也没有被授权去实现 Task、Worker 或 Pipeline。用虚构 `snapshotId`、虚构家族和虚构条目调用，会把测试输入说成一次契约解析。C1 不这样做。

该阶段的本地结果固定为阻断。诊断写明：没有已完成的快照读取，所以没有调用 `resolve`。不传入空列表，不生成快照，不生成契约版本。已固定快照上的重试规则也不在这里实现。IR-04 继续只阻断新任务和显式重放的第一次快照选择；C1 没有这次选择。

### 4.3 字段提取

没有已批准的提取规则，也没有 POS、京东、美团、淘宝闪购或饿了么的正式字段映射。C1 的占位接收标明虚构的输入，返回未配置，不生成正式字段结果，不改 `resolve`。以后某条规则要接入，必须另有批准和仓库里的证据。那个任务不是 C1。

### 4.4 金额、转换与质量

金额阶段只保留观察边界：不生成 `NormalizedAmount`，不做计算，`CONFLICT` 不进入计算，不决定精度、舍入、正负号或指数。二十项未确认时，本地结果是未配置。

转换阶段不把 `NO_CONVERT` 写成算法，不分配 `normalizationRuleVersion`。质量阶段在没有规则时返回未配置，不返回质量通过，不新增质量结果实体或表。IR-13、IR-14、IR-17 保持原状态。

### 4.5 Writer 与原文存储

原文存储是 `platform-connector` 里的普通 Java 对象，由 `app-worker` 在模拟许可通过后创建。它保存完整虚构报文字节，用本次运行产生的引用读取。读取要能分开三种结果：命中、引用不存在、存储不可用。进程停止或存储被关闭后，引用失效。存储不实现恢复和 Replay。这些记录不是 IR-10 的审计，日志也不是审计。IR-15 仍是待决策，本存储不代表已经选定介质。

Writer 是同一进程里的另一份内存结果。它不打开 JDBC，不建表，不写正式账本，不宣称幂等或恢复。关闭进程后结果消失。

Task 壳只产生本次运行的本地运行号。这个号码不是 `taskId`，也不能用来源单号代替稳定事件身份。IR-03 仍是部分确认 / 待决策。

接入模拟停在「虚构报文已经交给本进程」为止。它不连接 Kafka，不提交 offset。INT-05、INT-20、INT-21 不因此改变。

## 6. 实施任务

### C1-01 运行模式与 DEV_ONLY 门

- 依赖：无。
- 模块：`platform-common`、`app-admin`、`app-worker`。
- 代码范围：`StartupChecklist` 及其测试；两个启动器；两个应用测试。默认 `application.yml` 不写入新键。模拟和生产的配置文件只在本任务需要覆盖第 4.1 节时新增。
- 禁止：启用模拟链路，连接基础设施，引入 Web 依赖，把未命名启动改成生产。
- 单元测试：第 4.1 节的六个组合。
- 启动测试：未命名启动仍成功；`local-simulation` 且已确认时可以启动；生产模式加确认值 true 时拒绝启动。
- 验收：错误组合不能启动；正确的生产组合和未命名组合都看不到 `DEV_ONLY` 对象。
- 能够证明：启动门按两个键拒绝半套配置。
- 不能宣称：模拟业务已经跑通，或生产环境已经完成上线验收。

### C1-02 虚构来源与原文模拟存储

- 依赖：C1-01。
- 模块：`platform-connector`。
- 代码范围：虚构来源和进程内存储。存储构造要求第 4.1 节的许可。测试放在本模块，不启动 Spring，不连接外部进程。
- 禁止：文件、数据库、网络、跨进程共享、生产引用、恢复和 Replay。
- 单元测试：保存后按引用读回同一份完整报文；引用不存在；存储关闭后不可用；未持有许可时不能构造。
- 启动测试：本任务不要求。
- 验收：三种读取结果可以区分，报文在对象丢弃后不能再读。
- 能够证明：一个 JVM 内的 `DEV_ONLY` 存储能按引用工作。
- 不能宣称：IR-15 已选定介质，Admin 能读到这些报文，或记录可以用于正式重放。

### C1-03 阶段端口与编排

- 依赖：C1-01。
- 模块：`platform-pipeline`。
- 代码范围：阶段端口、阶段诊断和只通过端口调用的编排。测试用本模块内的假端口。
- 禁止：依赖四个实现模块，调用 `resolve`，保存报文字节，引入 Quartz，把诊断写成 IR-12 的持久化实体。
- 单元测试：端口分别返回成功、失败、未配置、阻断时，编排保留该结果并停止把未配置写成成功。
- 启动测试：本任务不要求。
- 验收：Pipeline 的 POM 仍然只有 common 和 core。
- 能够证明：编排不需要具体实现也能表达四种本地结果。
