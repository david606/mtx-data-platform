## 1. 背景与推进方式

Stage B 五个领域的调查已经完成。已实现的独立业务纯逻辑只有 `ContractVersionUniqueness.resolve`。配置、质量、转换和执行上下文都没有新的纯逻辑候选。不应再为了增加代码而制造没有调用方的抽象，也不应等待所有业务设计冻结后才做任何工程工作。

调整后的推进方式是：已接受的架构和技术基线可以进入实现；不影响正确性的不确定项可以做成受控临时实现；不能临时决定的规则保持阻断，只留接口和模拟边界。本地把处理流程跑通，不等于生产准入。

| 级别 | 目标 | 允许范围 | 不能宣称 |
| --- | --- | --- | --- |
| Level 1 本地完整模拟 | 验证模块边界和阶段顺序 | `DEV_ONLY` 的模拟数据、模拟组件和受控临时策略 | 生产验收、真实身份已解决、正式业务结果 |
| Level 2 真实基础设施集成 | 验证已经单独准入的 MySQL、Kafka、Doris 或 Quartz | 只接入该次批准的组件和测试 | 未准入组件已可用，或 Level 1 因此升级为生产 |
| Level 3 生产业务运行 | 承载真实业务数据 | 第 8 节门禁全部有接受记录和验证记录 | 用本地模拟成功代替任何一项门禁 |

本文提出的 C1 至 C6 是建议顺序。审查接受之前不开始其中任何代码。

## 3. A/B/C/D 分类

分类是本方案的实施策略，不改变台账状态。

| 类 | 含义 |
| --- | --- |
| A | 已接受或已经实现。后续代码必须遵守，但不能借此扩大范围 |
| B | 可逆、不影响身份和正确性。只允许 `DEV_ONLY` 临时策略 |
| C | 依赖真实组件或外部条件。先有边界和模拟，真实接入另批 |
| D | 正确性、安全或不可逆。禁止用默认值、假身份或哨兵绕过 |

## 4. 临时实现治理

这些规则是本方案的要求。仓库里还没有 `DEV_ONLY` 实现。写代码之前要先有审查过的任务，不能靠本节直接开工。

| 概念 | 含义 |
| --- | --- |
| 模拟数据 | 明确标注的虚构订单。不是来源契约，也不能进入生产 |
| 模拟基础设施 | 进程内的替身。不连接 MySQL、Kafka 或 Doris |
| 临时业务策略 | 只影响展示或占位、且可删除的选择。不产生正式金额、身份、版本或审计 |
| 正式业务规则 | 已接受 ADR 或已经批准的实现 |
| 生产正确性约束 | 身份、幂等、快照选择、事务、执行权、offset、恢复。属于 D 类 |

临时实现必须同时满足：

1. 代码和配置标明 `DEV_ONLY`。
2. 生产环境启动时拒绝启用 `DEV_ONLY`。
3. 正式实现替换的是同一个端口，不重写 Pipeline。
4. 临时策略放在独立配置，不写进 Pipeline 的业务分支。
5. 结果带“非正式”标记。Admin 不得把它显示成已验证的业务结果。
6. 不生成会进入生产的身份、契约版本、规则版本或审计记录。
7. 每项写明适用范围、退出条件和替换验收。负责人在该项开工时指定，本文不代填人名。

没有质量规则时，阶段结果是“未配置”，不是“质量通过”。没有正式金额语义时，不生成 `NormalizedAmount` 或汇总结论。`unknown` 与 `CONFLICT` 只保留观察边界，不做标准化或计算。

## 7. 未决事项的处理策略

第 3 节是分类。这里只补充容易混用的边界。

IR-04 保持 [06-04-60](../investigation/round-01/06-04/06-04-60%20MTX%20Data%20Platform%20V2%20IR-04%20R15快照选择决策比较与建议.md) 修订后的范围：新任务第一次选择并固定 `snapshotId` 仍阻断；已固定快照的原任务重试沿用原快照，不受 R15 阻断；显式重放是新任务，重新经过选择，仍阻断；`resolve` 不选快照，不受 R15 阻断。IR-04 不是已关闭，也不是 Stage C 的全局阻断。方案 A 仍是 `PROPOSED`。

IR-03 与 IR-04 不互相代替。没有稳定身份就不能建生产任务。有了身份，新任务仍不能在 R15 未批准时实现第一次选快照。

## 9. 模块与替换点

不新增模块。临时实现和正式实现都留在 ADR-0002 已经允许的模块里。

| 模块 | Level 1 的位置 | 正式替换 |
| --- | --- | --- |
| `platform-common` | 已有启动核对。不把业务策略放进来 | 不扩成工具库 |
| `platform-core` | 已有契约计数。不放基础设施 | 已批准的纯规则仍放这里 |
| `platform-pipeline` | 只编排阶段端口 | 不依赖具体实现，不引用 Quartz |
| `platform-messaging` | Kafka 的模拟边界 | 真实客户端仍在本模块 |
| `platform-connector` | 模拟来源的边界 | 真实平台接入仍在本模块 |
| `platform-transform` | 未配置占位 | 已确认的转换规则 |
| `platform-quality` | 未配置占位 | 已确认的质量规则 |
| `platform-writer` | Level 1 演示写入 | MySQL 或 Doris 的正式写入 |
| `app-admin` | 查看带标记的模拟状态 | 不执行数据处理，不依赖 Worker |
| `app-worker` | 独立启动 | 装配实现。不把装配上推到 Core 或 Pipeline |

Core 继续不依赖 Spring、JDBC、MyBatis、Kafka 或 Quartz。不引入 DDD。不为了 Level 1 预建没有调用方的第二套抽象。
