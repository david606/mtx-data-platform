## 3. C1-01

符合授权。解析器只在 `platform-common`，输入是两个 `Optional<String>`。空 Optional 表示键不存在，`Optional.of("")` 表示键存在且原文为空。比较使用原文 `equals`，不 trim、不忽略大小写、不转成布尔值。

`local-simulation` 与 `production`、`true` 与 `false` 才是合法原文。`ACKNOWLEDGED` 的类型注释写明它只表示操作者显式确认完整，不是可信非生产证明，也不是 `DEV_ONLY` 创建许可。`PRODUCTION_SELF_DECLARED` 写明只是自我声明。解析器不读取配置，不创建存储或清单，也没有 Spring 依赖。

两个键都非法时，`bothInvalidKeysKeepBothReasonsAndDoNotKeepOnlyTheFirst` 断言两份 `InvalidReason` 同时留下，顺序是 runtime-mode 然后 dev-only-acknowledged。单键非法不会被另一键的合法值改成 `ACKNOWLEDGED` 或其他合法组合。

## 4. C1-02

符合授权。`FictionalMessageSource` 只返回一份预先写好的 UTF-8 字节，正文包含 `DEV_ONLY` 和虚构数据，不读取配置，也不访问网络、数据库、Kafka 或文件。`InMemoryRawMessageStore` 把字节放在对象内的 `HashMap`。`put` 保存输入副本，`Found` 再复制一份给调用方。

读取分成 `Found`、`NotFound`、`Unavailable`。关闭在同一把锁内清空映射，之后读写都不再交出旧数据，重复关闭不会恢复。没有恢复、Replay、Task 或 Pipeline。生产类之间没有互相调用。

测试范围只增加了不写版本的 `junit-jupiter`。`ModuleArchitectureTest` 里 connector 的预期是 `platform-common`、`platform-core` 和这条测试依赖。依赖方向没有变。

06-04-01 第 9 节的持久化禁令仍然有效。本项没有写外部介质，也没有把它解释成禁令已经解除。类型位于 Worker 的运行时 classpath，是因为 Worker 原本就依赖 `platform-connector`。当前 Worker 源码没有构造或调用这两个类型。classpath 存在不是运行时许可。

## 5. C1-08

符合 A11-1 授权。`AdminDemoDiagnosticCatalog.entries()` 返回四条固定记录，状态依次是成功、失败、未配置、阻断。每条都带 `DEV_ONLY`、演示数据、非正式结果，阶段说明写明不是 Worker 执行结果。列表是 `List.of`，测试断言调用方不能追加。

类注释写明这不是正式业务结果或正式审计，也不提供运行时输出入口。测试类注释写明这是 A11-1，不启动应用。测试源码没有 `@SpringBootTest`。新类没有 Spring 注解，也不调用确认键解析器。

没有发现生产源码调用链，因此没有超出授权的调用需要按文件和行号列为阻断。

## 10. 未解决项与非阻断观察

没有发现授权外调用、启动装配、依赖越界或关键行为缺陷。下列观察不改变验收结论，本轮也不修改代码：

1. `RuntimeModeConfirmationParser.combine` 在返回非法组合之后，仍有一个到不了的 `INVALID` 分支，用来满足枚举 switch 的穷尽要求。
2. `Result` 核对非法原因的条数。`parse` 会按键放入对应原因。公开构造器本身不核对原因是否属于那个非法键。
3. `Entry` 的状态字段没有限定只能是四种演示状态。清单实际发布的四条记录是这四种。
4. C1-02 类型因既有模块依赖出现在 Worker classpath。没有调用点。
