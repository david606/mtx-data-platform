## 4. 发现的问题及严重级别

1. **阻断实现。** 二十项的最终选择和决策状态都是 `PENDING`，确认记录都是“无”。`06-03-03-11` 第 11 节写明当前一项都还不能写。金额分类修订、字符串许可、`Money` 和 `NormalizedAmount` 都不能按这些记录进入实现。
2. **阻断决策。** `11-JOINT-01` 把业务负责人与架构负责人写成同一条记录、同一个最终选择。业务准入来源和各层是否越权不能各自关闭。负值进入 `Money` 还同时等 `11-BIZ-01` 至 `11-BIZ-06`，见第 13.6 节。
3. **阻断决策。** `11-BIZ-11` 的 `N3` 在业务记录里写入“改读契约级三态”，并且只与 `11-ARC-04` 的 `B3` 可组合。映射级与契约级不能一边各选一边。这是两条记录上的同时成立约束，两条的最终选择栏仍然分开。任一方不能单独把冲突的一侧标成 `CONFIRMED`。
4. **阻断决策。** `K2`、`K3`、`C2`、`N2` 仍列在可选方案里。在第 4 节执行点不变、并且四种事实的读法边界仍有效时，第 13.7 节没有给它们留下可以变成 `CONFIRMED` 的组合。`11-ARC-05` 在 `B4` 下没有可采用的编码名，记录本身却仍是 `PENDING`。确认人不能在现有栏里把这些编号收成一项已关闭选择。
5. **阻断决策。** 第 13.7 节不允许把不可组合的两边分别变成 `CONFIRMED`。每条记录仍有自己的决策状态栏。禁止来自第 13.1 节和第 13.7 节的填写规则，不是一项已经填好的联合状态。规则不允许分别 `CONFIRMED`；独立状态栏也没有把这个禁止写成机械锁。
6. **文档冲突。** 第 3.2 节对照表把新正文缺省写成假或 `DENY`。同节后文、第 4 节、第 8 节第 5 点和 `11-BIZ-11` 要求字段缺失、显式 `NOT_DECIDED`、显式 `DENY`、显式 `ALLOW` 分成四种事实。`C1` 还规定编码完成后的新正文缺字段成为显式拒绝，并写明那个结果不是字段缺失。四种事实目前没有 `CONFIRMED` 的读法。只读对照表缺省格时，新正文缺字段和显式拒绝会落在同一个缺省值上。
7. **文档冲突。** `06-03-03-09` 第 3.2、4 节仍允许指数拒绝形态是 `OTHER_TEXT`。`06-03-03-10` 第 3.2 节与 `06-03-03-11` 第 5、2.6 节不采用这个归类，并把指数行留在审查建议。`06-03-03-01` 第 6 节仍把非零 JSON 数字写成 `NUMERIC_TEXT`。`06-03-03-04` 第 5 节写明 `06-03-03-01` 没有把科学计数法定义为十进制数字。`11-BIZ-09` 仍是 `PENDING`。
8. **文档冲突。** `06-03-03-10` 第 11 节第 3 点要求修订 `mapping-version-v2` 的字段顺序。`06-03-03-11` 第 3.2 节不采用这句，并要求新编码名、不改已定义的 v2 顺序。两句都还在库里。`11-ARC-04` 与 `11-ARC-05` 仍是 `PENDING`。
9. **文档冲突。** `06-03-03-01` 第 9 节对非金额标量使用 `TYPE_MISMATCH`，对非十进制字符串只写 `OTHER_TEXT`。`11-ARC-03` 仍是 `PENDING`。带单位文本和前后空格是否形成观测，因此还不能写入设计稿，见 `11-ARC-03` 的未决后果。

## 5. 问题之间的依赖关系

二十项全部保持 `PENDING`，是第 4 节第 1 点阻断实现的直接原因。设计稿修订还要等对应记录变成 `CONFIRMED`，见 `06-03-03-11` 第 10 节。Java 还要等那些设计稿按书面选择改完，见第 11 节。

`11-JOINT-01` 与 `11-BIZ-01` 至 `11-BIZ-06` 一起阻断负值进入 `Money` 或 `NormalizedAmount`。`11-BIZ-06` 在 `11-BIZ-01` 仍是 `PENDING` 时不能变成 `CONFIRMED`。

四种事实的读法同时挂在 `11-BIZ-11`、`11-ARC-04` 和 `11-ARC-06` 上。`N3` 只与 `B3` 可组合。`C2` 与四分法不可组合。第 3.2 节缺省格在这三项确认之前，不能单独当成编码规则。

`11-ARC-02` 的种类事实决定 `11-ARC-04`、`11-ARC-07` 能不能在标准化阶段执行。`K2` 或 `K3` 与 `B1` 至 `B4` 不可组合，所以字符串许可和“JSON `NUMBER` 是否受约束”都不能先于一个可组合的种类事实关闭。`11-ARC-05` 还依赖 `11-ARC-04` 已经 `CONFIRMED`，并且 `V1` 只与 `B1` 或 `B2` 可组合，`V2` 只与 `B3` 可组合。

指数归类的文档冲突要等 `11-BIZ-09`。`OTHER_TEXT` 字段码要等 `11-ARC-03`。`"+12"` 与 `"+0"` 分别等 `11-BIZ-10` 与 `11-BIZ-12`，不能互相代替。

ADR-0004 与冻结文档未同步，阻断的是提取入口怎样引用版本解析，不代替二十项里的任何一项。空 `conversionRuleVersion` 的物理表示和物理唯一约束不在二十项内。`06-03-03-11` 第 12 节写明它们继续阻断成功的 `NormalizedAmount`，不阻断设计稿修订完成之后的拒绝和分类。

## 6. 需要业务确认的事项

业务负责人必须确认的是第 13.1 节责任方为业务的十二项。本报告不代选编号。

1. `11-BIZ-01`：负值许可按类型、按场景、按类型与场景共同定义，还是本次不定义。
2. `11-BIZ-02`：未批准、未配置、明确禁止是否区分。三种候选都不构造 `Money`，差别在于是否分开记录原因。
3. `11-BIZ-03`：负优惠的符号语义。`P1` 至 `P5` 只适用于优惠。
4. `11-BIZ-04`：退款的符号语义。与 `11-BIZ-03` 互不绑定。
5. `11-BIZ-05`：冲正的符号语义。与前两项互不绑定。
6. `11-BIZ-06`：哪些标准金额类型允许负数。依赖 `11-BIZ-01`。类型从 `DRAFT` 改为 `ACTIVE` 不在本项里表决，见第 8 节末段和第 13.2 节。
7. `11-BIZ-07`：JSON `-0` 在计算和展示上有没有特殊含义。`Z3` 若要求改变 presence 或四段身份，本项不能关闭。
8. `11-BIZ-08`：字符串 `"-12"`、`"-12.50"` 是否属于数字文本。
9. `11-BIZ-09`：JSON 指数数字是否允许解析成十进制金额。`E2` 必须同时给出标度规则，否则不能记为 `CONFIRMED`。
10. `11-BIZ-10`：字符串 `"+12"` 是否属于非零数字文本。只在 `U1` 与 `U2` 之间选择。
11. `11-BIZ-11`：许可事实不存在时，字符串金额能否产生 `Money`。只在 `N1`、`N2`、`N3` 之间选择，并要与 `11-ARC-04` 同时成立。
12. `11-BIZ-12`：字符串 `"+0"` 是否属于零值数字文本。只在 `W1` 与 `W2` 之间选择。不因 `11-BIZ-10` 选择 `U2` 而一起决定。

`11-JOINT-01` 还要业务负责人确认准入规则的来源。架构负责人要同时确认各层不越权。它不是单独的业务项，也不是单独的架构项。

第 8 节写明：平台字段口径、类型从 `DRAFT` 改为 `ACTIVE`、业务精度和最值，不在本次输入语义里表决。

## 7. 需要架构决策的事项

架构负责人可以确认的是第 13.1 节责任方为架构的七项。可以确认是指责任方是架构，并且只能填写该记录已经列出的编号。组合规则不满足时，该项保持 `PENDING`，不能先写成 `CONFIRMED`。

1. `11-ARC-01`：是否采用 `MORPHOLOGICAL` 与 `BOOLEAN_NON_AMOUNT` 两种字段结果分支。边界是不增加第八种 presence，不新增提取字段码。
2. `11-ARC-02`：标准化用什么不可变事实区分 JSON `NUMBER` 与 JSON `STRING`。`K3` 在修订“不重读 JSON”之前不能标成 `CONFIRMED`。`K2` 与 `B1` 至 `B4` 不可组合。
3. `11-ARC-03`：普通 `OTHER_TEXT` 是否以 `OK` 形成观测。不覆盖 `"+12"` 与 `"+0"` 的 presence。
4. `11-ARC-04`：字符串许可放在映射枚举、映射布尔、契约三态，还是本次不增加许可字段。
5. `11-ARC-05`：新编码名用 `mapping-version-v3` 还是 `contract-version-v4`。依赖 `11-ARC-04`。`B4` 下没有可采用的编码名。
6. `11-ARC-06`：新正文缺字段、显式 `NOT_DECIDED` 与旧快照缺失如何读取。依赖 `11-ARC-04` 与 `11-ARC-05`，并且要与 `11-BIZ-11` 的四种事实一致。`C2` 不能与四分法分别确认。
7. `11-ARC-07`：JSON `NUMBER` 是否不受字符串许可约束。`R1`、`R2` 与 `K2`、`K3` 不可组合。

`11-JOINT-01` 的架构部分只确认各层不越权。它不决定哪种金额可以为负，也不决定字段结果采用哪一分支。

第 9 节第 6 点写明第二种解释和证据组合仍无字段，本次不设计该字段，不进入本次确认。架构负责人不在这七项里确认它。

架构负责人不确认 `11-BIZ-01` 至 `11-BIZ-12`，也不替业务选择 `U1`、`U2`、`W1`、`W2`、`N1`、`N2`、`N3`。
