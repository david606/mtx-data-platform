## 1. 背景与依据

ADR-0004 状态是 Accepted。它接受方案 C：在已经固定的金额映射快照内、金额路径提取之前解析契约版本。范围写明不包含表结构、索引、事务和 Java 实现，也不新增执行状态或错误码。

## 2. 已接受规则与 ADR 章节

已接受且本授权直接使用的规则在 ADR-0004「决策」节：

- 「snapshotId 固定规则」：解析发生在已经固定的 `snapshotId` 内。
- 「contractVersionId 输入优先级」：已经给出内部 `contractVersionId` 时，直接采用该值作为候选，不再用外部版本号在多个修订中选择。没有给出时，才按契约家族和外部版本号查找。报文外部版本号为「未提供」时，只与外部版本号同为「未提供」的修订比较。
- 「零个、一个、多个修订」：恰好一个才确定 `contractVersionId`。零个或多个都阻断，码为已有的 `CONTRACT_VERSION_UNRESOLVED`。多个「未提供」不另设结果，也不猜最新修订。
- 「契约家族身份校验」：版本表里仍有、但当前快照契约条目里没有的版本，结果是 `CONTRACT_VERSION_UNRESOLVED`。候选已经属于当前快照，但接入来源的契约家族身份或 `contractId` 与版本行不一致时，结果是 `CONTRACT_IDENTITY_MISMATCH`。该码不在多个修订中做选择。
- 「外部版本号一致性校验」：候选确定后，版本行上的外部版本号必须等于报文外部版本号，包括双方都是「未提供」。不一致时使用 `CONTRACT_IDENTITY_MISMATCH`，不改选另一条修订。
- 「UNMAPPED 的适用范围」：版本尚未确定时，不允许产生 `UNMAPPED`。

本授权只实现上述规则中的唯一性定位和计数。家族身份、`contractId`、候选确定之后的外部版本号一致性，以及正文哈希，仍由后续流程使用上列已有码处理。本函数不返回 `CONTRACT_IDENTITY_MISMATCH` 或 `CONTRACT_VERSION_HASH_MISMATCH`。

当前 `06-03-02-03` 第 8 节第 2 步、`06-03-03-01` 第 8 节和 Pipeline `06-03-03-06` 第 2 节已经写出与上述条款相同的计数和阻断结果。台账 IR-18A 记录这八条现行规则一致，同时写明该核验不授权修改 ADR。本文沿用这些已写出的计数规则，不重新决定它们。

ADR-0004 第 155 行仍写 Java 实现要等指定文档修订之后。ADR 开篇和 `docs/decisions/README.md` 仍保留接受当时「下游旧条款尚未同步」的说明。本文不删除、不改写这些句子。

## 4. 输入与输出

后续实现只接受以下输入：

| 输入 | 含义 |
| --- | --- |
| `snapshotId` | 调用方已经固定的快照标识。本能力不选择、不创建、不跳过快照 |
| 外部版本号 | 报文上的外部版本号。官方没有版本号时，这个值就是「未提供」。它不是 Java 空引用，也不等于「没有内部 `contractVersionId`」 |
| 内部 `contractVersionId` | 可选。未提供该标识，与外部版本号为「未提供」，是两件不同的事 |
| 调用方指定的契约家族 | 只在未提供内部 `contractVersionId` 时参与计数。内部标识已提供时，不得用它先过滤候选 |
| 候选集合 | 调用方已经读取完成的、当前固定 snapshot 的契约条目集合。不是按来源家族预先筛过的子集 |

每条候选至少包含：所属 `snapshotId`、`contractVersionId`、所属契约家族标识、版本行上的外部版本号。

调用前提：

- 候选集合是该 `snapshotId` 下已经读完的契约条目，不跨 snapshot，也不按来源家族提前缩小。
- 读取失败或条目数量尚未得出时，调用方不得调用本能力，也不得用空集合代替这次失败。
- 空集合只表示读取已经完成，且该 snapshot 的契约条目为零条。它不是「家族不一致」或「外部版本号不一致」的编码。

输出只有两种：

- 按第 5 节定位或计数后恰好一个：返回该 `contractVersionId`。
- 零个或多个：返回已有错误码 `CONTRACT_VERSION_UNRESOLVED`。

不返回 `UNMAPPED`。不返回 `CONTRACT_IDENTITY_MISMATCH` 或 `CONTRACT_VERSION_HASH_MISMATCH`。不新增错误码、执行状态或持久化字段。已经按内部 ID 在当前 snapshot 中定位到的条目，不得因家族、`contractId` 或外部版本号不一致改记成 `CONTRACT_VERSION_UNRESOLVED`。未提供内部 ID 时，计数得到零个或多个，仍按第 5 节返回 `CONTRACT_VERSION_UNRESOLVED`。这是没有形成唯一候选，不是把已定位候选的身份不一致改写成未解析。

候选所属 `snapshotId` 与输入不一致，或调用方把未完成的读取送入本能力时，前提不成立。这种情况不得记成 `CONTRACT_VERSION_UNRESOLVED`，也不得记成 `UNMAPPED`。本文不为它新增业务错误码。

## 5. 允许实现的行为

批准后只允许实现一个内存纯函数，放置位置见第 9 节。

1. 内部 `contractVersionId` 已提供时，在当前 snapshot 的全部契约条目中按该标识定位。不得先按来源契约家族、`contractId` 或报文外部版本号过滤。定位到则返回该 ID。条目中没有则返回 `CONTRACT_VERSION_UNRESOLVED`，并且不改用外部版本号继续查找。家族、`contractId`、外部版本号或正文哈希与版本行不一致，都不是「ID 不存在」。
2. 内部 `contractVersionId` 未提供时，只在当前 snapshot 的契约条目中，按调用方指定的契约家族和报文外部版本号计数。外部版本号为「未提供」时，只与版本行外部版本号同为「未提供」的条目匹配，不与明确版本号匹配。这是候选唯一性解析，不是完整契约身份校验。
3. 未提供内部标识时，计数恰好一个才返回该 `contractVersionId`。零个或多个都返回 `CONTRACT_VERSION_UNRESOLVED`。多个「未提供」使用同一已有码。不猜最新修订，不从其他 snapshot 补候选。
4. 相同输入每次返回相同结果。不同 snapshot 的条目不得混用。

内部标识已提供并定位成功后，纯函数停止。它不核对报文外部版本号与版本行是否一致。未提供内部标识时，外部版本号只参与上面的计数。计数得到唯一候选之后，ADR-0004「外部版本号一致性校验」仍由后续身份校验流程执行。那个流程才使用 `CONTRACT_IDENTITY_MISMATCH`。本函数不为这条校验增加返回分支。

本能力不产生字段结果，不产生 `ObservedAmount`，不进入金额路径提取或匹配。这些否定约束来自 ADR-0004「提取阻断边界」和「UNMAPPED 的适用范围」。本能力本身不写观测。

## 6. 明确排除的行为

本次授权不包括：

1. snapshot 的选择、创建、校验失败后的跳过，或把三句「最新快照」收成一条新规则。
2. 数据库、MySQL、Kafka、Doris 或其他基础设施访问。
3. 候选集合的读取，以及读取失败后的重试。
4. `contractId`、契约家族身份、候选确定后的外部版本号一致性，以及正文哈希的校验。未提供内部标识时用家族和外部版本号计数，不算完成这些校验。
5. 身份不一致与正文哈希不符同时成立时，选择哪一个已有错误码。
6. Task、Worker 或 Pipeline 的实现。
7. Replay 的创建和 `replayRequestId` 的生成。
8. `taskId`、稳定事件身份，以及 Task Create-or-Get。
9. MySQL 唯一约束和 Kafka offset。
10. 新增错误码、执行状态或持久化字段。

后续流程仍按 ADR-0004 使用已有码，本函数不实现它们：

- 单项家族身份、`contractId` 或外部版本号不一致：`CONTRACT_IDENTITY_MISMATCH`。
- 单项正文哈希不符：`CONTRACT_VERSION_HASH_MISMATCH`。
- 身份不一致和哈希不符同时成立时，保留哪一个已有码仍由 IR-05 决定。本轮不关闭、不绕过 IR-05，也不新造错误码。

## 8. 最小单元测试范围

批准后的实现任务只增加纯单元测试。不连接 MySQL、Kafka 或 Doris，不启动 Spring。

至少覆盖：

1. 内部 ID 已提供，且存在于当前 snapshot 的契约条目中，返回该 ID。同一次输入里即使还有其他家族、其他外部版本号，也不改选。
2. 内部 ID 已提供，但当前 snapshot 的契约条目中没有该 ID，返回 `CONTRACT_VERSION_UNRESOLVED`，且不改按外部版本号查找。
3. 内部 ID 已提供，ID 存在于当前 snapshot，但条目所属家族与来源家族不一致。纯函数仍返回该 ID。家族拒绝留给后续身份校验，测试不断言本函数返回 `CONTRACT_IDENTITY_MISMATCH`。
4. 内部 ID 已提供，ID 存在，但报文外部版本号与版本行外部版本号不一致，包括一方为「未提供」、另一方不是。纯函数仍返回该 ID。后续身份校验才负责 `CONTRACT_IDENTITY_MISMATCH`。
5. 内部 ID 未提供。当前 snapshot 中按指定家族和明确外部版本号恰好一个候选，返回该 `contractVersionId`。同一 snapshot 里其他家族的同号条目不计入。
6. 内部 ID 未提供。指定家族下，报文外部版本号为「未提供」，且恰好一个版本行同为「未提供」，返回该 `contractVersionId`。「未提供」不与明确版本号计成同一个候选。
7. 内部 ID 未提供时，指定家族和外部版本号对应零个候选，以及对应多个候选，都返回 `CONTRACT_VERSION_UNRESOLVED`。
8. 指定家族下有多个「未提供」候选时，返回同一已有码，不猜最新，不挑出其中一条。
9. 不同 snapshot 的契约条目不得混用。一次输入只使用本次 `snapshotId` 的条目。
10. 相同输入重复调用，结果相同。

这些测试只证明唯一性定位和计数。它们不得写成：本函数已经完成家族身份校验、`contractId` 校验、候选确定后的外部版本号一致性校验或正文哈希校验。

不在这组测试中：snapshot 如何被选中、读取失败后的重试、双失败时的错误码优先级、Task、Replay、offset，以及 `UNMAPPED` 的字段级命中。

空集合在读取已经完成、且该 snapshot 契约条目为零条时，内部 ID 视为不在条目中，未提供内部 ID 时计数为零。两种都返回 `CONTRACT_VERSION_UNRESOLVED`。测试不得把空集合写成读取失败的替身。
