## 1. 背景与依据

ADR-0004 状态是 Accepted。它接受方案 C：在已经固定的金额映射快照内、金额路径提取之前解析契约版本。范围写明不包含表结构、索引、事务和 Java 实现，也不新增执行状态或错误码。

## 2. 已接受规则与 ADR 章节

已接受且本授权直接使用的规则在 ADR-0004「决策」节：

- 「snapshotId 固定规则」：解析发生在已经固定的 `snapshotId` 内。
- 「contractVersionId 输入优先级」：已经给出内部 `contractVersionId` 时，直接采用该值作为候选，不再用外部版本号在多个修订中选择。没有给出时，才按契约家族和外部版本号查找。报文外部版本号为「未提供」时，只与外部版本号同为「未提供」的修订比较。
- 「零个、一个、多个修订」：恰好一个才确定 `contractVersionId`。零个或多个都阻断，码为已有的 `CONTRACT_VERSION_UNRESOLVED`。多个「未提供」不另设结果，也不猜最新修订。
- 「契约家族身份校验」：版本表里仍有、但当前快照契约条目里没有的版本，结果同样是 `CONTRACT_VERSION_UNRESOLVED`。
- 「UNMAPPED 的适用范围」：版本尚未确定时，不允许产生 `UNMAPPED`。

当前 `06-03-02-03` 第 8 节第 2 步、`06-03-03-01` 第 8 节和 Pipeline `06-03-03-06` 第 2 节已经写出与上述条款相同的计数和阻断结果。台账 IR-18A 记录这八条现行规则一致，同时写明该核验不授权修改 ADR。本文沿用这些已写出的计数规则，不重新决定它们。

ADR-0004 第 155 行仍写 Java 实现要等指定文档修订之后。ADR 开篇和 `docs/decisions/README.md` 仍保留接受当时「下游旧条款尚未同步」的说明。本文不删除、不改写这些句子。

## 4. 输入与输出

后续实现只接受以下输入：

| 输入 | 含义 |
| --- | --- |
| `snapshotId` | 调用方已经固定的快照标识。本能力不选择、不创建、不跳过快照 |
| 外部版本号 | 报文上的外部版本号。官方没有版本号时，这个值就是「未提供」。它不是 Java 空引用，也不等于「没有内部 `contractVersionId`」 |
| 内部 `contractVersionId` | 可选。未提供该标识，与外部版本号为「未提供」，是两件不同的事 |
| 候选集合 | 调用方已经完成读取后，交给本能力的该快照可见候选。每个候选至少带有自己的 `contractVersionId`、所属 `snapshotId` 和版本行上的外部版本号 |

调用前提：

- 候选集合只属于输入中的那一个 `snapshotId`，并且只属于调用方已经选定的一个契约家族。家族身份、`contractId` 和正文哈希不由本能力校验。
- 读取失败或候选数量尚未得出时，调用方不得调用本能力，也不得用空集合代替这次失败。
- 空集合只表示读取已经完成且匹配结果为零个候选。

输出只有两种：

- 恰好一个候选：返回该候选的 `contractVersionId`。
- 零个或多个候选：返回已有错误码 `CONTRACT_VERSION_UNRESOLVED`。

不返回 `UNMAPPED`。不返回 `CONTRACT_IDENTITY_MISMATCH` 或 `CONTRACT_VERSION_HASH_MISMATCH`。不新增错误码、执行状态或持久化字段。

候选所属 `snapshotId` 与输入不一致，或调用方把未完成的读取送入本能力时，前提不成立。这种情况不得记成 `CONTRACT_VERSION_UNRESOLVED`，也不得记成 `UNMAPPED`。本文不为它新增业务错误码。

## 5. 允许实现的行为

批准后只允许实现一个内存纯函数，放置位置见第 9 节。

1. 内部 `contractVersionId` 已提供时，只判断该标识是否出现在输入候选集合中。出现则返回它，不再按外部版本号重选。不出现则返回 `CONTRACT_VERSION_UNRESOLVED`，也不改用外部版本号继续查找。
2. 内部 `contractVersionId` 未提供时，只在该集合内比较外部版本号。双方都是「未提供」才算对应。「未提供」不与明确版本号匹配。
3. 比较结果恰好一个时，返回该 `contractVersionId`。
4. 比较结果为零个或多个时，返回 `CONTRACT_VERSION_UNRESOLVED`。多个「未提供」使用同一已有码。
5. 相同输入每次返回相同结果。不得猜测最新修订，不得读取另一份快照的候选来补齐结果。

本能力不产生字段结果，不产生 `ObservedAmount`，不进入金额路径提取或匹配。这些否定约束来自 ADR-0004「提取阻断边界」和「UNMAPPED 的适用范围」。本能力本身不写观测。

## 6. 明确排除的行为

本次授权不包括：

1. snapshot 的选择、创建、校验失败后的跳过，或把三句「最新快照」收成一条新规则。
2. 数据库、MySQL、Kafka、Doris 或其他基础设施访问。
3. 候选集合的读取，以及读取失败后的重试。
4. `contractId`、契约家族身份和正文哈希的完整校验。
5. 身份不一致与正文哈希不符同时成立时，选择哪一个已有错误码。
6. Task、Worker 或 Pipeline 的实现。
7. Replay 的创建和 `replayRequestId` 的生成。
8. `taskId`、稳定事件身份，以及 Task Create-or-Get。
9. MySQL 唯一约束和 Kafka offset。
10. 新增错误码、执行状态或持久化字段。

单项身份不符时应使用 `CONTRACT_IDENTITY_MISMATCH`，单项哈希不符时应使用 `CONTRACT_VERSION_HASH_MISMATCH`。这两项规则已经由 ADR-0004 分别写出，但不在本次函数内实现。

## 8. 最小单元测试范围

批准后的实现任务只增加纯单元测试。不连接 MySQL、Kafka 或 Doris，不启动 Spring。

至少覆盖：

- 未给内部标识，明确外部版本号恰好一个候选，返回该 `contractVersionId`。
- 未给内部标识，外部版本号为「未提供」且恰好一个同值候选，返回该 `contractVersionId`。
- 「未提供」不与明确外部版本号计为同一个候选。
- 明确外部版本号零个候选，返回 `CONTRACT_VERSION_UNRESOLVED`。
- 「未提供」零个候选，返回同一已有码。
- 明确外部版本号多个候选，返回同一已有码，且不选取其中较新的一个。
- 多个「未提供」返回同一已有码。
- 已给内部标识且它在集合中，返回该标识，即使外部版本号还能对应其他行。
- 已给内部标识但它不在该集合中，返回 `CONTRACT_VERSION_UNRESOLVED`，且不改按外部版本号查找。
- 同一输入重复调用，结果相同。
- 两份快照的候选分别输入时，结果只来自本次输入的集合。

不在这组测试中：snapshot 如何被选中、读取失败后的重试、家族身份、正文哈希、双失败优先级、Task、Replay、offset，以及 `UNMAPPED` 的字段级命中。

空集合在读取已经完成时按零个候选断言。测试不得把空集合写成读取失败的替身。
