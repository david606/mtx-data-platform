## 2. 当前持久化设计现状

已经接受或已经写进当前设计正文的事实：

- 领域结果和执行管理信息分开保存。任务状态变化不覆盖观测、标准化结果或计算结果。见 Pipeline 第 9 节。
- 观测与当次匹配结果按观测身份一次写出，不允许只有观测没有匹配结果，也不允许事后覆盖 `mappingStatus`。
- 观测身份是 `rawPayloadRef + snapshotId + contractVersionId + fieldPath`。解析器版本不进入该身份。
- `UNMAPPED` 和 `CONFLICT` 都保存观测。`MappingConflictDecision` 创建后不可修改。新快照不修改旧快照和历史观测。见 ADR-0003。
- 契约版本在已经固定的 `snapshotId` 内、金额路径提取之前解析。零个或多个修订是 `CONTRACT_VERSION_UNRESOLVED`，不降成 `UNMAPPED`。原任务重试不换快照。新配置上的重新处理是显式重放。见 ADR-0004 和 Pipeline 第 2 节。
- 标准化逻辑身份与 `versionFixKey` 不是同一个键。版本固定记录必须在 `NormalizedAmount` 写出前成功保存。
- 字段结果键是 `taskId + contractVersionId + fieldPath`。失败不写入 `ObservedAmount`。
- 审计身份与应用日志分开。物理存储、唯一索引、锁、隔离级别和 DDL 都尚未设计。
- `docs/database/` 和 `sql/` 没有已确认模型。06-03-02-03 中的 MySQL 表是“若配置库采用 MySQL”的建议，决策接受前不能建表。

没有物理表，也没有已经批准的存储产品。逻辑实体数量不等于表数量。

## 3. 持久化对象全景

清单里的 18 个名字分六类，合计 18。

| 分类 | 数量 | 对象 |
| --- | --- | --- |
| 已有明确逻辑实体 | 8 | Task、Snapshot、ContractVersion、ObservedAmount、NormalizedAmount、ConflictDecision、AuditRecord、RawPayloadReference |
| 已有逻辑身份，无物理模型 | 4 | TaskAttempt、TaskExecutionContext、ExtractedFieldResult、ReplayRequest |
| 阶段性数据，不一定独立成表 | 2 | MappingResult、ProcessingErrorRecord |
| 当前不应建立 | 2 | QualityCheckResult、WriterExecutionRecord |
| 原始报文正文，介质未选定 | 1 | RawPayload |
| 分析副本，物理模型尚未设计 | 1 | Doris 分析数据 |

RawPayload 是原始报文正文，不是 OLAP 分析副本，也不是 `rawPayloadRef`。它有保存需求，但没有已确认介质，所以不把它算成已经选定的一种库表。

MappingResult 在当前 Pipeline 里不是独立实体。匹配结果和 `mappingStatus` 属于同一次写出的 `ObservedAmount`。ConflictDecision 是配置侧的不可变决定，不是运行时那条 `CONFLICT` 观测。

QualityCheckResult 和 WriterExecutionRecord 在当前金额链路里没有定义。本轮不补造。`persistObservation` 的 `CREATED` 或 `ALREADY_EXISTS` 是端口返回，不是写入账本。

ProcessingErrorRecord 不单建通用错误表。任务阻断、字段失败和完整性异常已经有各自的逻辑记录。新增一种错误实体会和这些记录重复。

## 4. 存储职责划分

平台需要四类存储职责。这不是四种已经选定的数据库。

### 4.1 事务型元数据

承担任务、尝试、执行上下文、已发布快照、契约版本、冲突决定、重放请求标识和审计记录的权威。字段结果在逻辑上属于金额处理执行结果。它可以使用同一种事务型产品保存，但权威只有一份，不能在元数据和金额结果里各写一份。是否独立成表未决定。

这类存储必须能表达唯一性和“创建或返回已有记录”。Pipeline 已经禁止用 JVM 本地锁代替跨 Worker 幂等，但没有批准索引、锁或隔离级别。本轮也不设计它们。

06-03-02-03 的配置命令幂等表不写入观测、标准化结果或版本固定记录。配置发布和金额结果是两类权威。

### 4.2 原始报文

`rawPayloadRef` 是引用标识。它出现在任务权威输入和观测身份里，不能据此推断报文字节一定放在关系库。

报文正文是不可变字节。处理不修改原文。已有观测的恢复不读取正文。没有观测时才按权威引用读取。读不到沿用 `PAYLOAD_REF_INVALID`，不产生观测。

正文可以放在对象存储一类的不可变介质，也可以放在关系库的大字段。两条都还没有证据证明哪一条适合本项目的报文大小和保留要求。本轮不选产品，不设保留天数。权威引用和正文哈希若存在，应能从任务或报文记录复核，不能只留在应用日志里。

### 4.3 金额处理结果

权威包括 `ExtractedFieldResult`、`ObservedAmount`、与观测一次写出的匹配结果、版本固定记录和 `NormalizedAmount`。`ExtractedFieldResult` 的逻辑归属是金额处理执行结果。物理上允许与事务型元数据使用同一种存储产品，是否独立成表仍未决定。无论是否同产品或是否同表，字段结果只有一个权威来源。失败的字段结果不写入 `ObservedAmount`。计算结果身份尚未冻结，当前没有已发布计算规则时不写计算结果。

这些结果引用 `snapshotId`、`contractVersionId` 和 `rawPayloadRef`，但不替代配置库和原文库。观测一旦写出就不可覆盖。标准化结果按自己的逻辑身份保存，不回写观测。

### 4.4 OLAP 分析

ADR-0001 确认 Apache Doris 是 OLAP 方向。ADR-0005 把服务器版本接受为 4.0.7。库、表、分桶和字段都未确认。这个版本不改变 Doris 与事务型元数据的边界：Doris 不保存任务终态的权威，不执行配置发布事务，不保存审计的权威记录，也不代替原文读取。

平台数据分层方向是 ODS、DWD、DIM、DWS、ADS。本轮尚未完成各层的物理模型、表结构和层间加工规则。当前仓库没有这些层的已确认表，不等于这五层已经被取消。分析层只承接已经在权威存储中形成的不可变结果副本。本轮不设计这些表。

不能假设关系库和 Doris 共用一个本地事务。分析副本延迟或失败，不回滚已经提交的观测，也不把 Doris 写入成功当成任务终态的依据。

## 5. 实体身份与生命周期

身份规则以现有设计为准，不新增字段，也不发明 `taskId` 或 `replayRequestId` 的生成算法。

任务相关身份分成五件已经写明的事，不能合成一个通用键：

| 身份 | 已有规则 | 尚未决定 |
| --- | --- | --- |
| 稳定接入事件身份 | 只在来源契约已经声明时，才是非重放任务的幂等身份。Pipeline 第 4.2 节 | 来源没有声明时如何识别重复投递。待来源契约确认 |
| 内部 `taskId` | 逻辑任务的内部标识。重复投递和技术重试沿用它 | 生成算法待存储设计 |
| 普通重复投递 | 来源已声明稳定事件身份时，回到原 `taskId`。即使本次 `rawPayloadRef` 不同或缺失，或者看到的 `receivedAt` 不同，也不新建任务，不替换第一次保存的权威引用和权威 `receivedAt`，不创建 `replayRequestId` | 没有稳定事件身份的来源不适用这条规则 |
| 显式重放 | 新 `taskId`，调用方给出 `replayRequestId`。同一个 `replayRequestId` 返回已有重放任务。新任务另建观测，不覆盖旧观测 | `replayRequestId` 的生成算法未设计，且不能写入观测身份 |
| 没有稳定事件身份 | 不能假设每个来源都有 `sourceEventId` 或 `sourceMessageId`。不能用来源金额、`rawPayloadRef` 或 `receivedAt` 拼键，也不能写成已经具备跨投递幂等 | 等来源契约声明后再定。确认前不发明算法 |

| 对象 | 身份 | 生命周期要点 |
| --- | --- | --- |
| Task | 见上面五件身份。`receivedAt` 和 `rawPayloadRef` 不是任务身份 | 只有来源已声明稳定事件身份时，重复投递才回到原任务并保留第一次保存的权威引用和权威 `receivedAt`。终态提交后不覆盖。没有稳定事件身份时，任务幂等待决策 |
| TaskAttempt | `taskAttemptId` 表示一次尝试。不进入观测身份、字段结果键或阻断身份 | 技术重试可以新建。旧尝试不能覆盖已完成字段结果和已提交终态 |
| TaskExecutionContext | 任务上已经固定的快照、`parserVersion`、契约版本和正文哈希 | 第一阶段固定快照和解析器，第二阶段只在胜出快照内固定契约版本。原任务重试不改选 |
| Snapshot | 已发布批次。06-03-02-03 写 `batchId` 就是 `snapshotId` | 发布后不修改旧快照。审核通过本身不产生快照 |
| ContractVersion | `contractVersionId` 加封存正文哈希 | 正文变化是新版本。提取不在运行时重分配修订号 |
| RawPayloadReference | 任务第一次保存的权威引用 | 重复投递带来的新引用或缺失引用不替换它 |
| RawPayload | 字节本身还没有技术主键方案 | 不覆盖。保留期限待确认 |
| ExtractedFieldResult | `taskId + contractVersionId + fieldPath`。逻辑上属于金额处理执行结果 | 同一键返回已有结果，内容不一致是完整性异常，失败不写观测。物理上可以与事务型元数据使用同一种产品，权威只有一份。是否独立成表未决定 |
| ObservedAmount | 四段观测身份 | 创建后不改金额、`mappingStatus`、`presence` 和 `rawText`。换快照才是另一条观测 |
| MappingResult | 无独立身份。它是观测写出时的匹配内容 | 不单独更新 |
| NormalizedAmount | `normalizationIdentity`。它含观测身份和两个规则版本，不含 `taskId` | 相同身份且内容相同返回已有结果。内容不同是完整性异常，不覆盖 |
| 版本固定记录 | `versionFixKey = observationIdentity + taskId + 阶段“标准化”` | 固定成功后重试读取原版本。它不是标准化结果 |
| ConflictDecision | 配置决定自己的身份。变化时另建一条，不修改原决定 | 创建后不可修改，封存后不追加证据 |
| ReplayRequest | 调用方给出的 `replayRequestId`。生成算法未设计，且不进入观测身份 | 同一个标识返回已有重放任务。普通重复投递不能创建它 |
| AuditRecord | 阻断身份、迟到阻断身份或完整性审计身份。不含 `taskAttemptId` | 不参与已提交终态。不把审计失败写成有效阻断 |
| Doris 分析数据 | 无已确认身份 | 尚未设计。不能替代上面任一权威身份 |

显式重放是新 `taskId`，保留原任务关联，可以按该次策略重新固定快照，并遵守 ADR-0003 另建观测。不按订单号或原文自动重放。

## 6. 数据关系与引用完整性

| 关系 | 当前规则 | 引用方式 |
| --- | --- | --- |
| Task 与 TaskAttempt | 多次尝试共用一个 `taskId` | 业务标识。尝试不是任务的覆盖版本 |
| Task 与 Snapshot | 非重放任务只固定一份胜出快照 | 保存 `snapshotId`。不在运行时改挂另一份 |
| Task 与 ContractVersion | 只在胜出快照内确定权威版本 | 保存 `contractVersionId` 和 `contractBodySha256` |
| RawPayload 与 ObservedAmount | 观测使用权威引用，不保存第二份可变正文 | 业务标识。正文介质可以不同 |
| ObservedAmount 与 MappingResult | 同一次写出 | 强逻辑关联。不是两张可以单独提交的权威表 |
| ObservedAmount 与 NormalizedAmount | 标准化读取已经形成的观测，不回写观测 | 业务标识。`UNMAPPED` 和 `CONFLICT` 没有标准化结果 |
| ConflictDecision 与观测 | 运行时命中一条决定才形成 `CONFLICT` 观测。决定本身在配置侧 | 观测记录决定标识。不回写决定 |
| Task 与 ReplayRequest | 只属于显式重放任务 | 业务标识。一个重放请求对应一个重放任务 |
| Task 与 AuditRecord | 审计带 `taskId`，但不改变已提交终态 | 业务标识。审计可以独立保留 |
| 处理结果与 Doris | 分析数据若存在，只能复制已提交结果 | 异步副本。没有跨库外键，也没有跨库原子提交 |

已发布快照、已封存契约版本、已写出观测、已写出标准化结果、已创建冲突决定和已写入审计都保持不可变。任务终态可以在合法迁移中提交一次，提交后不覆盖。

本轮不规定数据库外键。配置库、原文介质、金额结果和 Doris 不一定在同一个产品里，跨介质外键没有已批准方案。同一事务型存储内部是否使用外键，留到物理模型设计，并要先选定产品。

## 7. 历史保留与归档

不设定保留天数、容量和冷热分层产品。

| 数据 | 当前可以确定的保留要求 | 尚未确定 |
| --- | --- | --- |
| 原始报文 | 已形成观测的恢复不依赖再次读到正文。尚未形成观测时，正文读不到就不能产生观测 | 在线保留、归档和删除条件 |
| 配置快照 | 旧快照不修改。历史观测必须还能指向它 | 归档介质 |
| 契约版本 | 被观测引用的版本和正文哈希不能消失或被改写 | 无观测引用的草稿能否删除 |
| 金额观测 | 不覆盖、不删除后改写成另一种 `mappingStatus` | 归档是否仍算权威 |
| 标准化结果 | 不覆盖已有内容 | 同上 |
| 冲突决定 | 不修改。变化另建 | 无 |
| 审计记录 | 不参与终态，不能为了补审计重开任务 | 物理保留和恢复扫描 |
| 任务与尝试 | 终态和字段结果要能再次读到 | 尝试日志保留多久 |
| Doris | 没有保留规则，因为它还没有模型 | 全部 |

在线、归档和冷存储只是以后的保留位置。它们不是本轮选出的产品。法规要求在仓库中没有记录，标为待确认。

## 8. 存储技术选型比较

比较的是职责适配，不是基准测试。下表没有引用新的外部官方文档，也没有在 2026-11-25 复核厂商支持政策。具体性能、许可和托管限制待确认。

| 维度 | MySQL 8.0.46（ADR-0005 已接受，尚未接入） | Apache Doris 4.0.7 | 对象存储 |
| --- | --- | --- | --- |
| 事务能力 | 适合配置发布、任务终态和“创建或返回已有” | 不作为这些事务的权威 | 不适合任务状态 |
| 唯一性约束 | 适合表达已有逻辑身份。具体索引未设计 | 不承担观测和任务的权威唯一约束 | 适合不可变对象键，不适合任务终态 |
| 并发写入 | 可以承接 Pipeline 已写的并发返回契约。隔离级别未选 | 不替代该契约 | 不解决先查后插 |
| 历史查询 | 适合按标识读取权威记录 | 适合以后的分析查询 | 适合按引用读取原文 |
| 报文正文 | 可以存小报文，但是否合适取决于报文大小，当前没有该数据 | 不作为原文权威 | 适合不可变字节，产品未选 |
| 增长、备份、运维、扩展 | 未评估 | 未评估。只确认 OLAP 方向 | 未评估 |

MySQL 8.0.46 是已接受的目标服务器版本。06-03-02-03 的建议表只说明结构可以怎样设计，不是已批准的物理模型。PostgreSQL 不是当前目标。本表不把 8.4 的行为写成 8.0.46 已验证能力。

Doris 4.0.7 不替代事务库。对象存储不保存任务状态。Redis 和 Flyway 不在本轮引入。

## 9. 模块职责映射

不新增模块，不把 JDBC、MyBatis 或 Doris 客户端放进 `platform-core`。

| 模块 | 持久化相关职责 |
| --- | --- |
| `platform-common` | 不放业务流程，不放存储客户端 |
| `platform-core` | 只放存储无关的模型和端口。端口不带具体数据库类型 |
| `platform-messaging` | 只承接消息适配。当前没有 Kafka 客户端 |
| `platform-connector` | 将来提供已经取到的报文。不决定原文介质 |
| `platform-transform` | 提取、匹配和标准化计算。不写存储 |
| `platform-quality` | 当前没有质量结果实体，不提前写存储 |
| `platform-writer` | 写出已经形成并通过门禁的领域结果。不决定任务终态和配置发布 |
| `platform-pipeline` | 按端口编排。不依赖 Writer 实现，不访问具体存储 |
| `app-admin` | 配置、审核和发布。不执行金额链路。当前允许依赖只有 common、core、messaging |
| `app-worker` | 装配并执行。可以依赖 writer 等实现模块 |

Admin 与 Worker 都要使用配置和任务端口，但 Admin 不能依赖 Writer。Core 又不能依赖 JDBC。因此共享存储适配器目前没有一个既符合依赖矩阵、又允许放置数据库客户端的模块。本轮不新增 `platform-persistence`，也不把适配器放进 Core。适配代码的模块归属待决策。

## 10. 推荐存储架构

这是建议，不是 Accepted 决策。前提是后续物理设计仍遵守 ADR-0002、ADR-0003 和 ADR-0004。

1. 使用一类具备事务和唯一约束的元数据存储，同时作为任务、配置、审计和金额结果的权威。这样避免在 IR-09 关闭前引入跨存储事务。金额结果与任务状态仍按 Pipeline 第 9 节分开记录，只是可以放在同一种产品中。
2. 原文正文单独评估对象存储或关系库大字段。权威引用留在任务上下文。不把正文介质当成任务状态库。
3. Doris 只接收已经提交的不可变结果副本。它不是配置库、任务库或审计库。
4. 不建 MappingResult、QualityCheckResult、WriterExecutionRecord、通用 ProcessingErrorRecord 的独立权威表。
5. 版本固定记录和字段结果保留为逻辑记录。物理上可以和任务或金额结果放在同一产品，但是否独立成表留给物理模型。

若元数据产品和金额结果产品必须拆开，先完成提交点和失败读取规则，再拆。本轮不冻结这个拆分。

## 12. 风险与实施约束

- 把 06-03-02-03 的 MySQL 建议表当成已经批准的物理模型。
- 把 Doris 主键模型当成任务发布事务的替代。
- 因为有 `rawPayloadRef` 就断定原文在某个数据库。
- 把 `mappingStatus` 拆成另一张可单独更新的权威表，从而违反一次写出。
- 修改已创建的 ConflictDecision，或用新快照改写旧观测。
- 用应用日志代替审计记录。
- 为了放 JDBC 而增加第十一模块，或让 Core 依赖数据库客户端。
- 在 R15、P-03、P-06 关闭前把某一种快照跳过规则或错误码优先顺序写进表约束。

## 14. 本轮结论

1. 需要四类存储职责：事务型元数据、原始报文正文、金额处理结果、OLAP 分析副本。不需要据此选定四种数据库。
2. 金额观测和事务型元数据不是必须使用同一个数据库。早期建议放在同一种具备事务和唯一约束的产品中，因为当前不能假设跨存储原子提交。
3. 原始报文正文的介质未选定。`rawPayloadRef` 只是权威引用。
4. Doris 4.0.7 是已接受的 OLAP 服务器版本，只保存分析副本。它不保存任务状态、配置发布和审计权威。ODS、DWD、DIM、DWS、ADS 是数据分层方向。各层物理模型、表结构和加工规则尚未设计，这不表示五层已经被取消。客户端版本未锁定。
5. `ObservedAmount` 和 `NormalizedAmount` 独立持久化。它们的身份不同，标准化不回写观测。
6. MappingResult 不需要独立物理实体。它随观测一次写出。
7. ConflictDecision 靠“创建后不修改、变化时另建一条”保证不可变。本轮不设计触发器或权限。
8. Task 的幂等只在来源契约已经声明稳定事件身份时成立。`taskId` 是内部标识。显式重放是另一个任务。没有稳定事件身份时不发明幂等键。TaskAttempt 是一次尝试，执行上下文是该任务已经固定的快照和契约版本。不另建通用阶段执行实体。
9. 配置快照发布后不修改。历史观测继续引用原 `snapshotId`。
10. 审计使用已有阻断身份或完整性审计身份。普通日志只关联标识，不代替审计。
11. 历史重放是新任务和新的观测身份，调用方提供 `replayRequestId`。它不覆盖旧观测，也不自动按订单号发生。
12. 关系库与 Doris 之间没有已批准的共同事务。分析副本失败不回滚权威结果，权威结果也不以 Doris 成功为准。
13. 需要强唯一性的是已经写明的逻辑身份：来源已声明的稳定事件任务、重放请求、观测身份、标准化身份、版本固定键、字段结果键、审计身份，以及已发布快照和冲突决定的各自身份。没有稳定事件身份的来源还没有幂等键。物理约束尚未设计。
14. 已发布快照、被引用的契约版本、观测、标准化结果、冲突决定和审计不能随意删除。保留天数待确认。
15. 还不具备进入物理数据库模型设计并产出 DDL 的条件。服务器版本已经确定，原文介质、物理唯一约束和适配器归属仍未决定。不能建表。
