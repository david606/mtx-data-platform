## 3. 当前架构和工程状态

已确认并已落地的只有工程骨架：

- 根 POM 聚合 ADR-0002 的十个模块。依赖矩阵与各模块 POM 一致。

- JDK 25、Spring Boot 3.5.16、JUnit Jupiter 5.12.2 与 ADR-0001 一致。
- MyBatis-Plus 3.5.18.1 只在根 POM 的 `dependencyManagement`。Kafka、Quartz、Doris 客户端和 DolphinScheduler 都没有进入模块依赖。

已经设计、尚未实现的是金额处理链路的逻辑契约。Pipeline 文首写明第二十一轮审查没有新的架构问题，P2-02 和 P3-01 已关闭，文档仍未冻结，E2E-001 至 E2E-177 均未执行。0 个标准类型是 `ACTIVE`，已确认生产映射数量是 0。

尚未确定的包括 Redis、Flyway、MySQL 驱动和连接参数、Doris 客户端与库表、调度实现所在的现有模块，以及本报告第 6 节列出的执行语义缺口。MySQL 8.0.46 和 Doris 4.0.7 已经是目标服务器版本。

## 4. 六个专项评估

### 4.1 总体架构与工程结构

模块化骨架和独立 Worker 应用与 ADR-0002 一致。Admin 不执行数据处理。Pipeline 模块没有 Quartz、DolphinScheduler 或具体处理实现的依赖。Core 没有 Spring、Kafka、JDBC、MyBatis 或 Quartz 依赖。

这只说明结构没有被打破。连接器、转换、质量检查、写入、Pipeline 编排和调度都还没有代码。调度文档写明这些职责尚未实现。

结论：结构可以继续承载实现。金额处理还不能按未冻结文档直接编码。

### 4.2 持久化模型与数据一致性

| 对象 | 当前证据 | 判断 |
| --- | --- | --- |
| 任务与尝试 | 有 `taskId`、`taskAttemptId` 和任务状态。生成算法待存储设计 | 有逻辑身份，没有物理实体 |
| 阶段执行 | 有快照固定和契约固定两阶段，没有通用阶段执行实体 | 未建模 |
| 配置快照与契约版本 | 06-03-02-03 有建议表。产品版本已由 ADR-0005 定为 MySQL 8.0.46，建议表仍不是已批准模型 | 建议，不是已批准模型 |
| 原始报文引用 | `rawPayloadRef` 是权威引用。原文保存位置和保留策略未定 | 身份有，介质未定 |
| ObservedAmount | 四段观测身份和不可覆盖规则已写明 | 没有物理唯一约束 |
| 映射结果 | 与观测一次持久化，状态只有 `MAPPED`、`UNMAPPED`、`CONFLICT` | 没有独立物理表 |
| 标准化结果 | `normalizationIdentity` 与 `versionFixKey` 已分开 | 版本分配未设计 |
| Conflict Decision | ADR-0003 规定创建后不可修改 | 没有已批准的表 |
| 质量检查结果 | 模块存在，没有结果实体 | 未设计 |
| Writer 写入记录 | 端口返回 `CREATED` 或 `ALREADY_EXISTS`。Doris 库表未确认 | 未设计 |
| 重放 | 新 `taskId` 加调用方 `replayRequestId`。生成算法未定 | 逻辑边界已有 |
| 审计 | 阻断、迟到和完整性审计的逻辑身份已有。物理存储和恢复未选型 | 不能建表 |

MySQL 8.0.46 是事务型元数据的目标版本，Doris 4.0.7 是 OLAP 服务器版本。两者都尚未接入。不能把任务状态、配置和审计放入 Doris，也不能把 06-03-02-03 的 MySQL 建议表当成已经批准。金额结果是否与元数据拆库仍是 IR-09。

### 4.3 并发与幂等

已经写明的逻辑规则是：稳定接入事件身份决定非重放任务是否回到原 `taskId`；第一次保存的 `rawPayloadRef` 和 `receivedAt` 保持权威；已有观测先返回，不覆盖；同一观测并发时只保留一条有效观测和一份匹配结果；显式重放是新任务。

尚未批准的是物理唯一约束、锁、隔离级别，以及来源没有稳定事件身份时的幂等键。E2E-044 明确写着物理索引未实现且该行未执行。先查询再插入的竞态被文档禁止，但没有数据库机制实现这项禁止。

不同 `snapshotId` 形成不同观测身份，因此不同快照在逻辑上隔离。快照选择本身仍受 R15 约束。

### 4.4 事务边界与一致性

Pipeline 规定观测、版本固定和标准化结果不共用一个长事务，失败不覆盖已写出的领域结果，也不声称已有补偿事务。任务终态和审计写入失败被定义成可同时观察到的不同结果。

没有已批准的任务领取事务、阶段事务或跨存储事务。Kafka 尚未接入，不能假设消息消费和数据库提交是一个本地事务。Doris 表也不存在，不存在已经验证的跨库一致性。

### 4.5 Worker 执行与故障恢复

当前 Worker 只是能够启动的 Spring Boot 进程。没有注册、领取、所有权、心跳、租约、超时检测、宕机识别、断点续跑或人工恢复设计。

Pipeline 有任务状态和合法迁移：`RUNNING` 可以进入四个互斥终态或 `RETRY_WAITING`，`RETRY_WAITING` 可以回到 `RUNNING`。这不是 Worker 所有权状态机。文档没有证明旧 Worker 在新的 `taskAttemptId` 开始后如何被拒绝，除了终态提交必须读取已持久化依据。哪些失败可以进入 `RETRY_WAITING` 仍待确认。

因此不能回答租约时长、心跳间隔或重试次数。这些参数没有证据。

### 4.6 审计与可观测性

Pipeline 把执行日志和审计记录分开：日志关联已有标识，审计使用阻断身份或完整性审计身份，并且不参与已提交终态。观测保留快照、契约版本和正文哈希，所以已形成的金额结果在逻辑上可以回到当时的规则。显式重放要求调用方给出 `replayRequestId`，但没有操作者审计模型。

用户操作审计、配置变更的不可覆盖保留、Worker 运行审计、指标和链路追踪都没有已确认设计。审计恢复扫描尚未选型。建议中的技术计数没有进入现有系统。

## 8. 风险

1. 把 06-03-02-03 的 MySQL 建议表直接执行。ADR-0005 只接受 MySQL 8.0.46 这个版本，不批准那些表。
2. 在唯一约束确定前写入观测，可能产生同一身份的两条有效结果。
3. 在 R15 关闭前实现任务创建，失败快照会被某一次实现自行跳过或自行停住。
4. 在 P-03、P-06 关闭前编码，错误码会偏离已有码表。
5. 在 Worker 所有权确定前运行多个进程，过期尝试可能提交结果。
6. 用两个应用上下文测试或构建成功，宣布 E2E-001 至 E2E-177 已通过。
7. 把 ADR-0001 里的 Spring Boot 3.5 支持日期和商业支持路径当成已经复核的现行政策，或把 Spring Boot 4.1 当成已经选定的迁移目标。该项只登记为 IR-20，本轮不升级依赖。

## 9. 阶段结论

- 不可以执行数据库 DDL，也不可以把某一份建议表当成最终物理模型。可以开始持久化专项设计。
- 不可以开始金额领域、Pipeline 业务或持久化的 Java 实现。现有骨架不需要为了本结论而改动。
- 不可以开始 Worker 的任务领取和执行实现。
- 不可以开始端到端集成。
- 可以并行的是：R15 的独立 ADR、P-03 与 P-06 的归类决策、IR-18A 的旧说明治理、IR-20 的支持资料核验。这些都不改代码，也不阻塞持久化专项的启动。
- 必须串行的是：存储职责决策，然后是逻辑身份到物理约束的设计，然后是事务提交点，然后是 Worker 恢复。后一步使用前一步的结果。计算身份可以晚于观测持久化，因为当前规则禁止没有计算规则就写计算结果。

## 10. 后续专项顺序

1. 物理唯一约束和仍未完成的物理模型。IR-01 已关闭。IR-02、IR-12、IR-17 仍未关闭。R15、P-03、P-06 作为输入约束；它们的决策可以并行起草，但必须在任务表和错误记录定稿前完成。
2. 并发与幂等的物理约束。它依赖第 1 步的存储产品，不单独发明锁方案。
3. 事务边界。只规定每个已有写入的提交点和失败后读取哪一份记录。
4. Worker 执行与故障恢复。依赖任务和尝试已经有持久化身份。
5. 审计保留与恢复。依赖存储和事务提交点，不把日志方案混进审计表。
6. 实现与验收基线。到这一步才把 E2E 设计转成测试。Pipeline 仍未冻结。IR-18A 只治理旧说明，IR-20 只在生产基线冻结前决策，两者都不插入本顺序的前面。

这个顺序里，数据库产品版本已经由 ADR-0005 确定。当前缺口是逻辑身份还不能落到已批准的物理约束。

持久化专项可以继续。它不得把建议表写成已批准模型，不得直接修改 DDL，不得把逻辑身份当成已经落实的物理唯一约束，不得提前冻结事务边界，也不得确定 Worker 锁、租约或恢复策略。MySQL 8.0.46 不得改写成 8.4，也不得写成仍处于常规维护支持。

- 原始报文的实际保存介质和加密方式。
- 生产环境是否已经存在 V2 库表。当前仓库的 `sql/` 没有已确认脚本。
- ADR-0001 所写 Spring Boot 3.5 开源支持日期、商业支持是否可用，以及 Spring Boot 4.1 与 JUnit 6 的当前兼容性。本轮没有对照官方资料复核，见 IR-20。
- ADR-0004 八条现行规则已在 IR-18A 核对一致。尚未逐句复核全部历史修订段落。ADR 开篇和决策索引仍保留“尚未同步”的旧说明。
