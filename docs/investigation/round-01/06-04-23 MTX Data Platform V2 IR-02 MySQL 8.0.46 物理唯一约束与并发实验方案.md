## 1. 目的与范围

要回答的是：每项实验验证哪条设计假设，需要什么隔离结构和数据，几个会话按什么时序执行，客户端和服务端各留什么证据，什么叫 PASS、FAIL、INCONCLUSIVE，对应第 13 节哪一条关闭条件，以及哪些参数必须先有项目决策。

不在范围内：

- Doris 4.0.7。ADR-0005 的 OLAP 不承担事务幂等。
- 生产库、正式业务表、可直接用于生产的 DDL。
- Java、Maven、新模块、Redis 锁、Inbox、Outbox、DLQ。
- 修改 ADR-0002、ADR-0003、ADR-0004、ADR-0005，或修改金额 Pipeline 与 06-04-11 的执行权规则。
- 为尚无稳定来源身份的 Task 虚构唯一键。IR-03 未给出字段前，任务创建实验不执行。
- 把 RawPayload 字节当成 ObservedAmount 的四段身份。

A 类与 B 类、第 6.3 节、第 6.4 节和第 6.5 节的五种断连，仍按 06-04-19 分开。两种超时错误分开记录。

## 3. 前置条件

实验开始前必须同时满足：

1. 目标服务器版本经 `SELECT VERSION()` 核对为 8.0.46。不是笼统的 8.0，也不是 8.4。
2. 实例是隔离测试库。账号不能访问生产库。实验结束删除本次临时对象。
3. 本节第 4 节里标为「待决策」的参数，凡是该项实验所依赖的，都已有书面决定。决定之前该项保持不可执行，结果不能写成 PASS。
4. 客户端关闭自动重试。连接池若存在，不得在断连后自行重发 `INSERT` 或 `COMMIT`。
5. 记录人能把客户端时间线和服务端连接号对上。对不上则该项为 INCONCLUSIVE。

## 7. A 组：物理唯一约束

共同假设：完整逻辑身份的唯一索引能在 8.0.46 上创建，并且只按完整列判断重复。普通索引、前缀索引、哈希相同和 NULL 都不能代替它。

会话：创建索引用 1 个会话。重复插入用 2 个先后会话，避免和 B 组的同时插入混在一次记录里。

| 编号 | 假设 | 结构与数据 | 判定要点 |
| --- | --- | --- | --- |
| A-01 | 列宽批准后，ObservedAmount 四段、ExtractedFieldResult 三段、Snapshot 的 `snapshotId`、ContractVersion 的 `contractVersionId`、ConflictDecision 的 `conflictDecisionId`、TaskAttempt 的 `taskAttemptId` 都能建成完整列 `NOT NULL` 唯一索引 | 每个实体一张临时表。只放该身份列和一列内容。TaskAttempt 不把 `taskId` 做成唯一键。ConflictDecision 不把正文、证据、窗口或 `bodySha256` 放进唯一键 | PASS：`SHOW INDEX` 显示非前缀的唯一索引，且第二次相同身份 `INSERT` 被拒绝。FAIL：索引不是唯一、只用了前缀，或相同身份插入成功。列宽未批准则不执行 |
| A-01N | `NormalizedAmount` 在空转换版本有 `NOT NULL` 表示之前不能靠唯一索引保证一行 | 不建该唯一索引，不选哨兵 | 决定前没有 PASS。IR-14 写出表示之后另开记录 |
| A-02 | 批准列宽、字符集、行格式和页大小之后，键长不超过该环境的上限 | 用批准后的列定义尝试创建。记录 `information_schema` 中的键长度相关报错原文 | PASS：创建成功且记录了实际上限环境。FAIL：超过上限。环境页大小未记录则为 INCONCLUSIVE |
| A-03 | 相同完整身份不能有两行。不同身份可以各有一行 | 两行只差身份中的一段，例如观测的 `fieldPath` | PASS：相同身份一行，只差一段则两行。FAIL：相同身份两行，或不同身份被拒 |
| A-04 | 选定排序规则后，业务上不同的身份字符串比较结果不同 | 使用项目已选定的规则，准备一组预先写明「业务上必须区分」的字符串。不在实验时改规则 | PASS：这些字符串同时插入成功，唯一冲突只发生在完全相同的字符串。FAIL：不同字符串触发唯一冲突。规则未选则不执行 |
| A-05 | 普通二级索引允许重复身份 | 同一组身份先只建普通索引，两次 `INSERT` 都提交 | PASS：两行都在。随后另建唯一索引的失败不能当成 A-01 已通过。FAIL：把普通索引的拒绝误记成唯一约束 |
| A-06 | 允许 NULL 的唯一索引不能保证「只有一行」 | 对照表的身份列允许 NULL，插入两行 NULL。正式候选列仍是 `NOT NULL`，本项只作反例 | PASS：两行 NULL 都能提交，并在结论中写明因此身份列不能可空。FAIL：把 NULL 重复成功写成唯一约束已生效 |
| A-07 | 哈希相同或前缀相同不是同一业务身份 | 两行原字段不同、摘要相同。另一组只在被截掉的后缀上不同 | PASS：原字段不同的两行都在。若前缀唯一索引把后缀不同的行拒掉，记录为前缀索引不合格，不是身份已唯一。FAIL：用摘要相等代替原字段比较并返回 `ALREADY_EXISTS` |

A 组不覆盖来源事件身份和 RawPayload 字节。版本固定记录是否独立成表仍待决策，不在 A-01 里单建。

## 8. B 组：两个会话的 Create-or-Get

共同假设：先查后插不能保证只有一行。唯一索引加上冲突后的加锁读才能留下一行，且不更新胜出行。

每项 2 个会话。都先 `BEGIN`。可选的先查不是正确性边界，记录里要写明查的是普通读还是加锁读。

| 编号 | 时序 | PASS | FAIL |
| --- | --- | --- | --- |
| B-01 | 两边都先普通读到没有行，再同时 `INSERT` | 只留下一行。冲突方得到唯一冲突错误，再加锁读到胜出行。内容相同则记 `ALREADY_EXISTS`，没有 `UPDATE` | 两行都提交，或冲突后更新了胜出行 |
| B-02 | 会话 A 插入并 `COMMIT` 成功返回后，会话 B 再 `INSERT` | B 唯一冲突，读到 A 的行，不新增 | B 插入成功，或把冲突当成任务成功 |
| B-03 | A 已 `INSERT` 未 `COMMIT`，B 再 `INSERT` | B 等待。A 提交后 B 按冲突读胜出行。A 若回滚，B 可以成为留下的那一行 | B 在 A 仍持锁时已经提交了第二行 |
| B-04 | A 插入后整笔回滚被确认，B 再执行 | B 的新插入可以留下一行。A 没有留下行 | 把 A 的已回滚内容当成权威行 |
| B-05 | 唯一冲突后加锁读到胜出行，不可变内容相同 | `ALREADY_EXISTS`，原行字节级内容不变 | 更新了原行，或没有读到行却返回 `ALREADY_EXISTS` |
| B-06 | 同一身份，不可变内容不同 | 完整性异常，原行保持，不新增错误码 | 覆盖原行，或插入第二行 |

没有唯一索引时 B-01 预期会两行都提交。那次结果只能证明「缺少唯一索引」，不能记成 Create-or-Get 已通过。

## 9. C 组：A 类与 B 类

| 编号 | 假设 | 会话 | PASS | FAIL |
| --- | --- | --- | --- | --- |
| C-01 | Snapshot、ContractVersion、ConflictDecision 的插入不先锁一条 `RUNNING` 任务 | 1。不创建任务行 | 身份插入成功或按 A 类处理唯一冲突。记录中没有任务行锁 | 因缺少 `RUNNING` 任务而拒绝插入 |
| C-02 | B 类领域插入前，同一事务锁定任务行并保持到结束 | 1。准备一条 `RUNNING`、代次匹配、`CURRENT`、无阻断的任务和对应尝试 | 插入提交时，锁视图在提交前仍能看到该任务行锁 | 未锁任务行就插入了领域行 |
| C-03 | 旧代次不能写 | 1。任务已提交代次大于调用方代次 | 插入前回滚，没有新领域行 | 旧代次留下领域行 |
| C-04 | 尝试不是 `CURRENT` 不能写 | 1 | 回滚，无新行 | 写下领域行 |
| C-05 | `status` 不是 `RUNNING` 不能写 | 1 | 回滚，无新行 | 写下领域行 |
| C-06 | 已有有效阻断不能写 | 1 | 回滚，无新行 | 写下领域行 |
| C-07 | B 类唯一冲突后若要再次插入，必须在新事务里重新锁任务行并重做五项校验 | 2。第一笔冲突后，用一个代次已变的新事务尝试再插入 | 再插入被围栏拒绝。已有行只作内容比较，不取得执行权 | 不锁任务行就插入第二笔，或沿用内存代次 |

C 组使用的任务表只含实验需要的代次、状态、阻断标记和尝试归属，不是正式任务模型。校验失败不得被记成第 6.3 节的提交结果不确定。

## 10. D 组：胜出记录读取

状态名称是第 6.4 节。它不是第 6.3 节，也不是第 6.5 节。

每项至少 2 个会话：一个先提交胜出行，另一个制造唯一冲突后再读。D-02、D-03 需要胜出事务仍持有冲突方要等的锁，因此胜出插入先不提交，或由第三个会话持有该索引记录上的锁。持锁方式写入记录。

| 编号 | 场景 | PASS | 不得写成 |
| --- | --- | --- | --- |
| D-01 | 冲突后加锁读到胜出行 | 读完成，进入内容比较 | 读取未完成 |
| D-02 | 加锁读等待 | 等待期间没有返回 `ALREADY_EXISTS`，也没有第二行 | 把等待当成缺行 |
| D-03 | 这次加锁读本身超时 | 保持读取未完成，不插入，不进入第 6.3 节 | 提交结果不确定 |
| D-04 | 读取失败 | 同上 | `ALREADY_EXISTS` 或提交成功 |
| D-05 | 读取不完整 | 同上。不把没看见行当成没有行 | 确认缺行 |
| D-06 | 内容相同 | `ALREADY_EXISTS`，不 `UPDATE` | 任务终态成功 |
| D-07 | 内容不同 | 完整性异常，原行保持 | 覆盖 |
| D-08 | 加锁读完成且确认没有该行 | 记录为「唯一冲突后确认缺行」。不插入，不进入第 6.3 节 | 自行决定重新插入。该后续动作仍待决策 |

普通一致性读看见没有行，不能作为 D-08 的证据。D-08 若只能证明「这次读没看到」，而不能证明加锁读已经完成，则是 INCONCLUSIVE。

## 11. E 组：COMMIT 已发送

本组只对应第 6.3 节。`COMMIT` 尚未发送的断连放在 F 组与第 6.5 节，不放进本组。

客户端必须留下 `COMMIT` 已经发出的证据。没有这份证据的断连不得记成 E 组。恢复使用另一条连接上的新事务，按完整身份加锁读。B 类再插入前还要重新锁定任务行并重做五项校验。A 类恢复读取不锁任务行。

| 编号 | 场景 | 会话 | PASS |
| --- | --- | --- | --- |
| E-01 | `COMMIT` 已发送，服务端已提交，客户端没收到成功响应 | 原连接 1，恢复连接 1 | 加锁读看见该行。内容相同为 `ALREADY_EXISTS`，不更新。不把客户端超时写成未提交 |
| E-02 | `COMMIT` 已发送，服务端尚未完成时连接断开 | 同上。需要服务端能显示事务仍在或随后结束 | 在服务端状态确认前不插入。状态不能确认则为 INCONCLUSIVE |
| E-03 | `COMMIT` 已发送，但服务端随后确认回滚 | 同上 | 确认没有该行之后才允许按第 6.3 节重新插入。B 类还要围栏通过。不能记成第 6.4 节 |
| E-04 | 客户端不能判断 `COMMIT` 是否到达服务端 | 同上 | 保持提交结果不确定，直到加锁读完成。读失败则仍不确定，不插入 |
| E-05 | 恢复加锁读看见行 | 恢复连接 1 | 比较内容。相同复用，不同为完整性异常 |
| E-06 | 恢复加锁读确认没有行 | 恢复连接 1 | 只有在 E 组前提下才可以再插入。第 6.4、6.5 节的缺行不能引用本项 PASS |
| E-07 | 恢复加锁读失败或不完整 | 恢复连接 1 | 继续不确定，不插入，不用内存代次 |

若实验不能证明 `COMMIT` 已经发出，整项为 INCONCLUSIVE，不能降级记成第 6.5 节的 PASS。

## 12. F 组：死锁、超时与 COMMIT 前断连

本组覆盖第 6.5 节五种断连，以及超时错误完整返回且连接仍可用的情形。五种已知事实分开编号。

制造断连的方法必须让客户端记录「有没有收到完整语句结果」和「有没有发送 `COMMIT`」。服务端用连接号、事务状态和锁等待视图对照。对不上则 INCONCLUSIVE。

| 编号 | 对应子场景 | 客户端已知事实 | PASS | FAIL |
| --- | --- | --- | --- | --- |
| F-01 | 死锁错误完整返回，且整笔回滚已确认。这不是第 6.5 节 | 完整死锁错误，随后整笔回滚被确认 | A 类从协议起点重做。B 类重新锁任务行并重做五项校验。可以新插入 | 未确认整笔回滚就重做 |
| F-02 | 第 6.5 节：死锁错误未完整返回后断连，`COMMIT` 未发送 | 不能把 `INSERT` 说成一定成功或一定失败，不能认定整笔已回滚 | 不按 F-01 重做，不插入。加锁读看见行才比较内容。确认缺行不插入 | 记成死锁已确认，或进入第 6.3 节 |
| F-03 | 超时错误完整返回，连接仍可用 | 知道发生了超时。默认只知道当前语句回滚。`innodb_rollback_on_timeout` 的实际值必须记下来 | 未确认整笔回滚时不重做、不插入。参数未选时，本项只能描述这次观测，不能写成项目已选参数 | 把语句回滚写成整笔回滚，或未确认就插入 |
| F-04 | 第 6.5 节：超时错误完整返回后断连 | 知道超时和默认的语句回滚，不知道整笔是否回滚 | 不进入第 6.3 节。普通查询缺行不插入。加锁读等待不是缺行 | 与 F-05 记成同一条 |
| F-05 | 第 6.5 节：超时错误未完整返回后断连 | 只有「没有完整错误响应」。不能确认发生了超时，不能确认语句已回滚，不能确认整笔已回滚 | 不重做，不插入，不进入第 6.3 节，不并入 F-02，也不并入 `INSERT` 执行期间断连 | 结论写成「已经发生锁等待超时」或「当前语句已经回滚」 |

另外两项第 6.5 节场景单独编号，避免算进超时：

| 编号 | 子场景 | PASS |
| --- | --- | --- |
| F-06 | `INSERT` 执行期间断连，没有完整语句结果 | 不推断语句已执行。不插入。不叫 F-05 |
| F-07 | `INSERT` 已明确成功，发送 `COMMIT` 前断连 | 语句成功不等于事务已提交。不进入第 6.3 节。看见已提交行才比较内容。确认缺行不插入 |

F-06 与 F-07 使第 6.5 节五种都有编号。F 组合计 7 个编号，其中 F-01、F-03 不是断连子场景。

原事务可能仍持锁。恢复加锁读若在等待，记录等待，不记缺行。等待再次超时仍不插入。

## 13. 记录模板

每次实验一行主记录，会话和锁证据可以附多行。不能只填最终行数。

| 字段 | 要求 |
| --- | --- |
| `experimentId` | 上表编号。F-04 与 F-05 不得共用 |
| `requirementId` | 第 15 节的关闭条件编号 |
| `scenario` | 场景名，沿用第 6.3、6.4 或 6.5 节的状态名 |
| `mysqlVersion` | `SELECT VERSION()` 原文 |
| `isolationLevel` | 会话实际值 |
| `innodbRollbackOnTimeout` | 实际值。未选定项目标准时注明「仅本次环境」 |
| `sessionId` | 实验会话名 |
| `connectionId` | 服务端连接号 |
| `transactionId` | 能取到的事务标识。取不到则写明缺失，该项容易成为 INCONCLUSIVE |
| `clientTimeline` | 每条语句的发送、完整响应或断开。必须能看出 `COMMIT` 是否已经发送 |
| `serverEvidence` | 事务状态、提交或回滚的服务端痕迹 |
| `sqlResult` | 完整成功、完整错误，或没有完整结果 |
| `errorCode` | 没有完整结果时留空，不填推测码 |
| `errorMessage` | 原文。不完整则保存已收到片段并标明不完整 |
| `lockEvidence` | 谁在等待、谁持有锁、等待是否结束 |
| `finalRows` | 该身份的权威行数量 |
| `finalContent` | 胜出行的不可变字段。用于判断有没有被更新 |
| `classification` | `PASS`、`FAIL` 或 `INCONCLUSIVE` |
| `conclusion` | 对应哪条设计假设，不扩写成 IR-02 已关闭 |
| `limitations` | 未冻结参数、无法制造的断连、无法关联的时间线 |

必须能分开：客户端有没有收到完整响应，服务端有没有执行语句，事务有没有提交或回滚，锁是否还在，加锁读有没有完成，权威行是否存在。

## 14. 判定

PASS：结果与该项「PASS」栏一致，客户端时间线和服务端证据能对上，并且没有另一种同样说得通的解释。

FAIL：出现第二行权威身份、原行被更新、A 类被要求先有 `RUNNING` 任务、B 类绕过围栏、把三种恢复状态记成同一种、或把 F-05 写成已经发生超时或语句已回滚。

INCONCLUSIVE：缺关键证据，时间线对不上，依赖参数未冻结，服务端提交或回滚无法确认，或者不能排除连接清理之外的其他解释。INCONCLUSIVE 不是 PASS，也不能用来勾掉第 13 节。

## 16. 风险

- 在参数冻结前跑完全部编号，会得到一批不能引用的非正式结果。
- 断连实验若分不清 `COMMIT` 是否发出，会把第 6.3 节和第 6.5 节记混。
- 锁等待的不完整错误若被填上推测的错误码，会把 F-05 做成假的 F-04。
- 确认缺行后如果实验脚本自行插入，就超出 06-04-19 的待决策边界。脚本不得包含这一步。
- 临时表被抄进正式迁移，会把未批准的列宽变成物理模型。

## 18. 结论

42 项场景和 A-01N 都是计划。第 6.3、6.4、6.5 节仍然分开。五种断连分别是 F-02、F-04、F-05、F-06、F-07。F-01 与 F-03 记录完整错误且已确认回滚或连接仍可用的情况。两种超时错误没有合并。

IR-02 仍是待决策、P0。下一步是先决定字符集、排序规则、列宽、隔离级别、`innodb_rollback_on_timeout` 和 IR-14 的空版本表示，再在隔离的 MySQL 8.0.46 上按编号执行。执行记录出现之前，关闭条件一项都不算满足。
