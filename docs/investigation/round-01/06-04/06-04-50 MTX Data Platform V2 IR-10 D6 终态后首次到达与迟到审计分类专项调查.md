## 2. 已确认业务语义

[06-04-40](06-04-40%20MTX%20Data%20Platform%20V2%20IR-10%20业务语义决策确认记录.md) 确认：责任事实成功 `COMMIT` 才发生；终态是另一笔事务；审计可以尚未写入；恢复不得按当前终态重判历史分类。

[Pipeline 第 11.1 节](../06-03/06-03-03-06%20MTX%20Data%20Platform%20V2%20金额处理%20Pipeline%20集成与端到端处理设计.md) 的已有设计是：终态已提交，且这个 `blockIdentity` 还没有任何有效阻断、拒绝审计或迟到审计时，首次返回 `LATE_BLOCK_RECORDED`。已有迟到审计且四个字段相同，返回 `LATE_ALREADY_RECORDED`。已有拒绝审计则仍是 `BLOCK_IDENTITY_REJECTED`，不因终态改成迟到。同一身份四个字段不同是 `BLOCK_CONTENT_CONFLICT`，不覆盖。`ALREADY_BLOCKED` 只用于同一条有效阻断，不用于迟到或拒绝。这些返回码已经存在，本轮不新增。

该节的「还没有任何记录」没有把责任事实算进去。这是 06-04-48 的文档空档，不是实验结论。

[06-04-42](06-04-42%20MTX%20Data%20Platform%20V2%20IR-10%20架构批准阻塞项拆解与技术决策顺序审查.md) 第 4.6 节要求把「责任事实已提交、审计未补写」和「从未形成责任事实的终态后首次到达」分开。前者只补拒绝审计。后者才是迟到。读完仍不能判断时，不写迟到，也不写拒绝。这是待决处理，Pipeline 正文尚未按它改写。

[ADR-0002](../../../decisions/0002-v2-module-architecture.md) 固定十个模块。[ADR-0003](../../../decisions/0003-unmapped-conflict-observation.md) 不定义拒绝或迟到审计。[ADR-0005](../../../decisions/0005-mysql-doris-storage-baseline.md) 的 MySQL 8.0.46 尚未接入这组读取。

## 3. D6 状态分类

任务已经是五个终态值之一。下表的「允许首次迟到」只在权威地确认没有已提交责任事实时才可能成立。06-04-46 和 06-04-49 都还没有这种读法，所以本表里没有任何一行在当前证据下可以执行 `LATE_BLOCK_RECORDED`。

| 状态 | 首次迟到 | 拒绝审计补写 | `LATE_BLOCK_RECORDED` | 必须停止 | 幂等返回 | 内容冲突 |
| --- | --- | --- | --- | --- | --- | --- |
| A. 终态后该身份第一次到达，责任事实、拒绝审计、迟到审计都不存在 | 只有权威确认责任事实不存在时才是 D6。该确认目前不存在 | 否。没有责任事实，不进入 D5 | 前提满足时，Pipeline 的首次写入是这一码。前提未满足时不允许 | 前提未满足时停止 | 尚无迟到行，没有幂等对象 | 尚无行可比 |
| B. 责任事实已成功 `COMMIT`，拒绝审计尚未补写 | 不允许。这不是 A | 交给 D5 发现。D5 的插入仍受缺行和 D7 限制 | 不允许 | 迟到写入必须停止 | 还没有拒绝审计行，不能把 `REJECT_AUDIT_ALREADY_RECORDED` 当成已经补完 | 尚无审计行。不得改写成迟到来回避冲突 |
| C. 责任事实已提交，拒绝审计已提交且四个字段一致 | 不允许再写迟到 | 不再插入。能否标成补写完成，仍看 06-04-47 的 D3 交叉前提 | 不允许 | 交叉无法解释时停止，不标完成 | Pipeline 对已有拒绝审计返回 `BLOCK_IDENTITY_REJECTED`，持久化结果 `REJECT_AUDIT_ALREADY_RECORDED`。不改成 `LATE_ALREADY_RECORDED` | 四个字段一致，不是冲突 |
| D. 责任事实已提交，拒绝审计内容不一致 | 不允许 | 停止补写。不覆盖，不改成迟到，不删除责任事实 | 不允许 | 是 | 否 | `BLOCK_CONTENT_CONFLICT`。不新造错误码 |
| E. 责任事实 `COMMIT` 不确定 | 不允许 | 不进入 D5 | 不允许 | 是。留在 D4 | 否 | 还没有权威比较对象 |
| F. 查询没有返回责任事实，但读视图、事务或完整性不能证明不存在 | 不允许。这不是 A | 不把「可能还在」送进 D5，也不当成没有事实 | 不允许 | 是 | 否 | 否 |
| G. 同一身份已经有迟到审计 | 不是首次 | 若同时还有已提交责任事实，交叉按 06-04-47 停止，不把已写上的迟到当成补写成功 | 不允许再插一条 | 内容冲突或交叉无法解释时停止 | 四个字段相同：`LATE_ALREADY_RECORDED`。这只表示迟到行已在，不证明当初不该写迟到 | 四个字段不同：`BLOCK_CONTENT_CONFLICT` |
| H. 同一身份已有有效阻断，或已有拒绝审计 | 不允许把有效阻断或拒绝审计再写成迟到 | 已有拒绝审计且内容一致时，见状态 C。只有有效阻断、没有责任事实时，不补造责任事实 | 不允许 | 内容不同时停止 | 有效阻断且内容相同：`ALREADY_BLOCKED`，终态前后都适用。已有拒绝审计：`BLOCK_IDENTITY_REJECTED` | 内容不同：`BLOCK_CONTENT_CONFLICT` |

不能进入迟到审计的是 B、C、D、E、F、G、H，以及前提尚未证明的 A。当前能够执行首次迟到分类的行数是零。

## 4. 首次到达与重复到达时序

两条路径都是设计时序，不是实验记录。责任事实和拒绝审计仍是两次 `COMMIT`。

路径一，真正的终态后首次到达：

| 步骤 | 事务 | 业务分类 |
| --- | --- | --- |
| 终态事务成功 `COMMIT` | 终态事务。设计文本先锁任务行 | 任务进入终态 |
| 该 `blockIdentity` 第一次到达 | 迟到路径。06-04-11 不锁任务行 | 还没有分类 |
| 权威读取确认没有已提交责任事实，且没有阻断或审计行 | 另一次读取，快照必须能够看见此前的提交 | 才是 D6 |
| 首次写入迟到审计 | 审计自己的事务 | `LATE_BLOCK_RECORDED`。这一步今天被第 5 节挡住 |

路径二，责任事实先提交：

| 步骤 | 事务 | 业务分类 |
| --- | --- | --- |
| 责任事实成功 `COMMIT` | 规则 C 的事务，持锁时仍非终态 | 拒绝已经发生。定义 B |
| 终态随后成功 `COMMIT` | 另一事务，同一条任务行 | 终态不改写已发生的拒绝 |
| 拒绝审计尚未补写 | 审计事务还没有成功 `COMMIT` | 状态 B，不是状态 A |
| 同一身份再次到达 | 可以是原 Worker 重试，或另一个 Worker，或终态后的第一次调用 | 入口仍是 `recordTaskBlock`。调用者不同不构成另一种业务 |
| 读取身份和已有事实 | 必须能看见已提交的责任事实。06-04-49：旧一致性读快照可能看不见 | 看见恰好一行则留在 D5，不得写迟到。看不见则是状态 F，停止，不得当成路径一 |

路径一没有已提交的拒绝事实。路径二已经有。终态相同、身份相同、审计都还没有，也不能互相替代。Pipeline 若只查阻断和审计、不查责任事实，路径二会得到和路径一相同的 `LATE_BLOCK_RECORDED`。那是误判，不是两种路径的合并。

## 5. 责任事实不存在的证明边界

06-04-49 的结论是：新鲜读视图只能排除旧快照把已提交行藏起来，不能把缺行升级成权威不存在。下表不新增 D4 状态，也不宣布某一读法已经够用。

| 读法 | 缺行表示什么 | 能否支持 D6 的「责任事实不存在」 |
| --- | --- | --- |
| 当前事务里的普通一致性读缺行 | 可能是旧快照不可见、未提交、确实没有、身份不对 | 不能 |
| 新事务的一致性读缺行 | 排除了调用方旧快照。仍可能是副本落后、读得不完整，或 06-04-46 尚未接受的缺行 | 不能 |
| `READ COMMITTED` 下的缺行 | 每次普通读换快照。级别未选，也未实验。换快照不等于权威不存在 | 不能 |
| `SELECT ... FOR SHARE` 缺行 | 锁定读按手册看最新已提交行，并加锁。等待不是缺行。06-04-46 不接受锁定读缺行为确认不存在 | 不能 |
| `SELECT ... FOR UPDATE` 缺行 | 同上一行，锁更强。间隙范围未在 8.0.46 上验证 | 不能 |
| 结果不完整 | 不确定 | 不能 |
| 数据库读取失败 | 没有完整结果 | 不能。不用失败前的空结果 |
| 副本读取落后 | 源库上可能已经有行 | 不能 |
| 同一身份多行 | 不是不存在 | 不能。停止，不挑选，也不写迟到 |

D6 依赖的前提「责任事实不存在」目前无法证明。这是首次迟到分类的阻塞条件。在该条件被另一次已接受的读取定义打开之前，终态后的到达不能执行 `LATE_BLOCK_RECORDED`。

## 6. D5 与 D6 交叉状态

D5 从已经提交的责任事实出发。D6 只处理确认没有这种事实的终态后首次到达。D5 有发现候选，并不使 D6 变安全：发现责任事实和证明没有责任事实是两件相反的事。

| 同时发生的事 | 结果 |
| --- | --- |
| D5 看见状态 B，D6 按 Pipeline 字面也看见「没有审计」 | 可能一条路径补拒绝审计，另一条路径写迟到审计。类型不同，身份相同 |
| 两边四个字段一致 | 仍是两条记录时，06-04-46 要求停止，不挑选。内容一致不表示 D7 已经满足，也不表示迟到行可以充当拒绝补写 |
| 两边四个字段不一致 | `BLOCK_CONTENT_CONFLICT`。不覆盖，不把其中一条改成另一种 |
| 统一身份判定入口 | 能让两条路径先回答同一问题：有没有已提交责任事实。06-04-49：它不刷新调用方的旧快照，也不把缺行变成权威不存在 |

统一入口因此解决不了数据库读取的新鲜度，也解决不了 D6 的阻塞条件。没有这个入口时，旁路仍会按第 11.1 节把状态 B 写成迟到。

## 7. D3 锁协调影响

已有设计：责任事实事务和终态事务先锁同一条任务行。迟到审计不锁任务行，也不写 `status`。D3 未批准，Java 中没有 `FOR UPDATE`。

D3 候选挡住的是「终态先提交，然后再插入终态前责任事实」。它挡不住「责任事实和终态都已提交，迟到路径不读责任事实」。不锁任务行，分类交叉不会自动消失。要避免交叉，靠的是看见已提交责任事实，而不是再锁已经终态的任务行。

若考虑让 D6 也锁任务行：

- 会改变 06-04-11 和 06-04-40 所依据的「迟到审计不锁任务行」。业务语义没有批准这个改变。
- 锁顺序若仍要遵守 D3，必须先任务行，再碰责任事实或审计索引。先锁索引再锁任务行，与终态事务的先任务行形成逆序。死锁未实验。
- 只锁任务行、不读责任事实，窗口仍在。
- 不改变定义 B 和规则 C，但本轮不把「锁一下更方便」写成已经批准。

## 8. D7 并发幂等影响

| 情形 | 普通查询或内存能否解决 | 依赖 |
| --- | --- | --- |
| 读取时已经看见审计行 | 能按已有种类做幂等或冲突。看不见不等于没有 | 读取本身要完整。不是 D7 |
| 两个 Worker 同时认为审计不存在 | 不能。两边都可以插入 | D7 的唯一约束。未实现。IR-02 不关闭 |
| 一个写拒绝审计，一个写迟到审计 | 不能。种类不同，查询「没有迟到行」和查询「没有拒绝行」可以同时为真 | 同身份的权威行仍要约束。本轮不设计索引如何覆盖两种审计 |
| 两个 Worker 同时写相同迟到审计 | 不能靠谁先在内存里登记 | D7。冲突后必须按 06-04-46 定位具体约束，再读胜出行。约束对不上就停止 |
| 同身份多行 | 查询发现之后只能停止 | 修复是 D7 与 IR-02，本轮不修 |
| 内容冲突 | 读到胜出行后按四个字段比较。不一致就 `BLOCK_CONTENT_CONFLICT` | 比较不是唯一约束。没有约束时可能根本没有「唯一冲突」这个错误 |

读到恰好一行，也不表示 D7 已经实现。

## 9. 候选策略比较

字母只用于本节，与 06-04-48、06-04-49 的字母不是同一套。只比较，不选定，不批准。

| 维度 | A. 按现行第 11.1 节直接分类 | B. 迟到分类前读取责任事实 | C. 所有入口先做统一身份判定 | D. 在「不存在」被证明前一律不写迟到 |
| --- | --- | --- | --- | --- |
| 能否区分真正首次到达和责任事实已提交 | 不能。不读责任事实 | 读到恰好一行时能把状态 B 留在 D5。缺行时不能把状态 F 收成状态 A | 与它所做的读取相同。旁路不调用则不能 | 不区分成功。两种都不写 |
| 能否避免把 D5 的责任事实记成迟到 | 不能 | 只有新鲜且完整的命中才可以避免。旧快照漏读时不能 | 入口齐了才可以。服务本身不保证新鲜读 | 可以避免误写，因为状态 B 也不写迟到 |
| 是否依赖 D4 | 不读，就会把不确定当成没有记录 | 依赖。不确定则停止 | 同 B | 依赖。没有 D4 的确认不存在，就不写 |
| 是否依赖 06-04-49 的新鲜读取 | 否，所以会漏 | 是 | 是。统一服务不是新鲜读的替代 | 是。否则连「先别写」的判断也会用旧快照 |
| 是否需要 D3 锁 | 现行设计不锁 | 看见已提交行不需要任务行锁 | 同 B | 不需要为了停止而去加锁 |
| 是否依赖 D7 | 并发首次写入依赖，但 A 没有这层约束 | 依赖。读到一行也不代替它 | 同 B | 未写入时少一次并发插入。已有行的幂等仍依赖读取，并发仍依赖 D7 |
| 是否改变现有返回码 | 状态 B 会得到 `LATE_BLOCK_RECORDED` | 状态 B 不应再得到该码。没有新码可返回，只能停止在现有码之外 | 同 B | 状态 A 在前提打开前也不返回 `LATE_BLOCK_RECORDED`。不新增码 |
| 是否引入新的持久化事实 | 否 | 否 | 否。不因此新增模块或待办表 | 否 |
| 当前证据是否足够执行首次迟到 | 不足。会误判 | 不足。缺行仍不是不存在 | 不足。同上 | 足够支持「现在不写」。不足支持「以后按 D6 写入」 |

| 新事务、`READ COMMITTED`、`FOR SHARE`、`FOR UPDATE` 的缺行 | 是否仍不能当作权威不存在 | 未执行 |
| 副本落后时的缺行 | 源库有行时迟到路径是否仍写入 | 未执行 |
| 同一身份多行、读取失败、结果不完整 | 是否停止而不是写迟到 | 未执行 |
| 一个 Worker 写拒绝审计，另一个同时写迟到审计 | 是否留下两种审计 | 未执行 |
| 两个 Worker 同时首次写迟到 | 是否两行都提交。没有唯一索引时这是预期风险，不是通过 | 未执行 |
| 已有拒绝审计且四个字段一致后再到达 | 是否停在 `BLOCK_IDENTITY_REJECTED`，而不新增迟到 | 未执行 |
| E2E-088、E2E-095 | 06-04-42 已标未执行的迟到首次写入 | 未执行 |
| E2E-135 至 E2E-139 | 跨进程审计恢复 | 未执行 |

## 12. 调查结论与未决事项

已确认的业务语义仍是定义 B 与规则 C。已有设计把终态后、阻断和审计都还没有的首次到达写成 `LATE_BLOCK_RECORDED`，并且迟到路径不锁任务行。技术推论是：这条设计看不见责任事实，所以状态 B 会被当成状态 A。06-04-49 进一步说明，就算补上读取，普通缺行和新事务缺行也都不是「责任事实不存在」。

因此 D6 的首次迟到分类当前没有可执行的前置条件。不能进入迟到审计的状态是 B、C、D、E、F、G、H，以及尚未被权威读取证明的 A。D5 的恢复不能代替这个证明。统一入口不能代替新鲜读，也不能代替 D7。

未决：权威不存在由哪一种尚未被 06-04-46 接受的读法承担，停止时返回哪个现有码，以及拒绝审计和迟到审计的并发唯一性如何落在 IR-02。策略 A 至 D 都未选定。定义 B、规则 C 和 D3 的锁顺序不因这些未决而改变。
