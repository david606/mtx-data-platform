## 4. 正常原始报文存储能力

正常原文是来源契约已经识别、并且准备进入 Task 创建的那一份报文字节。它不是异常隔离记录。

候选生命周期，本轮推导：

1. 接收外部消息。读到消息只说明投递到达。
2. 校验来源与契约。失败则不进入本节，转入第 8 节的候选隔离，并且该隔离现在不可执行。
3. 可靠保存原始字节。
4. 另行确认以后还能读到。
5. 只有第 4 步成立，才有权威 `rawPayloadRef`。
6. 用来源契约已声明的稳定事件身份做 Task Create-or-Get。见 06-04-26 与 06-04-19 第 6.1 节。
7. Worker 按任务上已经绑定的权威引用读取字节。Pipeline 第 4.2 节写明，校验引用不等于读取字节。
8. Pipeline 在已固定的快照和契约版本上处理。ADR-0004：确定性失败不换快照。
9. 保留、归档和删除见第 9 节。现在没有批准的期限。

保存成功和可再读确认是两个状态。写入调用返回成功，只说明保存动作声称完成。可再读确认需要另一次读取返回与当时保存的字节一致。用什么比较，长度、校验和或原文哈希，都还没有批准的算法。哈希若被采用，只做内容校验，不充当 SourceEventIdentity。06-04-10 第 8 节已有同样限制。

本轮不界定压缩、加密或信封格式。进入解析的字节必须与契约所描述的原文一致。编码、是否允许压缩后再存、静态加密，都待决策。大报文上限没有证据，不写死长度。

原文暂时不可读时，不允许把任务推进到依赖这次读取的 Pipeline 步骤。Pipeline 第 8 节已写：没有观测时内容读不到是 `PAYLOAD_REF_INVALID`，不产生观测。已有观测的恢复不读原文。永久不可读时，不换快照，不伪造字节，不把任务写成已经可重放。如何进入人工可恢复状态，待决策。

当前四个来源没有稳定事件身份，正常自动接入因此不能走到第 6 步。即便身份以后出现，存储产品未选定之前，第 3 步也不存在。这是 IR-09 条件 A 的阻塞项。

## 5. rawPayloadRef 语义与身份边界

Pipeline 第 4.1 节：`rawPayloadRef` 是权威原文引用标识，是观测身份的一段。校验标识不等于读取内容。06-04-25：格式未定义，不把它写成对象键、文件路径或内容摘要。报文字节没有技术主键。

| 概念 | 是什么 | 不是什么 |
| --- | --- | --- |
| 原始报文字节 | 契约要解析的内容 | 不是事件身份 |
| 内容哈希 | 将来若批准，只校验字节 | 不是 SourceEventIdentity，也不是本轮的幂等键 |
| 物理地址 | 某个产品里的桶、路径或内部定位 | 未选定。不得直接当成观测身份 |
| `rawPayloadRef` | 任务上绑定的逻辑引用 | 算法和长度未冻结 |
| SourceEventIdentity | 来源契约声明的稳定事件身份 | 不是引用，不是 offset |
| DeliveryIdentity | 一次投递的位置 | 不是原文身份 |
| TaskIdentity | 内部 `taskId`，算法未设计 | 不是原文 |

观测身份包含 `rawPayloadRef`。引用一旦绑进已提交任务并被观测使用，再改这个字符串就会变成另一条观测身份。因此本轮推导：权威引用在第一次成功绑定后保持不变；存储迁移不得改写这个逻辑引用。物理定位若需要分开，必须放在引用后面的解析层。这一拆分尚未被 ADR 接受，也没有字段设计。

引用必须能被任一执行中的 Worker 解析到同一份已确认字节。跨实例可读是要求，不是已验证能力。版本号、访问控制和校验和是否放进引用，待决策。不在本轮冻结生成算法或列宽。

## 6. 重复投递与原文保存幂等性

Pipeline 第 4.2 节：是否回到原任务只看稳定事件身份。同一事件再次到达时，即使这次 `rawPayloadRef` 不同，也不新建任务，也不替换第一次接受时保存的权威引用。新引用不进入原任务的观测，也不用来读原文。

| 情况 | 存储层能否只靠字节判断 | 任务侧 |
| --- | --- | --- |
| 同一已声明事件再次投递 | 不能只靠字节。相同事件的非身份字段以后可能不同，见 06-04-26 场景 6 | 回到原任务。权威引用不变 |
| 同一事件、不同 offset 或不同分区 | offset 和分区不是幂等键 | 同上。各分区的下一条待消费位置按 06-04-28 单独判断 |
| 重复保存得到相同引用 | 只有存储契约按稳定事件身份返回同一逻辑引用时才成立。该契约未批准 | 可以绑定这一个引用 |
| 重复保存得到不同引用 | 允许发生，Pipeline 已经考虑了这种结果 | 已绑定的权威引用不替换。新对象未被该任务引用 |
| 保存成功，Task 创建失败 | 对象可以已经存在 | 没有可安全执行的任务。对象要能被以后的恢复找到，不能立刻当成垃圾删除 |
| Create-or-Get 返回已有任务，本次又保存了新原文 | 新对象不是权威引用 | 不覆盖。新对象是未引用对象 |
| 保存成功但确认响应丢失 | 不能假设对象不存在，也不能再分配一个引用并写成权威 | 保持保存结果不确定，不创建可执行任务 |
| 读取失败后重试 | 重试仍用已绑定引用 | 暂时失败不换引用，不换快照 |
| 字节相同但事件身份不同 | 禁止并成一份原文身份 | 两个任务。不得用哈希合并 |

原文存储层的幂等若要存在，依据只能是已经声明的稳定事件身份，不能是内容哈希、offset、`receivedAt` 或 `taskId`。当前来源没有这份身份，所以存储层幂等现在不能实现。未引用对象的回收见第 9 节。回收前必须证明任务、重放、观测、审计和隔离记录都不再使用该引用。证明方法未设计。

## 7. 原文存储与 MySQL 跨系统事务边界

原文存储和 MySQL 不是一个本地事务。保存成功不能推出任务已创建。任务已创建不能推出 Worker 已执行。Kafka 的下一条待消费位置也不能掩盖这两边的不确定。06-04-19 的实验没有执行。

| 状态 | 原文 | 任务 | 下一条待消费位置 | 恢复 |
| --- | --- | --- | --- | --- |
| 保存前失败 | 无权威对象 | 不创建可执行任务 | 不移过本条 | 保存能力恢复后从保存重做 |
| 保存成功，创建尚未开始 | 对象在，任务未绑定 | 不创建，直到可再读确认完成 | 不移过本条 | 确认可再读后再 Create-or-Get |
| 保存成功，确认响应丢失 | 结果不确定 | 不创建，不另造权威引用 | 不移过本条 | 先按同一逻辑操作核对对象是否可再读。核对不完则保持不确定 |
| `INSERT` 已执行，`COMMIT` 未发送即断连 | 不因 MySQL 断连删除已保存字节 | 06-04-19 第 6.5 节。确认缺行也不再插入 | 不移过本条 | 不加新的权威引用 |
| `COMMIT` 已发送，结果不确定 | 同上 | 第 6.3 节。不再插入。读不完保持不确定 | 不移过本条 | 不用普通缺行查询推断已回滚 |
| `COMMIT` 已确认 | 权威引用已绑定且此前可再读 | 原任务可再读 | 仅当该记录已在分区连续前缀内，才把位置移到它之后 | 重复投递不替换引用 |
| 创建成功后读取失败 | 引用仍是权威 | 不换快照。无观测时 `PAYLOAD_REF_INVALID` | 不因读取失败改写已提交的 MySQL | 暂时故障稍后用同一引用重读。永久不可读待决策 |
| Worker 执行中存储故障 | 同上 | 围栏内的未提交写入按 06-04-11 回滚 | 不提交会跳过未完成记录的位置 | 不换引用 |
| 保留策略要删除仍被任务需要的原文 | 不得删 | 任务保持 | 与删除无关 | 见第 9 节 |

普通 MySQL 缺行不是「原文一定不存在」或「事务一定已回滚」。保存确认不确定时，不得假设对象不存在，也不得用新引用覆盖权威引用。

## 8. 异常隔离记录能力

异常隔离记录用于不能进入正常 Task 创建的消息。06-04-10 第 9 节的行为契约是候选：原文和接入上下文要能再读；上下文至少包括来源名、契约编号、topic、partition、offset、接收时间和失败原因；这些不是已建表。记录不是 `taskId`，不生成 `replayRequestId`。没有已批准规则前不自动恢复成任务。

本轮不扩大成一张已设计的表，只列出必须回答、但现在没有批准答案的问题：

| 问题 | 现有证据 | 结论 |
| --- | --- | --- |
| 记录的是什么 | 06-04-10：消息和接入上下文 | 不是 Task |
| 保存完整字节还是只保存引用 | 写的是原始消息要能再读。没有说字节放在哪 | 待决策。不能用正常任务的权威 `rawPayloadRef` 冒充 |
| 失败原因、来源、首次接收、重试 | 第 9 节列出了候选字段 | 候选，不是已建列 |
| 谁处理 | 同节写恢复责任人尚未指定 | 待决策 |
| 能否重新解析或 Replay | 补齐身份后可以再决定建任务。普通重复投递不写 `replayRequestId` | 不自动 Replay |
| 如何避免重复隔离记录 | 无稳定身份时不能用来源事件去重 | 待决策。不能用字节哈希合并不同投递 |
| 如何确认可再读 | 与正常原文相同，确认动作未定义 | 未执行 |
| 保留期限 | 未指定 | 不给天数 |

来源无法识别、契约无法识别、身份缺失、身份无法验证、原文保存失败、引用无法确认、Create-or-Get 无法完成、格式不符，都停在正常路径之外。确定性失败和瞬时失败的分类，Pipeline 已用于契约解析；隔离记录是否沿用同一分类，待决策。

介质、保留和责任人都没有批准。异常隔离只是候选，不是可执行能力。不建 DLQ、隔离表、临时文件、Inbox、Outbox 或 Redis 锁。无身份时，06-04-28 要求该分区的下一条待消费位置不移过未完成记录。

## 9. 数据保留、归档与删除

台账要求按实体列出保留和删除条件，并禁止把某一句建议当成全库策略。06-03-02-03 的「不自动删除」只覆盖该稿里的配置、目录、冲突决定和审计，且稿未冻结。ADR-0003 要求已形成的观测保持可追溯，不覆盖历史观测。这些都不是原文产品的保留天数。

正常原文和异常隔离记录分开列条件。本轮不给天数。

| 问题 | 约束 |
| --- | --- |
| 起算点 | 不能只按接收时间删除。任务未执行、失败重试、显式重放、观测和审计仍可能要读 |
| 仍被引用 | Task、Attempt、Replay、观测、审计或隔离记录仍使用该引用时，不能无条件删除 |
| 窗口 | 要覆盖任务可能存在的时间和已批准的重试、重放窗口。这两个窗口都还没有数字 |
| 正在运行 | 删除不得拆掉正在执行或仍可能恢复的任务所需要的字节 |
| 归档 | 归档后 Worker 是否仍能用同一逻辑引用读到字节，待决策。不能把归档写成已经满足读取 |
| 删除失败 | 引用仍在，对象还在或状态不确定。不能记成已删除 |
| 未引用对象 | 只有证明没有任何有效引用之后才可回收。证明方法未设计 |
| 引用失效 | 对象没了而任务仍需要它，按永久不可读处理，不换快照，不伪造字节 |
| 备份与灾难恢复 | 没有已接受方案。不能假设备份能找回权威字节 |

法律或业务保留期限没有入库证据，不编造。

## 10. 安全与访问边界

四个来源的报文至少包含金额和对账字段，见 06-04-26 第 3 节。它们可能带有业务标识。本轮不推断具体个人敏感字段，也不设计 IAM。

架构要求，均为待决策：

- 传输和静态保存是否加密，以及密钥放在哪里，未选。
- Worker 只在执行已绑定任务时按权威引用读取所需字节。
- Admin 不因为依赖 messaging 就获得原文读取或消费链路。ADR-0002 与 06-04-11：Admin 不执行数据处理。
- 运维查看和导出需要单独的审批与审计。审批人未指定。
- 应用日志不写完整原文、口令或真实连接串。这与仓库入口的日志纪律一致。
- 读取、删除和归档要有审计记录。审计落在哪里仍是 IR-10，本轮不选。

## 11. 模块职责与架构边界

ADR-0002 不允许新增模块。Core 不依赖具体存储产品。Pipeline 不依赖 Connector、Writer 的实现。

| 层 | 本轮推导 |
| --- | --- |
| `platform-core` | 可以定义「保存、确认可再读、按逻辑引用读取」的端口。端口不出现桶、路径、SDK 类型 |
| 产品适配 | 必须放在现有模块并由 `app-worker` 装配。放在 messaging、connector 还是 writer，三处都不自然，本轮不选定 |
| `platform-pipeline` | 只使用任务上的逻辑引用和已经固定的上下文。不打开物理地址 |
| Kafka Consumer | 不直接调用存储产品。接入适配调用 Core 端口 |
| `app-worker` | 装配端口实现，领取后按权威引用读取 |
| `app-admin` | 不运行这条保存和消费链路 |
| `platform-writer` | 现有职责是目标库写入，包括将来的 Doris。Doris 不是原文权威，ADR-0005 写明它不承接任务状态 |

不把「新增 platform-persistence」当作默认方案。

## 12. 状态模型

下列名称是逻辑状态，不是数据库枚举，也不是已建字段。

### 12.1 一份原文对象

同一份对象在同一时刻只处在其中一个状态。

| 状态 | 可否进入可执行 Task | 迁移 |
| --- | --- | --- |
| 未保存 | 否 | 开始保存后进入保存中 |
| 保存中 | 否 | 得到明确失败则回到未保存。调用没有明确结果则进入保存结果不确定 |
| 保存结果不确定 | 否 | 核对到可再读证据后才能离开。核对不完则留在这里。不另造权威引用 |
| 已保存但尚未确认可再读 | 否 | 另一次读取一致后进入已确认可再读。读失败则仍不能绑定 |
| 已确认可再读 | 可以进入 Create-or-Get。绑定成功后引用不可替换 | 可变为暂时不可读 |
| 暂时不可读 | 不推进依赖这次读取的 Pipeline | 恢复读取后回到已确认可再读 |
| 永久不可读 | 否。不换快照，不伪造字节 | 不自动回到可再读。人工恢复待决策 |
| 已归档 | 只有归档仍能用同一逻辑引用读到字节时，才视为可再读。这一点待决策 | 恢复失败则不能当成可再读 |
| 已删除 | 否 | 不自动恢复。仍有引用时不允许进入此状态 |

### 12.2 任务与引用

- 创建可安全执行或可恢复的 Task 之前，必须有已确认可再读的原文，并且权威引用指向它。06-04-28 第 5 节。
- 绑定提交之后不替换权威 `rawPayloadRef`。Pipeline 第 4.2 节。
- 重复投递产生的新对象不进入原任务。
- 显式重放是另一个 `taskId`。Pipeline 第 4.2 节没有规定重放必须更换引用。原任务的引用不被重放改写。重放任务若要读原事件字节，使用仍可再读的原权威引用，或者在自己的任务上绑定一份新的已确认引用。两种都未冻结。不得把新引用写回原任务。
- 原文不可读时，不换 ADR-0004 的快照和契约版本。无观测则 `PAYLOAD_REF_INVALID`。已有观测的恢复不读原文。
- 已执行任务的观测身份仍含原引用。删除字节会破坏追溯。

### 12.3 异常隔离

06-04-10 没有状态机。下面只是待决策的候选名称，不构成实现：待记录、记录中、记录结果不确定、已确认持久化、待处理、处理中、已恢复、已关闭。没有介质和责任人之前，任何一条都不能执行。记录结果不确定时，不假设记录不存在，也不提交会跳过该消息的 Kafka 位置。

## 15. 已确认规则

来自已有文档，不是本轮新决定：

1. 历史观测不覆盖。配置、冲突决定和审计在未冻结稿中不自动删除。台账禁止把一句建议当成全库策略。
2. `rawPayloadRef` 不是稳定事件身份。权威引用以第一次绑定为准，重复投递不替换。Pipeline 第 4.2 节。
3. 内容读不到且尚无观测时，不产生观测，不换快照。
4. 原文存储与 MySQL、Kafka 都不是一个本地事务。
5. 无稳定身份不自动建任务。隔离记录不是任务。

本轮推导，待正式决策：

- 保存成功与可再读确认分成两个状态。未确认可再读，不创建可安全执行或可恢复的任务。
- 逻辑引用与物理定位分开。引用字符串一旦绑定就不变。
- 存储幂等键若存在，只能是已声明的稳定事件身份。
- 未引用对象在证明没有有效引用之前不删除。
- 异常隔离维持候选。不建 DLQ 或隔离表。

## 18. 结论

台账 IR-15 原始范围是保留和删除策略。原文只出现在「不要被当成可覆盖缓存」的风险里。异常隔离和存储产品是 06-04-10 之后的扩展，不是台账已经批准的能力。

正常原文要先保存、再确认可再读、再绑定权威 `rawPayloadRef`，然后才允许 Create-or-Get。`rawPayloadRef` 是逻辑引用，不是事件身份，不是物理地址，也不是内容哈希。重复投递不替换已绑定引用。原文存储、MySQL 和 Kafka 不能原子提交。异常隔离仍是候选。保留天数、归档是否仍可按原引用读取、未引用对象如何证明可回收，都待决策。

建议台账以后把三个问题分开关闭，本轮不拆编号，也不改变 IR-15 的待决策、P2。IR-09 的条件 A 和条件 B 继续分别被阻塞。
