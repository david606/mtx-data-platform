## 4. D6 最小成立条件及证据状态

下列各项都是「协议范围内没有已提交责任事实」这一句的必要条件。没有任何一项，或全部加在一起，等于首次迟到的执行许可。

| 项 | 最小条件 | 证据状态 |
| --- | --- | --- |
| 1 | 所有责任事实写入都先锁同一条任务行，持锁重读状态和有效阻断，并把锁保持到事务结束 | 规则 C 已确认这一笔事务。入口覆盖待代码核验。未实现 |
| 2 | 所有把 `status` 写成终态的入口都先锁同一条任务行 | 06-04-40、06-04-44。设计文本没有第二条不锁的终态路径。没有代码可证将来没有旁路。待代码核验 |
| 3 | 终态提交后不再打开。若重新打开，终态屏障失效，规则 C 可能再次插入终态前责任事实 | 06-04-11 条件更新。待数据库实验 |
| 4 | 锁内重读、分类和责任事实插入在同一事务提交 | 规则 C。已有业务确认。待架构批准其物理协议 |
| 5 | 责任事实的正式发生点仍只是该事务成功 `COMMIT` | 定义 B。已有业务确认。锁取得、插入成功、审计行都不是这个时点 |
| 6 | D6 的判定读取打在 MySQL 主库 | 06-04-49、06-04-56。仓库没有数据源，不能证明当前会打到主库。待代码核验 |
| 7 | 实际使用的一致性读视图建立在目标终态成功 `COMMIT` 之后 | 06-04-56 条件 5。验收的是读视图，不是语句开始时间。待数据库实验 |
| 8 | 可重复读：事务内第一次普通一致性读固定视图，之后的普通读可能沿用旧视图。读已提交：每条普通读语句自己的视图，两条 SQL 不是同一逻辑状态。`REQUIRED` 只加入已有事务，不保证旧视图或新视图。`REQUIRES_NEW` 只有真正新开事务才离开调用方视图，新事务仍可能在终态前提前读过。单条 SQL 能避免两条语句各看各的快照，但不能单凭执行时间证明可重复读视图晚于终态 `COMMIT` | 手册语义加 06-04-49、06-04-56。级别和传播未选。未实验 |
| 9 | 普通缺行、单独的新事务缺行，只说明这次视图没有返回行。锁定读缺行在 06-04-51 第 4.1 节只覆盖下一笔也拿任务行锁的守约写入，而且那个读者不是迟到审计。06-04-55 的协议内缺行还要求终态 `COMMIT` 已确认、读视图在其后、全部写入守约。三者都不是数据库全局不存在 | 已有调查。不能升成权威不存在 |
| 10 | D7 未关闭，会挡住首次迟到的写入，即使缺行证明以后成立。两个都认为「没有迟到行」的 Worker 仍可能各插一行。拒绝补写与迟到写入可以各插一行。唯一约束未实现时，分类正确不等于只留下一行 | 06-04-50 第 8 节、06-04-51。这不阻止把「缺行证明」本身写成另一件事，但阻止把 D6 标成可执行 |

另外三件不能漏：

- 终态后查不到责任事实，不是全局不存在。06-04-55、06-04-56。
- 06-04-56 的验收条件不是首次迟到的充分授权。策略 A 至 D 仍未选。
- 责任事实已提交、拒绝审计尚未补写、同身份再次到达，是状态 B，归 D5 的发现，不得写成迟到。06-04-48、06-04-50。有效阻断登记尚未提交时，拒绝或迟到前提也不成立。06-04-54。

最小前提清单到「协议内否定证据」为止。首次迟到仍差：已有阻断和审计记录的排除、D2 把恰好一条挡出 D6、D7 的插入约束、以及一次被接受的读取定义。今天这些都没有。

## 5. D7 最小成立条件及证据状态

| 关系 | 最小要求 | 任务行锁能否代替 | 证据状态 |
| --- | --- | --- | --- |
| 责任事实对责任事实 | 同一身份至多一条已提交事实 | 不能。锁只排队守约事务。旁路、漏掉重读、其他入口仍可再插 | D1、D7。物理约束没有 |
| 拒绝审计对拒绝审计 | 同一身份、同一内容一条。Pipeline 第 839 行 | 不能。拒绝审计不锁任务行 | 已有设计。索引未建 |
| 迟到审计对迟到审计 | 同一身份一条，且不得改成 `ALREADY_BLOCKED` | 不能。迟到审计不锁任务行 | 同上 |
| 责任事实与拒绝审计 | 允许先后两笔 `COMMIT` | 锁不判断这对关系。一个共享键会误伤 | 定义 B。必须保持 |
| 拒绝审计与迟到审计 | 不能互相替代，也不能各留一行后挑选 | 锁不在这两条路径上。分表唯一索引各管各的表 | 06-04-24 第 8.2 节、06-04-51、06-04-53。未解决 |
| 有效阻断与三类记录 | 同身份不再写成拒绝、迟到或另一条责任事实。名额按 `taskId`，留在任务行 | 锁只挡住也锁这行的登记、责任事实和终态。挡不住不锁行的审计 | 06-04-19：MySQL 8.0 没有带 `WHERE` 的部分唯一索引。06-04-54 |
| 胜出类型 | 先确认约束和类型。类型与调用路径不同就停止。内容不同不覆盖 | 锁不返回类型 | 06-04-51。不新增返回码 |
| 跨类型同时存在 | 停止。不挑选、不合并、不改种类 | 无 | 06-04-50。未批准处理方案 |

D7 因此分成三层，不能收成「做个唯一索引」：

| 层 | 能保障的 | 不能保障的 |
| --- | --- | --- |
| 事务协议 | 守约的责任事实事务和终态事务按锁排队；规则 C 在锁内不再插入终态前事实 | 不锁任务行的审计。不守约的入口。同类型双插 |
| 数据库约束 | 只有落在同一个已冻结的唯一键空间里，才有机会拒绝第二行 | 跨表。任务行上的有效阻断。责任事实与拒绝审计这种必须并存的一对。06-04-53 没有证明哪一种形状同时满足全部关系 |
| 完整性检查 | 读到多行、类型不明、内容不完整时停止 | 不能阻止已经提交的第二行。`COUNT` 不是唯一约束。06-04-19 第 4 节 |

协调载体若存在，只是未批准的协调信息。它的 `COMMIT` 不是定义 B 的发生点，也不能先于任务行去锁，以免和 D3 的调查边界相反。06-04-53、06-04-54、06-04-55。本轮不选 A 至 E。

绕过协议的入口不会因为主路径写了锁就消失。物理约束只有在每条插入都占用同一个键空间时才看得到旁路。这个键空间本身还没冻结。因此「防止旁路」今天既没有协议清单，也没有约束。

## 7. 架构批准证据门禁

E1 是业务规则已确认。E2 是设计逻辑已调查，并有独立复审或后续调查衔接。E3 是物理设计已明确。E4 是 MySQL 并发实验已通过。E5 是代码和自动化测试已验证。调查通过只可能落在 E2，不能写成 E3、E4 或 E5。

| 项 | E1 | E2 | E3 | E4 | E5 | 能否进入架构讨论 | 能否批准 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 定义 B | 有。06-04-40 | 有。后续调查没有改写发生点 | 无。实体未定 | 无 | 无 | 可以。只讨论语义 | 可以讨论批准语义。不能连同表和实现一起批准 |
| 规则 C | 有 | 有。06-04-44、06-04-55 衔接了锁顺序 | 无。第三类协调未批准 | 无 | 无。没有 `FOR UPDATE` | 可以。只讨论锁内分类和同一事务提交 | 物理协议未批准前，不能批准成已实现协调 |
| D3 任务行锁 | 语义来自规则 C | 有调查，无架构批准 | 无 | 无 | 无 | 可以作为规则 C 的附件说明 | 不能单独批准成已验证协议 |
| D4 | 不明两边都不认定，来自定义 B | 有。06-04-46 | 无 | 无 | 无 | 可以作为语义附件 | 具体读法不能批准 |
| D5 | 补写不重分类 | 有。插入仍不可执行 | 无 | 无 | 无 | 可以说明边界 | 不能批准补写执行 |
| D6 | 终态后、没有已提交责任事实时不把内存仲裁补成拒绝 | 调查明确今天不可执行 | 无 | 无 | 无 | 只能作为未决项列入，不能作为通过项 | 不具备独立批准条件 |
| D7 | 并存与互斥来自已确认语义和 Pipeline | 06-04-52 复审过，方案仍未选 | 无。A-09 未解决 | 无 | 无 | 只能作为未决项 | 不具备独立批准条件 |
| IR-02 物理唯一约束 | 台账要求有约束。业务身份已写在 Pipeline | 06-04-19、06-04-20 至 06-04-24 是候选和复审 | 无。列宽、字符集、DDL 都未定 | 42 项与 A-09 未执行 | 无 | 观测身份可以另案讨论 | 不能把候选写成已批准。也不能代替 D7 |
| D6/D7 故障恢复 | D4 的原则已确认 | 停止规则已调查 | 无 | 无 | 无 | 可以写明「不明则停止」 | 恢复步骤不能批准 |

可以进入架构 ADR 讨论的，只有定义 B 和规则 C 的语义，以及它们已经写明的排除项：不合并两笔 `COMMIT`，不按当前状态重判补写，不把任务行锁当成唯一约束。

可以在语义被批准时附带、但必须写成实现前置条件而不是已完成事实的：全部入口守约、终态不再打开、读视图时点、主库。这些前置条件未满足时，批准文本不能写成 D6 可执行。

在物理设计和实验完成前不能批准的：D6 首次迟到、D7 任何一种键或载体、IR-02 的 DDL、隔离级别和字符集。

必须等代码存在之后才能验证的：入口清单是否真的没有旁路，`FOR UPDATE` 是否只出现在约定的事务里，语句是否打到主库，自动化测试是否覆盖状态 B 与双插。仓库今天没有这些代码，E5 全部为无。

## 8. 未决问题与风险

P0：把 D6 或 D7 写进同一次架构批准，会把未实验的缺行和未解决的跨表唯一性说成已决定。协议内不存在一旦被写成全局不存在，旁路插入就会被漏掉。D7 若用一个键覆盖责任事实和拒绝审计，会破坏定义 B。

P1：IR-02 的 A-09、列宽和字符集仍是建议或未执行项。06-04-50 的策略和停止时的现有返回码未选。06-04-56 的读取方式未选。台账里的 IR-10 仍是待决策，本轮不改台账。

P2：IR-15 的保留未定。它不阻塞语义讨论，但物理删除会在以后破坏 D5 和 D6 的读取。不在本轮规定天数。

## 9. 下一阶段工作分解

推荐顺序只有一条主线。完成标准写在每步后面。不在这一步选择技术方案。

| 顺序 | 工作 | 完成标准 | 实验时机 |
| --- | --- | --- | --- |

| 3 | 为 `blockIdentity` 单独立项物理问题：列是否 `NOT NULL`、是否单一键空间、分表时互斥靠什么。这是 IR-02 第 8.2 节和 A-09，不是观测四段那一项的关闭 | 有一份待确认的物理问题清单。没有选定载体字母 | 正式实验仍要等字符集、列宽和用户授权。06-04-24 阶段 A 到阶段 C |

## 10. 调查结论

1. 定义 B 和规则 C 具备进入架构批准讨论的条件。证据停在 E1 和 E2。讨论范围只能是语义。它们不具备连同物理设计、实验和实现一起批准的条件。
2. D6 不具备独立批准条件。协议屏障是推论，读视图方式未选，验收条件不是充分授权，状态 B 仍必须离开迟到路径。
3. D7 不具备独立批准条件。没有任何已选方案被证明同时满足同类型唯一、合法并存和跨类型互斥。
4. IR-02 的直接阻塞是：`blockIdentity` 物理列未冻结，跨表唯一性未解决，A-09 未执行，字符集和隔离级别仍是建议。观测身份上的唯一约束即使以后关闭，也不提供责任事实实体，也不提供 D6 的读视图。
5. 语义分界、两笔 `COMMIT`、补写不重分类，可以用设计决策讨论。读视图是否晚于终态 `COMMIT`、唯一索引是否跨表生效、终态条件更新是否不能改回，必须在 MySQL 8.0.46 上实验。入口是否穷尽，必须等代码。
6. 现在不能形成一份关闭 IR-10 的 ADR 草案，也不必等整个 IR-02 关闭才讨论定义 B 和规则 C。D7 的物理批准则必须先有 `blockIdentity` 键空间问题的决定，不能用 IR-02 其余身份的关闭来代替。
7. 下一步唯一优先任务是第 9 节第 1 步：准备只覆盖定义 B 和规则 C、并写明排除项的架构讨论输入。不实现，不实验，不选 D7 方案。

本轮对已接受 ADR 没有修改要求。ADR-0002 仍禁止为持久化加模块。ADR-0003 和 ADR-0004 仍不规定责任事实。ADR-0005 仍只接受服务器版本。定义 B 和规则 C 的业务确认保持不变。
