# 06-04-45 MTX Data Platform V2 IR-10 责任事实不可变内容专项调查

本文只调查 D2：一条拒绝责任事实在成功 `COMMIT` 之后，哪些业务事实必须固定，以及以后怎样比较。它不是 ADR，也不是架构批准。不关闭 D4、D5、D7、IR-02、IR-15。不修改 Java、Maven、DDL、已接受 ADR、台账、06-04-40、06-04-43、06-04-44。没有执行数据库写入、MySQL 实验或 E2E。不指定物理表名、列名、索引名，也不新选内容哈希算法或编码。

## 1. 调查目标与范围

要分开四件事：逻辑身份、不可变业务内容、分类证据、诊断或物理属性。然后回答：

1. 责任事实要固定哪些业务事实，哪些不能因为审计表现有字段就被塞进来或被删掉。
2. 分类结论和分类证据怎样在提交时固定，而不是以后再读任务当前状态。
3. 五种持久化状态下，责任事实和拒绝审计各比什么。
4. 同身份的重复、内容冲突、`COMMIT` 不明分别停在哪一步。
5. D2 与 D1、D3、D4、D5、D7 各管哪一段。

## 2. 已确认业务语义和前置决策

[06-04-40](06-04-40%20MTX%20Data%20Platform%20V2%20IR-10%20业务语义决策确认记录.md) 已确认定义 B 和规则 C。责任事实事务实际成功 `COMMIT` 才发生。`COMMIT` 前故障不认定已经发生。响应丢失仍可能已经发生，进入不确定性处理。`COMMIT` 之后审计还没写，可以按已提交责任事实补写，不能按当前任务状态重判历史分类。

规则 C 要求该事务先锁任务行，持锁读状态和有效阻断，再插入并提交。终态事务锁同一行。锁成功和 `INSERT` 成功都不是发生。

[06-04-44](06-04-44%20MTX%20Data%20Platform%20V2%20IR-10%20Task%20行锁协调专项调查.md) 的锁候选是第三类协调。任务行锁只排队分类和终态，不代替身份、内容比较、唯一约束或 `COMMIT` 不明后的读取。D3 同样尚未批准。

## 4. 身份、不可变内容、分类证据和诊断属性的边界

| 层 | 回答的问题 | 候选归属 |
| --- | --- | --- |
| 逻辑身份 | 到哪一条责任事实上去找 | D1：被拒绝的 `blockIdentity`。存储它是为了查找。它不重复进入内容相等集合 |
| 不可变业务内容 | 这条已提交事实的业务载荷是否与另一次相同 | 被拒绝阻断的四个字段，加上下面的分类结论 |
| 分类证据 | 当时凭什么判成拒绝，而不是凭恢复时的任务行 | 锁内读到的非终态 `status`，以及当时有效阻断的身份和四个内容字段的副本 |
| 诊断或物理属性 | 谁在什么机器上何时看见 | `taskAttemptId`、Worker、`receivedAt`、发现时间、日志时间、异常文本、自增标识、插入时间、更新时间。不参与内容比较 |
| 事务执行状态 | 锁是否还拿着、`COMMIT` 是否已确认 | 不是这行的业务字段。不明属于 D4 |
| 任务当前状态 | 这行提交之后任务变成了什么 | 动态属性。不得写回这条历史事实，也不得充当它的内容 |

权威来源在写入当时一次取齐，并随责任事实事务一起提交：

- 四个内容字段来自已经持久化的执行上下文和稳定条件。Pipeline 第 11.1 节禁止改用本次尝试的本地值。
- 任务状态和有效阻断来自规则 C 的锁内读取。写入的是这次读到的副本。
- 分类结论由这次锁内读取算出，并和副本一起提交。提交之后不再按任务行重算。

尚未成功 `COMMIT` 的候选值只存在于这次事务的内存里。它不是权威内容，也不能拿去和一条还不存在的责任事实做冲突。

## 5. 责任事实内容候选字段分析

下表是候选，不是已批准列。物理类型、字符集和序列化不在本轮决定。Pipeline 已经写明的 `EMPTY` 与 `NONE` 只沿用于那四个字段的取值规则，不据此发明新的编码。

| 候选 | 业务含义 | 不可变 | 参与哪一种比较 | 能否从已提交责任事实恢复 | 来源与生命周期 |
| --- | --- | --- | --- | --- | --- |
| 被拒绝的 `blockIdentity` | 查找键 | 是。身份不变 | 只做查找，不进入内容相等 | 能。它就在这行上 | D1 候选。`taskId` 算法和稳定阻断码算法仍在 IR-03，未选 |
| `snapshotId` | 这次拒绝所依据的已固定快照 | 是 | 责任事实内容，以及与拒绝审计的四个字段 | 能 | 执行上下文。未固定时 Pipeline 允许 `EMPTY`。不得用尝试本地值填上 |
| `contractVersionId` | 该快照内已固定的内部契约版本 | 是 | 同上 | 能 | ADR-0004 规定它是契约版本的内部身份。责任事实只保存当时已经固定的值，不重新解析 |
| `contractBodySha256` | 该版本正文的已有哈希 | 是 | 同上 | 能 | 沿用已有字段名。本轮不新定义一种把整份责任事实再哈希的算法。Pipeline 写明摘要不是幂等条件 |
| `conditionCode` | 比阻断码更细的稳定条件 | 是 | 同上 | 能 | 无子条件为 `NONE`。阻断码本身属于身份，不重复放进内容 |
| 分类结论 | 锁内判定为终态前拒绝，不是迟到，也不是有效阻断 | 是 | 只比较责任事实彼此。审计行没有这个列时，不因此判冲突 | 能。必须写在行上，不能等恢复时从当前 `status` 推断 | 06-04-42 已把它列入待查快照。不新增第三种业务种类 |
| 锁内 `status` | 分类当时读到的非终态值 | 是。它是证据副本 | 只比较责任事实彼此 | 能。副本在行上 | 不是任务行以后的 `status`。终态事务后来提交，不改这格 |
| 当时有效阻断的身份 | 分类当时「已经有另一条有效阻断」的身份 | 是 | 只比较责任事实彼此 | 能，因为保存的是副本 | 只存指针不够。06-04-30 没有批准删除，但一旦该行以后不可读，历史无法核对。现行设计虽不允许覆盖有效阻断内容，补写仍被要求不必打开任务行 |
| 当时有效阻断的四个内容字段 | 那条有效阻断当时的稳定事实 | 是 | 只比较责任事实彼此 | 能 | 与被拒绝阻断的四个字段不是同一组。不得互相填入 |

明确不纳入不可变业务内容：

| 项 | 理由 |
| --- | --- |
| `taskAttemptId`、Worker 实例 | Pipeline 已定为审计元数据。不同尝试、不同 Worker 可以是同一次事实。没有业务依据把它们放进内容 |
| `receivedAt`、发现时间、日志时间、本地时钟 | 定义 B 的发生时点是责任事实 `COMMIT`。这些时间不是该时点，也不参与现有内容比较 |
| 异常文本 | Pipeline 已排除。文本变化会把同一次拒绝写成内容冲突 |
| 自增标识、插入时间、更新时间 | 物理属性。两次相同业务内容会得到不同物理值 |
| 任务当前 `status` | 动态。写进历史行会让终态提交改写已经发生的分类 |
| 原文正文、契约正文 | 现有比较用的是引用和已有哈希，不是正文本身。本轮不把正文收成新内容 |
| 事务是否已提交、锁是否仍持有 | 执行状态。成功 `COMMIT` 之后事实才存在；不明不是内容的一种取值 |

四个字段能够从已提交责任事实直接读出，因此 D5 补写拒绝审计时不必再打开任务行，也不必重读当前 `status`。分类结论、锁内 `status` 和有效阻断副本同样在行上，用来证明当时为何是拒绝。它们不是拒绝审计现有的四个比较字段。

## 6. 责任事实与拒绝审计内容比较

责任事实的内容集合大于拒绝审计的 `blockContent`。审计比较停留在 Pipeline 已经写明的四个字段。责任事实多出来的分类结论、锁内 `status` 和有效阻断副本，不因为审计行没有这些列就被删掉，也不因为审计行没有这些列就判成内容不一致。

[06-04-43](06-04-43%20MTX%20Data%20Platform%20V2%20IR-10%20责任事实逻辑身份专项调查.md) 的五种状态在内容上是：

| 状态 | 内容规则 |
| --- | --- |
| 责任事实已提交，审计不存在 | 权威内容是责任事实行。可以进入 D5，用被拒绝身份和四个字段补写审计。分类不再读取当前任务状态 |
| 两边都在，四个字段一致 | 这四个字段的审计补写已经完成。不因为审计缺少分类证据列而再插一行，也不把缺少的列写成冲突 |
| 两边都在，四个字段不一致 | `BLOCK_CONTENT_CONFLICT`。停止。不覆盖，不改成迟到，不把补写标成成功，不把冲突当成没有审计 |
| 责任事实不存在，审计已存在 | 没有责任事实内容可供比较。审计的四个字段不是责任事实快照。不得反向补造。这是 06-04-43 的兼容边界，不是内容冲突 |
| 两边都不存在 | 没有比较对象。是否允许本次形成责任事实，由定义 B 和规则 C 在锁内决定。两个尚未提交的不同候选内容，不是 `BLOCK_CONTENT_CONFLICT` |

`REJECT_AUDIT_ALREADY_RECORDED` 只说明审计行在。它不证明责任事实已提交，也不提供责任事实的分类证据。

## 7. 幂等、冲突与不确定场景推演

下列场景都未执行 E2E，也未在 MySQL 8.0.46 上试验。错误码沿用 `BLOCK_CONTENT_CONFLICT`。不新造错误码。

| 场景 | 判定 |
| --- | --- |
| 同身份、同内容，责任事实已成功 `COMMIT` | 幂等。复用已提交行，不插入，不覆盖。内容指第 5 节的责任事实集合。尝试和 Worker 不同不构成内容不同 |
| 同身份、内容不同，责任事实已成功 `COMMIT` | `BLOCK_CONTENT_CONFLICT`。保持先提交的快照。后到的内容不写入 |
| 同身份、内容不同，责任事实尚未成功 `COMMIT` | 没有冲突对象。不返回责任事实上的 `BLOCK_CONTENT_CONFLICT`。若拒绝审计已经存在，仍按上一节第四种状态处理，不补造责任事实。若两边都不存在，回到锁内分类 |
| 不同 `taskAttemptId`，身份和内容都相同 | 尝试不在内容里。已有成功 `COMMIT` 时与第一行相同。还没有时，不把「内容看起来一样」写成已经发生 |
| 不同 Worker，身份和内容都相同 | Worker 不在内容里。规则与上一行相同 |
| `COMMIT` 响应丢失后的独立读取 | 响应丢失不是失败。读到已提交行且内容一致：已形成，复用。读到已提交行且内容不同：冲突，停止。读取不完整或无法分类：保持不确定，不插入。确认没有这行的读法属于 D4，本轮不写 |
| 审计补写发现四个字段不一致 | `BLOCK_CONTENT_CONFLICT`，停止。不当成审计缺失，也不标成补写完成 |
| 已有审计与已提交责任事实的四个字段不一致 | 与上一行相同。比较的是这四个字段。分类证据列不参与这次审计比较 |

锁成功、`INSERT` 成功、以及 `COMMIT` 尚未发送，都还没有权威内容。语句执行期间断连是语句不确定，不是已经形成的另一种内容。这些边界与 [06-04-44](06-04-44%20MTX%20Data%20Platform%20V2%20IR-10%20Task%20行锁协调专项调查.md) 和 06-04-42 第 4.4 节一致。D4 仍未关闭。

## 8. D1、D3、D4、D5、D7 的依赖

| 决策 | 负责 | 不负责 |
| --- | --- | --- |
| D1 | 用被拒绝的 `blockIdentity` 决定查找哪一条 | 内容是否相同 |
| D2 | 同一身份下，已提交快照是否一致；审计只比其中四个字段 | 谁先看见终态 |
| D3 | 任务行锁把分类和终态排成先后，使锁内副本来自同一次持锁读取 | 副本里哪些字段相等 |
| D4 | `COMMIT` 不明之后如何独立读取。读到行时必须用 D2 的内容核验 | 本轮不设计读取步骤 |
| D5 | 已确认提交的责任事实如何补写审计。无审计才补写；四字段一致算完成；不一致则冲突并停止 | 不按当前 `status` 重分类 |
| D7 | 数据库唯一约束保证并发下同一身份的权威行。冲突后还要读胜出行并做 D2 比较 | 唯一约束不能代替内容比较，任务行锁也不能代替唯一约束 |

D1 和 D3 的调查结论是本轮输入。本文不把它们改成已批准。

## 9. P0、P1、P2

| 项 | 级别 | 说明 |
| --- | --- | --- |
| 身份、四个字段、分类结论、锁内状态副本、有效阻断副本分开 | P0 | 不分开就会把证据漏掉，或把诊断字段写成冲突 |
| 内容比较只针对已成功 `COMMIT` 的责任事实 | P0 | 与定义 B、06-04-43 一致 |
| 审计比较限于四个字段，责任事实可以多出分类证据 | P0 | 防止两边互相裁剪 |
| 诊断字段、物理时间、当前 `status` 不进入内容 | P0 | Pipeline 已排除前一组。后一组会改写历史 |
| 不新造错误码，不把冲突当缺失 | P0 | 沿用 `BLOCK_CONTENT_CONFLICT` |
| 列类型、字符集、是否另存摘要 | P1 | Pipeline 已写摘要不是幂等条件。摘要即使以后存在，也不代替逐项比较 |
| 有效阻断用副本而不是活指针 | P1 | 候选已写明理由。物理列和归档后的可读性仍受 IR-15，不关闭 IR-15 |
| 唯一约束与胜出读取 | P1 | D7 与 IR-02。本轮不指定索引，不关闭 IR-02 |
| `COMMIT` 不明的读取步骤 | P1 | D4。原则是用不可变内容核验，步骤未设计 |
| 孤立审计与责任事实的兼容 | P1 | 06-04-43 已留后续专项。本轮不补造 |
| 可选诊断列是否落库 | P2 | 即使落库也不进入比较 |
| 保留天数 | P2 | IR-15。未选天数 |

## 10. 候选设计与未决事项

候选原则，待架构负责人评审，未批准：

1. 责任事实的查找身份沿用 D1，不把身份三部分再放进内容相等集合。
2. 参与责任事实彼此比较的不可变内容是：被拒绝阻断的四个字段、分类结论、锁内非终态 `status` 的副本、当时有效阻断的身份及其四个字段的副本。
3. 与拒绝审计比较时，只用被拒绝身份加那四个字段。分类证据保留在责任事实行上，不要求审计行具备同名列，也不因审计缺少这些列而冲突。
4. 四个字段的取值来自已持久化执行上下文。分类证据来自同一次持锁读取。分类结论随这次提交固定。
5. `taskAttemptId`、Worker、`receivedAt`、发现时间、日志时间、异常文本、自增标识和插入或更新时间都不参与内容比较。
6. 没有已提交责任事实时，不形成责任事实层面的 `BLOCK_CONTENT_CONFLICT`。

仍未决，且本轮不选：

- 物理表、列、索引、字符集、序列化。
- 把整行再做成摘要的算法。幂等仍是逐项相等。
- D4 的独立读取步骤，D5 的补写执行者，D7 的索引。
- IR-02、IR-03、IR-15 的原有缺口。
- 孤立审计如何与未来责任事实并存。
- 架构是否接受本候选，以及是否接受 D1、D3。

## 11. 本轮结论及禁止事项

已有设计事实：Pipeline 把现有阻断和审计的内容比较限定为四个字段，并把尝试、Worker、时间和异常文本排除在比较之外。06-04-40 要求未来的责任事实行能独立表达任务身份、被拒绝身份与四字段、当时有效阻断和持锁时的非终态。06-04-43 要求内容冲突只对着已提交责任事实。06-04-30 要求已有审计不覆盖。ADR-0003 与 ADR-0004 不定义这行的列。

本轮候选是第 10 节的六条。它尚未批准，也没有实现。MySQL 8.0.46 实验和相关 E2E 均未执行。

本轮禁止：修改既有调查、ADR 和代码，执行 SQL 写操作，新建模块，引入 Inbox、Outbox、DLQ 或 Redis 锁，把候选写成已批准，把 D1 或 D3 写成已批准，用锁或 `INSERT` 代替 `COMMIT`，用审计行反向补造责任事实，把当前任务状态写进历史内容，以及关闭 D4、D5、D7、IR-02 或 IR-15。
