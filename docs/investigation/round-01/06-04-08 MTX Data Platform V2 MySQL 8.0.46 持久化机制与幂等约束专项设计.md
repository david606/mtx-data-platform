# 06-04-08 MTX Data Platform V2 MySQL 8.0.46 持久化机制与幂等约束专项设计

本文把已经写明的逻辑身份映射到 MySQL 8.0.46 上的候选唯一约束，并规定不可变记录的 Create-or-Get 语义。它是候选设计，不是已批准的物理模型，也不是 DDL。

基线提交是 `99b4978d0b04def51347d8d96db7476eb4cb869a`。服务器版本以 [ADR-0005](../../decisions/0005-mysql-doris-storage-baseline.md) 为准：MySQL 8.0.46，Apache Doris 4.0.7。8.0.46 不处于常规维护支持。生命周期风险的接受责任人仍未确认。

实体和生命周期沿用 [06-04-05](06-04-05%20MTX%20Data%20Platform%20V2%20持久化实体与数据生命周期清单.md)。存储职责沿用 [06-04-04](06-04-04%20MTX%20Data%20Platform%20V2%20持久化模型与存储职责专项设计.md)。工程边界沿用 [06-04-07](06-04-07%20MTX%20Data%20Platform%20V2%20数据库选型决策落实与工程约束.md)。未决状态沿用 [06-04-02](06-04-02%20MTX%20Data%20Platform%20V2%20工程实施未决设计决策台账.md)。

## 1. 官方能力与适用边界

证据来自 MySQL 8.0 参考手册。8.0.46 属于该手册覆盖的 8.0 系列。8.0.46 发布说明的条目是缺陷修复，没有改写下面引用的唯一索引、隔离级别或 `INSERT ... ON DUPLICATE KEY UPDATE` 定义。本轮不引用 MySQL 8.4 手册，也不把 8.4 的 `RETURNING` 或其他新增语法写成 8.0.46 的能力。

手册中的能力不等于本项目已经选用。字符集、排序规则、隔离级别、行格式和页大小都还没有项目决策。

| 能力 | 8.0 手册结论 | 对候选约束的限制 | 章节 |
| --- | --- | --- | --- |
| 唯一索引 | `UNIQUE` 要求索引值互异。为列指定前缀时，唯一性只覆盖该前缀长度，不覆盖整列 | 领域身份必须用完整列值约束。前缀唯一索引不能代替领域身份 | 15.1.15 `CREATE INDEX` |
| NULL | 允许 NULL 的列上，唯一索引可以有多行 NULL | 参与幂等的身份列必须是 `NOT NULL`。没有稳定事件身份时，不能靠 NULL 唯一索引合成“只有一行” | 同上 |
| 复合索引 | 多列索引最多 16 列 | 现有逻辑身份都少于 16 列。这不是把多个身份并成一个索引的理由 | 17.22 InnoDB Limits |
| 键长度 | `DYNAMIC` 或 `COMPRESSED` 行格式下，索引键上限 3072 字节。`REDUNDANT` 或 `COMPACT` 是 767 字节。页大小小于 16KB 时上限按比例下降。该限制同时适用于整列索引 | 列宽和字符集未定，所以现在不能证明四段观测身份一定放得进一个唯一索引 | 17.22 |
| 字符串比较 | 12.8.6 的例子说明，同一对字符是否相等取决于排序规则，例如某些规则下 `Bar` 与 `Bär` 比较相等。15.1.15 规定前缀长度对非二进制字符串按字符计，对二进制字符串按字节计。唯一索引判断的是索引值是否重复，因此身份列的排序规则会影响哪些字符串冲突 | 身份列若使用会把不同标识判为相等的排序规则，不同标识可能被当成同一键。具体排序规则仍未决 | [15.1.15](https://dev.mysql.com/doc/refman/8.0/en/create-index.html)，[12.8.6](https://dev.mysql.com/doc/refman/8.0/en/charset-collation-effect.html) |
| 分区 | 分区表达式中的每一列都必须出现在每一个唯一键中。不包含分区列的唯一键不能保证分区间唯一 | 不假设这些权威表分区。未证明分区列属于逻辑身份之前，不选分区键 | 26.6.1 |
| 普通 `INSERT` | 插入成功时对插入行加排他记录锁。唯一冲突时语句失败，并对已有重复索引记录加共享锁。两个等待者在持有者回滚或删除提交后，可能因互相持有共享锁而死锁 | 冲突后的读取要预期死锁。死锁不是覆盖原行的理由 | 17.7.3 |
| 重复键错误的事务 | 未使用 `IGNORE` 时，重复键错误回滚的是这条语句。死锁回滚的是整个事务。单条语句回滚不释放该事务已经持有的锁 | 重复键之后可以在同一事务中读取胜出行。死锁之后必须重试整个事务 | 17.21.5 |
| `INSERT IGNORE` | 与 `ON DUPLICATE KEY UPDATE` 一起使用时，重复键错误降为警告，语句继续，后续行仍可能插入 | 会掩盖本应失败的错误，也不能返回已有行。不用于不可变权威记录 | 15.2.7.2 |
| `ON DUPLICATE KEY UPDATE` | 唯一冲突时更新旧行。受影响行数 1 为插入，2 为更新，0 为写成原值；`CLIENT_FOUND_ROWS` 会把最后一种变成 1。多个唯一索引时可能只更新其中一行。冲突时加的是排他锁 | 定义本身就是更新。不可变记录不使用它，包括把列设成原值的写法 | 15.2.7.2、17.7.3 |
| 隔离级别 | InnoDB 默认 `REPEATABLE READ`。同一事务中的普通一致性读使用第一次读建立的快照。手册不建议在同一 `REPEATABLE READ` 事务里混用普通 `SELECT` 和加锁语句，因为两者看到的表状态可能不一致 | 项目尚未选定隔离级别。失败方不能靠一条更早的普通 `SELECT` 读取胜出行 | 17.7.2.1 |

上述行为没有在本仓库的 MySQL 8.0.46 实例上执行。标为官方文档，项目验证为待验证。

显式重放若四段观测身份都没有变化，候选唯一约束会返回原观测，不能另插一行。这保持“不覆盖旧观测”。若重放必须产生另一条观测，它必须改变这四段中的已有一段，例如新的 `snapshotId`。本轮不把 `taskId` 加进观测身份，也不替 R15 决定重放选哪一份快照。

## 3. Create-or-Get

不可变权威记录使用同一种行为。任务终态的合法迁移不是这条路径里的更新。本轮不写 Java 实现。

| 场景 | 行为 |
| --- | --- |
| A 首次写入 | 唯一索引中没有该身份。`INSERT` 成功，返回 `CREATED`，调用方采用刚写入的行 |
| B 相同身份、相同内容 | `INSERT` 因唯一冲突失败。读取胜出行，比较后内容相同，返回 `ALREADY_EXISTS`。不执行 `UPDATE` |
| C 并发写入 | 只有唯一索引能决定唯一胜出行。先提交成功的插入是权威。失败方读取该行，不保留自己的未提交副本 |
| D 相同身份、不同内容 | 仍然不 `UPDATE`。结果是已有的完整性异常。原行保持。不新增错误码 |
| E 事务异常 | 重复键只回滚该语句时，同一事务可以改为读取胜出行后结束，不能改写胜出行。死锁回滚整个事务，重新执行整次 Create-or-Get。锁等待超时按 8.0 默认只回滚当前语句；若服务器打开整事务回滚，则重试整次操作。这个服务器参数尚未选定 |

先 `SELECT` 再 `INSERT` 不能保证跨 Worker 幂等。两个事务都可以在对方插入前看到缺失。唯一索引才是并发边界。先读只是减少冲突的可选步骤。

| 语句 | 适用条件 | 风险 | 是否符合不可变记录 |
| --- | --- | --- | --- |
| 普通 `INSERT`，冲突后读取胜出行 | 身份列 `NOT NULL`，唯一索引覆盖完整逻辑身份 | 要处理 1062、死锁和锁等待。失败方必须用加锁读或新事务读取，不能用更早建立的 `REPEATABLE READ` 普通快照 | 符合。这是候选方案 |
| `INSERT IGNORE` | 无 | 重复键变成警告，其他可忽略错误也被吞掉，不返回已有行，多行语句还可能继续插入 | 不符合 |
| `INSERT ... ON DUPLICATE KEY UPDATE` | 无 | 手册定义是更新旧行。写成原值仍然走更新路径，并受 `CLIENT_FOUND_ROWS` 影响。多唯一索引时可能只更新一行 | 不符合 |

失败方读取的候选顺序：

1. 使用覆盖完整身份的唯一索引做加锁读，读取当前已提交的胜出行。
2. 比较不可变内容。相同则 `ALREADY_EXISTS`，不同则完整性冲突。
3. 提交或回滚当前事务，不对胜出行发 `UPDATE`。
4. 若遇到死锁，丢弃整个事务后从插入重新开始。

隔离级别仍未决。在它选定之前，不把某一种默认级别写成项目标准。上面的读取规则是为了避开 8.0 默认 `REPEATABLE READ` 下普通一致性读的旧快照。

## 4. 跨 Worker 并发

不使用 JVM 本地锁。不设计 Worker 租约、心跳或任务所有权，那些仍属于 IR-07。

| 情形 | 候选处理 |
| --- | --- |
| 两个 Worker 处理同一已声明稳定身份 | 任务唯一约束只留下原 `taskId`。双方都使用第一次保存的权威引用和权威 `receivedAt` |
| 两个 Worker 创建同一观测 | 四段唯一约束只留下一行。失败方读取该行及其一次写出的匹配结果 |
| 两个 Worker 创建同一标准化结果 | `normalizationIdentity` 只留下一行。版本固定记录先按 `versionFixKey` 取得胜出版本，再写标准化结果 |
| 不同 `snapshotId` | 观测身份不同，历史观测互不覆盖 |
| 显式重放 | 新 `taskId` 和新的 `replayRequestId`。同一 `replayRequestId` 返回原重放任务。不覆盖旧任务和旧观测 |
| 冲突后的内容校验 | 比较胜出行的不可变内容。不一致时不覆盖，也不把 Doris 副本当作权威 |

两个 Worker 同时插入同一键时，8.0 手册已经说明可能死锁。应用必须重试整次 Create-or-Get。重试仍然走插入和读取，不改成更新。

## 5. 候选唯一约束

这些是候选，不是 DDL。列名不必等于下表中的逻辑字段名。能直接落实指逻辑身份已经足够写出约束条件。字符集未定时，即使逻辑上可以直接落实，也不能创建物理索引。

| 实体 | 逻辑身份 | 候选唯一约束 | 依据 | 未决问题 |
| --- | --- | --- | --- | --- |
| Task | 来源已声明的稳定事件身份 | 该身份的全部字段 `NOT NULL` 且完整列唯一。没有声明的来源不建这条约束 | Pipeline 第 4.2 节 | 依赖 IR-03。作用域和字段未定。受排序规则和键长度影响。不分区 |
| ReplayRequest | `replayRequestId` | 该标识 `NOT NULL` 唯一，并只指向一个重放任务 | Pipeline 重放规则 | 依赖 IR-03 的生成算法。受排序规则影响 |
| TaskAttempt | `taskAttemptId` | 尝试标识唯一。不把 `taskId` 做成尝试表的唯一键 | 一次任务多次尝试 | 生成算法未定。不提前加入租约列 |
| TaskExecutionContext | 非重放任务的一份胜出上下文 | 每个非重放 `taskId` 唯一。可以是任务行上的列，不一定独立成表 | 两阶段固定 | IR-04 决定第一次写入哪份快照。IR-12 禁止另造通用阶段表 |
| Snapshot | `snapshotId` | `snapshotId` `NOT NULL` 唯一 | 已发布批次 | 不决定 R15 |
| ContractVersion | `contractVersionId` | 该标识 `NOT NULL` 唯一。正文哈希是内容，不是第二条身份 | 封存版本 | 哈希列长度未定 |
| RawPayloadReference | 任务上的权威引用 | 不做全局唯一。随任务行保存且不更新 | 引用不是正文 | 引用字段长度未定 |
| RawPayload | 无 MySQL 主键 | 不建 | 介质未选 | IR-15 |
| ExtractedFieldResult | 三段字段结果键 | 三段都 `NOT NULL` 的完整列唯一 | Pipeline 字段结果键 | 受键长度和排序规则影响。不建第二份 |
| ObservedAmount | 四段观测身份 | 四段都 `NOT NULL` 的完整列唯一。匹配结果在同一行 | Pipeline 第 2 节 | 受键长度和排序规则影响。不含 `taskId` 和 `parserVersion` |
| MappingResult | 无 | 不建 | 一次写出 | 无 |
| 版本固定记录 | `versionFixKey` | 该键 `NOT NULL` 唯一 | 标准化前的固定 | 是否独立成表未决 |
| NormalizedAmount | `normalizationIdentity` | 该身份 `NOT NULL` 唯一 | Pipeline 第 8 节 | IR-14。受键长度影响 |
| ConflictDecision | 决定标识 | 该标识 `NOT NULL` 唯一 | ADR-0003 | 新决定用新标识 |
| AuditRecord | 三类审计身份之一 | 按所属身份唯一，不把 `taskAttemptId` 放进身份 | Pipeline 审计身份 | IR-10。物理列未冻结 |
| QualityCheckResult、WriterExecutionRecord、ProcessingErrorRecord | 无 | 不建 | 当前不应建立 | IR-17 只约束前两个 |
| Doris 分析数据 | 无 | 不建权威唯一约束 | ADR-0005 | 物理模型未做 |

对候选约束的统一限制：

- 身份列使用 `NOT NULL`。否则 8.0 的唯一索引允许多个 NULL。
- 唯一性必须覆盖完整逻辑列。前缀索引只保证前缀唯一，不能采用。
- 排序规则未决。候选要求不同的身份字符串在所选排序规则下仍然不同。具体字符集和排序规则不在本轮指定。
- 3072 字节上限是否足够，要等列宽、字符集和页大小确定后验证。现在标为待验证。
- 不因为可能超长就把哈希列当成领域身份。若以后增加固定长度的技术摘要列，冲突或读取时仍要比较全部逻辑字段。摘要碰撞不能当成同一业务身份。算法未选。
- 不分区。8.0 要求分区列进入每一个唯一键。现有身份里没有已经证明可以当分区键的列。

可以留给后续物理模型使用的候选结论是：不可变记录用普通 `INSERT` 加完整列唯一索引，冲突后加锁读取胜出行，内容不同则保持原行。不能留给后续直接执行的是表、索引名、列宽、字符集、隔离级别和哈希算法。

IR-02 关闭至少还要同时满足：身份列宽已经证明可以建立完整列唯一索引，排序规则不会把不同身份并成一个键，失败方读取胜出行的过程有针对 8.0.46 的验证，并且相关设计场景不再只是未执行条目。本轮一项都没有完成。
