# 06-04-07 MTX Data Platform V2 数据库选型决策落实与工程约束

本文记录 [ADR-0005](../../decisions/0005-mysql-doris-storage-baseline.md) 接受之后，工程上可以依赖什么，以及仍然不能做什么。它不编写 DDL，不引入驱动，也不把建议表写成已批准物理模型。

## 1. 已落实的版本

| 技术 | 目标服务器版本 | 决策状态 | 工程状态 |
| --- | --- | --- | --- |
| MySQL | 8.0.46 | 已接受 | 未接入。无驱动、无连接配置、无已确认库表 |
| Apache Doris | 4.0.7 | 已接受 | 未接入。客户端和驱动未锁定，五层物理模型未设计 |

版本写完整的 8.0.46。不使用笼统的 8.0。旧生产环境的 MySQL 8.0.45 和 `doris-4.0.7-rc02` 构建标识属于 `trade-flow` 证据，不是 V2 目标构件。

IR-01 已关闭。关闭的是事务型产品及其服务器版本，以及 Doris 服务器版本。IR-09 仍待决策。IR-17 仍待决策，质量结果、Writer 账本和 Doris 物理模型都没有完成。

## 2. 版本确定不等于工程接入

服务器版本确定之后，下面这些事仍然没有发生：

- 根 POM 或模块 POM 没有 MySQL 驱动，也没有 Doris 客户端。
- 应用没有数据源配置。
- `docs/database/` 和 `sql/` 没有已确认模型。
- 06-03-02-03 的 MySQL 表仍是建议。不能因为版本已经接受就执行。
- JDK 25 与 MySQL 8.0.46 的连通、字符集行为和隔离级别都没有在本仓库验证。

驱动版本、连接池、字符集、排序规则和事务隔离级别继续未决。Redis 和 Flyway 仍未选定。

## 3. 工程约束

1. Core 不依赖 JDBC 或数据库客户端。不新增模块来放置驱动。
2. 金额结果是否与元数据放在同一个数据库，仍按 06-04-04 的早期建议保持同一种产品、同一个数据库，直到 IR-09 写明提交点。ADR-0005 没有批准拆库。
3. Doris 4.0.7 只接收已经提交的分析副本。它不保存任务终态、配置发布、审计权威或原始报文正文。
4. 原始报文介质仍未选定。`rawPayloadRef` 不是正文，也不因为 MySQL 版本已确定就把正文放进关系库大字段。
5. MySQL 8.4 手册中的语句、分区和 JSON 行为不能写成 8.0.46 已验证能力。
6. 不假设以后可以无风险直接升级到 MySQL 8.4 LTS。升级前必须另做兼容性评估，并另有已接受决策。生产上线前还要重新核验安全维护和支持条件。
7. 8.0.46 的生命周期风险已记入 ADR-0005。End of Life、Sustaining Support 和常规维护支持不是同一个状态。风险接受责任人尚未确认，本文不虚构审批记录。

## 4. 仍不能开始的工作

- 创建数据库或执行 DDL。
- 把 06-03-02-03 的建议表当成已批准设计。
- 设计 Doris 的 ODS、DWD、DIM、DWS、ADS 物理表，并把它写成已经完成。
- 关闭 IR-09 或 IR-17。
- 修改金额处理规则。那些规则仍以 ADR-0003 和 ADR-0004 为准。
