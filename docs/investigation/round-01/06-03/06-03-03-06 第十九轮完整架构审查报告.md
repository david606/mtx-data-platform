## 3. 第十八轮整改差异核验

`git show f065e5b` 删除的原句是：本次输入声明的 `rawPayloadRef` 必须与该任务已经保存的权威引用标识相同。

同一次差异还改了第 3.1 节图、第 4.2 节、第 5.1 节和 E2E-063，并新增 E2E-170 至 E2E-175。第 17 节至第 33 节没有被改写。第 34 节记录这次修订，并继续把 P-03、P-06、R15 标成未决定。

## 5. 任务身份及执行上下文审查

这些身份没有合并：

| 身份 | 作用 | 重复投递或重试时 |
| --- | --- | --- |
| 稳定接入事件身份 | 非重放任务的幂等身份 | 决定是否回到原 `taskId` |
| `taskId` | 逻辑任务内部标识。生成算法待存储设计 | 重复投递和技术重试沿用 |
| 权威 `rawPayloadRef` | 第一次接受时保存。观测身份的一部分 | 不被本次新引用替换 |
| `receivedAt` | 窗口判断的业务时间 | 以第一次接受的值为准，不充当任务身份 |
| `taskAttemptId` | 一次尝试 | 技术重试可以新建 |
| `replayRequestId` | 显式重放的调用方标识 | 同一个标识返回已有重放任务。普通重复投递不能产生它 |
| `snapshotId`、`parserVersion` | 第一阶段固定 | 原任务重试不换。显式重放可以按该次策略重固定 |
| `contractVersionId` | 第二阶段在胜出快照内确定 | 原任务重试不换已固定版本 |

首次接收保存不可变输入，其中包括权威引用和权威 `receivedAt`。重复投递保留这些原值。技术重试复用原任务和已固定上下文，见 E2E-174。显式重放是新 `taskId`，见 E2E-066 和 E2E-175。没有发现用 `rawPayloadRef` 或 `receivedAt` 反推任务身份的现行规则。来源没有稳定事件身份时，文档仍写明待来源契约确认，不伪造幂等键。
