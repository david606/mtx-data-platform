## 2. 当前已确认规则

- presence 只有七种。不增加第八种。
- `0`、`0.0`、`"0"`、`"0.00"` 都是 `NUMERIC_ZERO`，token 各自保留。空 `Money` 不是 0。
- 06-03-03-02 的字符串例子把 `rawText` 写成 `18.50`，JSON 引号不在 `rawText` 里。
- 带空格、带单位、多个数字拼在一起是 `OTHER_TEXT`。不 trim，不挖数字。
- 提取不建 `Money`。标准化不改 `rawText`，失败不把观测改成 0。
- `UNMAPPED` 和 `CONFLICT` 保留观测，不进入标准化。ADR-0004 的契约版本失败不写观测，不降成 `UNMAPPED`。
- `PRESERVE_SOURCE`：不取绝对值，不丢负号，不把负数改成 0，也不因类型是退款就改成负数。
- 观测身份是 `rawPayloadRef + snapshotId + contractVersionId + fieldPath`。不含 `parserVersion`。标准化身份再加两个规则版本，不含 `parserVersion`。
- 已有观测的重试返回原观测，不重新解析覆盖字面量。
- 三个版本不合并。`normalizationRuleVersion` 尚未分配。没有封存的 `conversionRuleVersion`。

## 3. 四项决策的方案比较

### 3.1 JSON 数字与数字字符串

【待确认】06-03-01 把 `NUMERIC_TEXT` 写成字符串。06-03-03-01 把非零 JSON 数字和整个十进制字符串都标成 `NUMERIC_TEXT`。

| 问题 | 方案 A：只保留 presence 和 rawText | 方案 B：七种 presence 不变，另记 JSON 节点种类 |
| --- | --- | --- |
| `12` 与 `"12"` | presence 相同，`rawText` 都是 `12`。节点差别丢失 | presence 仍可相同，节点种类分别是数字和字符串 |
| `12.0` 与 `"12.0"` | 标度都可以是 1，节点差别同样丢失 | 标度规则不变，节点种类分开 |
| `0`、`0.0`、`"0"`、`"0.00"` | 【设计决定】都是 `NUMERIC_ZERO`，token 不合并。A 已能保留这四种字面量 | 同样保留 token。节点种类再区分数字零和字符串零 |
| JSON 引号 | 【设计决定】现有例子不把引号放进 `rawText`。A 因此无法用引号补回节点种类 | 引号仍不进入 `rawText`。节点种类单独保存 |
| 事实放在哪里 | 只放在提取结果和观测已有的 presence、`rawText` | 提取的内存结果先记下。观测必须抄下同一事实，因为 `RawAmountValue` 不单独落库 |
| 观测身份 | 两种方案都不把节点种类加入四段身份 | 同左。身份变化会让同一报文变成另一条观测，本方案不建议 |
| 历史数据 | 没有生产观测。一旦按 A 写下，以后不能从 `rawText` 恢复节点种类 | 从第一条观测就带上种类。不需要回填 |
| Java 与测试 | 输入模型少一个字段。测试不能断言 `12` 和 `"12"` 不同 | `ObservedAmountFacts` 增加节点种类。测试可以分开断言 |

代价和风险：方案 A 改动小，但永久丢失节点差别，字符串是否允许解析就无法按节点执行。方案 B 多一个不可变事实，观测字段变多；若忘记抄到观测上，标准化阶段重读 JSON 才能知道种类，而这是禁止的。

【审查建议】推荐方案 B。节点种类放在提取结果，并作为观测上的不可变事实抄录。不进入观测身份，不进入 `rawText`，不新增 presence。确认前两种方案都不实现。

需要确认的问题：`12` 与 `"12"`、`12.0` 与 `"12.0"` 是否必须在观测上区分。若回答否，方案 A 就够用。

### 3.2 科学计数法

【待确认】06-03-03-04 不把 `1e2` 收成 `100`。06-03-03-01 又把非零 JSON 数字都标成 `NUMERIC_TEXT`。JSON 语法允许指数，不等于业务允许。`BigDecimal` 能解析指数，也不等于业务允许。

五个例子在语法上都是指数：`1e2`、`1E2`、`1.0e2`、`1e+2`、`1e-2`。`e` 与 `E`、显式 `+` 与省略 `+`，都是同一种指数写法，不是四种业务单位。

| 方案 | 提取 | 标准化 | 数值和标度 | 代价 |
| --- | --- | --- | --- | --- |
| 接受并定义语义 | 标成 `NUMERIC_TEXT` 或 `NUMERIC_ZERO`，token 原样保留 | 按新定义的标度解析，仍不改 `rawText` | 必须新写规则。例如 `1e-2` 的标度可以是 2，`1e2` 的标度却没有现成句子。`1.0e2` 与 `1e2` 不能自行当成同一标度 | 抵触标准化初稿“不收成 100”。重放时提取表和解析标度必须同时冻结 |
| 拒绝且不转换 | 不标成两种数字形态 | 不生成结果，不改 token | 不产生标度 | 要收窄“全部非零 JSON 数字” |
| 提取为 `OTHER_TEXT` | 字段码仍可为 `OK`。token 留在观测上 | 现有门禁已拒绝 `OTHER_TEXT` | 无 | `OTHER_TEXT` 今天的例子是其他字符串。用它容纳 JSON 数字指数，是扩大这一个 presence 的对象，不是新枚举 |
| 提取为字段失败 | 不形成正常观测。现有字段码只有 `TYPE_MISMATCH`、`PATH_NOT_UNIQUE`、`RAW_TEXT_UNRETAINABLE` | 没有观测可解析 | 无 | 这三个码都不是“语法拒绝”。用它们会改失败语义。字面量若因失败而不留在观测上，就看不到平台原来传了 `1e2` |

职责：提取负责分类和保留 token。标准化不重新分类，不把指数改成普通十进制。接受方案的标度只可能出现在标准化，且现在没有定义。

【审查建议】推荐拒绝，并且提取记为 `OTHER_TEXT`、字段码保持 `OK`。标准化见到指数 token 或 `OTHER_TEXT` 都不生成结果、不改 `rawText`。不推荐字段失败，因为没有对得上的现有字段码。不推荐接受，因为会发明标度。确认前，提取表的“全部 JSON 数字”仍然有效，Java 不能提前拒绝。

需要确认的问题：五个指数写法是否一律 `OTHER_TEXT`。若负责人要求不留观测，必须指出使用哪一个已经存在的字段码，不能新造码。

### 3.3 正负号

【设计决定】符号一旦进入金额值，就按 `PRESERVE_SOURCE` 保留。退款类型不因此变成负数。负优惠是否允许仍待业务确认。冲正没有已接受的 V2 符号规则，本方案不补。

| 输入 | 语法 | 现有分类 | 原始符号 | 业务允许性 |
| --- | --- | --- | --- | --- |
| JSON 数字 `-12` | JSON 数字可以有减号 | 非零 JSON 数字行会把它标成 `NUMERIC_TEXT` | token 应留下 `-` | 分类不等于允许负金额 |
| JSON 数字 `-0` | 语法合法，数值是 0 | “正好是 0”可能落入 `NUMERIC_ZERO`。稿件没有 `-0` 例子 | 不能改写成 `0` | 同上 |
| 字符串 `"-12"`、`"-12.50"` | 不是 JSON 数字规则本身 | 06-03-03-04 第 15 节：没有例子 | 若将来接受，减号留在 token | 负优惠、退款、冲正都未因此获准 |
| 字符串 `"+12"`、`"+0"`、`"+12.50"` | 不能作为 JSON 数字。只能是字符串 | 没有例子。正号不是已写的十进制数字 | 不能删掉 `+` 变成无符号 token | 正号不是业务方向 |
| 字符串 `"-0"` | 字符串 | 没有例子 | 不能改成 `0` 或 `0.00` | 不等于 `NUMERIC_ZERO` 已有的四个例子 |

【审查建议】推荐：

- JSON 数字的减号留在 token 里，presence 仍按现有“非零 JSON 数字”和“数值正好是 0”两行。`-0` 在确认前不写成已经是 `NUMERIC_ZERO`。
- 正号字符串推荐为 `OTHER_TEXT`。标准化不解析。
- 减号字符串保持待确认，不归入 `NUMERIC_TEXT`。
- 任何方案都不取绝对值，不丢符号，不把负数改成 0。
- 业务是否允许负优惠、负的退款金额或冲正，单独确认。技术解析成功不代替这项确认。

代价：正号被拒绝后，若某平台把金额放在带 `+` 的字符串里，该字段没有标准化结果，观测仍可保留为 `OTHER_TEXT`。减号字符串继续悬空时，解析器不能上线。

需要确认的问题：正号字符串是否就是 `OTHER_TEXT`；减号字符串是否属于数字文本；`-0` 作为 JSON 数字时是否为 `NUMERIC_ZERO` 且 token 为 `-0`；负优惠和退款负数是否允许出现。

### 3.4 字符串数字的映射许可

【待确认】06-03-01 写明只有 `NUMERIC_ZERO` 或映射明确允许的 `NUMERIC_TEXT` 才可能产生 `Money`。06-03-03-01 对字符串行写“映射没有允许之前，不能变成 `Money`”。06-03-02-02 对个别字段写“本规则未批准解析”。06-03-03-04 则写门槛通过后按第 5 节解析。

| 方案 | 映射表达 | 资格枚举 | ADR-0003 | 类型和快照 | 重放 |
| --- | --- | --- | --- | --- | --- |
| 凡是十进制字符串都可进入标准化 | 映射不用再声明字符串许可。与 06-03-01、06-03-03-01 的“映射允许”句子冲突 | 不需要新值 | 不改变 `UNMAPPED`、`CONFLICT` 的保存 | 不激活类型。会让尚未批准解析的草稿字段在将来发布后自动可解析 | 旧观测不改。新快照上的新观测会按更宽的规则解析 |
| 契约或该字段映射明确声明后才允许 | 声明写在该映射条目已有的正文里，不新造资格 | 不新增 `MappingEligibility` | 不修改 ADR-0003。未声明时仍可形成观测，只是不产生 `Money` | 不改类型生命周期，不改快照结构。声明是映射正文的一项事实 | 旧观测的 `mappingStatus` 不回写。新快照才用新声明 |
| 继续只用现有资格，不增加许可字段 | `ALLOWED_IF_CONTRACT_DEFINES` 回答能不能映射，不回答字符串能不能解析 | 不新增 | 不修改 | 资格不变，字符串许可仍然没有着落 | 冲突继续存在，重放无法知道字符串是否可解析 |

JSON 数字节点和字符串节点在这里分开：06-03-03-01 的“映射没有允许之前”写在字符串那一行。数字节点没有同一句限制。方案比较不应把这句扩到全部 JSON 数字。

【审查建议】推荐第二条：不新增资格枚举，不修改 ADR-0003，不改标准类型。字符串节点要产生 `Money`，必须由该字段映射正文明确允许。没有这句时，观测可以存在，标准化不产生结果。JSON 数字节点不套用这句字符串许可。确认前，06-03-03-04 的“门槛通过即解析”仍然没被撤销，代码不能选择其中一边。

代价：映射正文要有一处可读取的“允许字符串数字”事实。今天的草稿没有这条已发布声明，所以即使语法确认了，也不会产生生产结果。

需要确认的问题：这句声明放在映射正文的哪一项现有字段；JSON 数字节点是否确实不需要同一句声明。

## 4. 推荐方案与推荐理由

【审查建议】四项推荐同时成立才构成一套可修订的输入语义。任一未确认，都不写 Java。

| 决策 | 推荐 | 理由 |
| --- | --- | --- |
| 数字节点与字符串 | 方案 B | 引号不在 `rawText` 里，方案 A 区分不了 `12` 和 `"12"` |
| 科学计数法 | 拒绝，提取为 `OTHER_TEXT` | 不发明标度，不新造字段码，token 仍留在观测上 |
| 正负号 | 正号字符串为 `OTHER_TEXT`；减号字符串继续待确认；JSON 减号留在 token | 正号不是 JSON 数字，也没有十进制例子。业务负金额另确认 |
| 字符串许可 | 映射正文明确允许后，字符串才产生 `Money` | 与 06-03-01、06-03-03-01 的字符串句子一致，且不新增枚举 |

## 5. 每项推荐的代价和风险

- 方案 B 让观测多一个事实。漏抄就会迫使标准化重读报文。
- `OTHER_TEXT` 容纳指数，扩大了这个 presence 今天的例子范围。若负责人拒绝扩大，五个指数例子就没有可落的现有码。
- 减号字符串不推荐归类，解析器的成功路径继续关闭。
- 字符串许可依赖映射正文。正文里还没有冻结的栏目名，架构负责人需要指定用哪一项已有字段，而不是新枚举。
- 四项都未确认。按推荐提前编码，会把本方案写成事实。

## 6. 提取阶段与标准化阶段契约

以下是推荐被确认之后的候选契约，不是已批准接口。

### 6.1 提取

输入：

| 输入 | 必填 | 语义 |
| --- | --- | --- |
| 原始报文引用 | 必填 | 权威 `rawPayloadRef`。取不回原文是任务级阻断 |
| `snapshotId` | 必填 | 任务已经固定的快照。不改读最新快照 |
| `parserVersion` | 必填 | 与快照同一阶段固定。重试复用。不进入观测身份 |
| `contractVersionId` | 必填 | 只在该快照内确定。未确定则没有字段结果 |
| 契约声明的字段路径 | 必填 | 只读封存清单。不扫描报文猜金额 |

输出，每个声明路径一条：

| 输出 | 语义 |
| --- | --- |
| 节点种类 | 仅方案 B 被确认后才有。数字、字符串、null、缺失、数组或对象 |
| presence | 现有七种之一 |
| rawText | 有字面量时保留 token，不含 JSON 引号。缺失和 null 没有字面量 |
| 字段提取状态 | 现有 `fieldCode`：`OK`、`TYPE_MISMATCH`、`PATH_NOT_UNIQUE`、`RAW_TEXT_UNRETAINABLE` |
| 拒绝信息 | 只引用已有阻断码或已有字段码。不新造错误码 |

任务级阻断：报文无法解析、原文引用无效、契约版本无法确定、契约身份不一致、正文哈希不符、路径清单未定义、损坏或完整性失败。这些都不写字段结果和观测，不降成 `UNMAPPED`。

字段级失败：`TYPE_MISMATCH`、`PATH_NOT_UNIQUE`、`RAW_TEXT_UNRETAINABLE`。其他路径继续。这三种不形成正常观测。

按推荐，指数和正号字符串是 `OTHER_TEXT` 且字段码 `OK`，不是任务阻断。未确认前，这句推荐无效。

### 6.2 标准化

输入：

| 输入 | 必填 | 语义 |
| --- | --- | --- |
| 不可变 `ObservedAmount` | 必填 | 只读 presence、`rawText`、字段码、匹配事实。不重读 JSON |
| 字段映射事实 | 必填 | 当次观测已写下的资格、语义、证据。不重新匹配 |
| 快照目录事实 | 必填 | 该观测引用的目录，不是今天的最新目录 |
| `normalizationRuleVersion` | 仅结果构造时 | 门禁未过不得编造。未分配时不能构造生产结果 |
| `conversionRuleVersion` | 仅在要求换算并已封存时 | 当前没有封存版本。不转换时为空，不是标准化规则版本号 |

两个版本不是门禁函数的输入。06-03-03-04 和 06-03-03-06 的顺序是先过门禁，再固定版本，再写结果。本契约保持这个顺序。

输出三选一：

- 标准化成功结果：只在全部门禁通过且版本固定返回之后。当前不会发生。
- 字段级拒绝：形态、单位、币种、字面量、未声明的字符串许可，或要求换算但没有转换版本。观测不改。其他字段继续。
- 任务级完整性异常：三种禁止资格、非 `部分确认` 的已映射语义、未排除的第二种解释，或运行时证据表禁止的证据出现在 `MAPPED` 上。不降成 `UNMAPPED`。

标准化不重新读取原始 JSON，不修改观测，不推断币种、单位、精度或舍入，不取绝对值。

## 7. 候选 Java 类及模块职责

这些类没有创建，也不是已批准接口。Core 包候选 `com.mtx.rdp.core.amount`。Transform 包候选 `com.mtx.rdp.transform.amount`。

| 类 | 模块 | 职责 | 输入及必填语义 | 输出 | 依赖 | 是否等待决策 | 对应测试 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `RawAmountValue` | Core | 一次提取的内存事实 | 路径必填。presence 必填。rawText 在缺失和 null 时无。节点种类在方案 B 确认前不设 | 不可变过程值 | 无基础设施 | 是。四项都影响分类 | 第 9 节提取行。现在不写 |
| `ObservedAmount` | Core | 不可变领域记录 | 四段身份必填。抄录 presence 和 rawText。节点种类仅方案 B 确认后必填 | 观测。匹配结果在同一记录 | 不依赖 Transform | 是。身份本身不改 | 不可变和重试不覆盖。现在不写 |
| `ObservedAmountFacts` | Core | 交给纯函数的只读输入 | 字段码、presence、执行状态必填。节点种类待方案 B | 无副作用 | 无 | 拒绝判断可以暂不带节点种类 | 06-03-03-08 的拒绝用例。语法用例等待决策 |
| `AmountNormalizationGate` | Transform | 已写明的拒绝 | 事实必填。是否要求换算必填 | 拒绝，或“不足以成功” | 只依赖 Core | 成功路径等待四项决策 | 未识别、冲突、非数字形态、要求换算 |
| `NormalizationRefusal` | Core | 返回已有门禁 | 门禁名称必须是已有句子，不能新造码 | 字段级或任务级拒绝 | 无 | 指数和正号在确认前没有稳定原因名 | 只断言不生成结果 |
| `DecimalLiteralParser` | Transform | 无修改解析已确认 token | rawText 必填。节点种类在方案 B 后必填 | 未标度整数和标度，或失败 | 禁止 `double` | 是 | 第 9 节全部待决策行。现在不能写成通过标准 |
| `Money` | Core | 数值、币种、单位、标度 | 四项都必填。符号在数值里 | 不可变值。不写回观测 | 无 | 是。币种、单位、负金额都未决 | 不生成。禁止默认 `CNY` |
| `NormalizedAmount` | Core | 逻辑结果 | 观测身份和两个已固定版本必填 | 一条结果 | 版本固定记录尚不存在 | 是 | 不生成生产结果 |

调用方向：提取产生 `RawAmountValue`；匹配形成 `ObservedAmount`；Transform 的门禁只读事实；解析器在门禁通过之后才可能被调用；Pipeline 将来只依赖 Core 端口；Writer 将来只写出已经形成的结果。

## 8. 完整调用流程

```text
权威原文引用
  -> 固定 snapshotId 与 parserVersion
  -> 只在该快照内确定 contractVersionId
       不能确定：任务阻断，无观测
  -> 按声明路径提取
       字段码不是 OK：不写观测，其他字段继续
       字段码 OK：记下 presence、rawText，方案 B 再记节点种类
  -> 匹配
       UNMAPPED 或 CONFLICT：保留观测，停止
       任务级完整性异常：不改读最新快照
       MAPPED：进入标准化
  -> 标准化只读观测
       不重读 JSON，不改观测
       字段拒绝或其他门禁失败：无结果
       全部通过：才固定两个规则版本
       版本不能固定：不编造，无 NormalizedAmount
  -> 将来的 Pipeline 与 Writer
```

当前仓库停在“无已发布映射”。流程中的成功结果不会出现。
