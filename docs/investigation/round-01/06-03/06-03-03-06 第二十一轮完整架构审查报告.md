## 5. 任务身份及原文引用审查

这些身份没有合并，也没有新增字段：

| 身份 | 作用 | 重复投递、重试或重放 |
| --- | --- | --- |
| 稳定接入事件身份 | 非重放任务的幂等身份 | 决定是否回到原 `taskId` |
| `taskId` | 逻辑任务内部标识。生成算法待存储设计 | 重复投递和技术重试沿用。显式重放新建 |
| `taskAttemptId` | 一次尝试 | 技术重试可以新建。不进入观测身份 |
| 权威 `rawPayloadRef` | 第一次接受时保存。观测身份的一部分 | 不被本次新引用或本次缺失替换 |
| `receivedAt` | 窗口判断的业务时间 | 以第一次接受的值为准。不是任务身份 |
| `snapshotId`、`parserVersion` | 第一阶段固定 | 原任务重试不换。显式重放可以按该次策略重固定 |
| `contractVersionId` | 第二阶段在胜出快照内确定 | 原任务重试不换已固定版本 |
| `replayRequestId` | 显式重放的调用方标识 | 同一个标识返回已有重放任务。普通重复投递不能产生它 |

九种入口行为与现行句子一致：

1. 首次接收保存不可变输入，其中包括权威引用和权威 `receivedAt`。
2. 相同稳定事件再次投递返回原 `taskId`。E2E-170。
3. 不同稳定事件不因引用相同或不同而合并。E2E-171。
4. 相同事件、不同引用仍回原任务，并继续使用第一次保存的权威引用。E2E-063、E2E-172、E2E-173。
5. 相同事件、本次缺失引用仍回原任务。E2E-176、E2E-177。
6. 相同事件、看到的 `receivedAt` 不同，仍回原任务，权威业务时间不变。E2E-064。
7. 技术重试沿用原 `taskId`、原权威引用和已固定上下文，可以新建 `taskAttemptId`。E2E-065、E2E-174。
8. 显式重放是新 `taskId` 加调用方 `replayRequestId`。普通重复投递不创建重放。E2E-066、E2E-067、E2E-068、E2E-175。
9. 多 Worker 并发时，第一阶段只保留一套胜出快照，第二阶段只在该快照内保留一套契约版本。观测并发由 `persistObservation` 的 `CREATED` 或 `ALREADY_EXISTS` 收敛。物理索引、锁和事务仍待存储设计。

来源没有稳定事件身份时，仍待来源契约确认。文档没有用来源金额、`rawPayloadRef` 或 `receivedAt` 拼通用键。

缺失引用规则的适用前提是：该事件第一次接受时已经保存了权威引用。首次接入本身就没有引用，不在 E2E-176 和 E2E-177 的场景里，正文也没有把它写成另一条任务创建规则。这是既有前提，不是第二十轮引入的规则缺口。

## 7. ADR-0004 一致性审查

Pipeline 第 2、3.1、4、4.1、5.2 节仍是方案 C，与 ADR-0004、06-03-02-03、06-03-03-01 和 06-03-03-03 的已同步规则一致：

- 先固定 `snapshotId`，再在该快照内解析。
- 已给出 `contractVersionId` 时只作为候选优先校验。不属于胜出快照是 `CONTRACT_VERSION_UNRESOLVED`。家族身份、`contractId` 或外部版本号不一致是 `CONTRACT_IDENTITY_MISMATCH`。正文哈希不符是 `CONTRACT_VERSION_HASH_MISMATCH`，不使用部分路径。全部通过后不再用外部版本号重选。
- 未给出时才按家族和外部版本号解析。“未提供”只与同为“未提供”的修订比较。零个或多个是 `CONTRACT_VERSION_UNRESOLVED`，不降成 `UNMAPPED`。
- 临时读取尚未确定候选数量时，原任务用原 `snapshotId` 重试，不记成 `CONTRACT_VERSION_UNRESOLVED`。
- 确定性失败不因普通重试变成功，也不自动切换新快照。新快照上的重新处理是显式重放，不覆盖旧观测。

身份不一致和正文哈希不符同时成立时，第 4.1 节仍标待确认。这与 ADR-0004 只分别给出两个已有码、没有单一优先条款的现状一致。本轮不选择其中哪一个。

R15 仍待决。ADR-0004 文末保留 06-03-02-03 第 8 节与第 14 节的快照选择措辞差异，以及校验失败时能否跳过快照。Pipeline 第 2 节写明本文不决定。本轮不关闭它。
