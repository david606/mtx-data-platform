## 3. 总体架构结论

当前主链路是：用稳定事件身份找到逻辑任务，只比较权威 `rawPayloadRef` 标识，两阶段固定快照和契约版本，再按观测身份查询。已有观测直接返回。没有观测时才读取原文内容、提取、匹配并一次持久化。`MAPPED` 通过第 5.6 节全部门禁后才标准化，标准化成功不是计算授权。

这条逻辑设计与 ADR-0004 方案 C、观测身份和模块边界一致。第十四轮 P-01、P-02 的原缺陷、P-04、P-05、P-07 在当前正文中已经关闭。P-03 和 P-06 仍正确地标为待确认。R15 仍独立待决。第十六轮已经把已有观测的恢复从原文内容读取中拆开，E2E-165 至 E2E-169 与这一规则一致，并且都未执行。

不具备设计冻结条件。测试没有执行。物理索引、事务、解析器版本、计算身份和跨进程审计恢复仍待设计。另外，第 4 节初始化第 2 步写“本次引用必须与权威引用相同”，第 4.2 节和 E2E-063 又允许同一稳定事件以另一个 `rawPayloadRef` 回到原任务。这是新的措辞冲突，不是第十六轮要消除的“内容读取失败取消恢复”。

## 7. 新发现的问题

### P2-01

| 项 | 内容 |
| --- | --- |
| 严重程度 | P2 |
| 章节 | 第 4 节初始化第 2 步，对照第 4.2 节和 E2E-063 |
| 原文依据 | 第 2 步写：“本次输入声明的 `rawPayloadRef` 必须与该任务已经保存的权威引用标识相同。”随后只写标识缺失或不一致时不改用另一份报文，并且不得因为内容尚未读取就在查询前阻断 |
| 冲突依据 | 第 4.2 节写：相同稳定事件再次到达时，即使重新保存报文导致 `rawPayloadRef` 不同，也不新建逻辑任务。权威原文引用以第一次被接受时保存的输入为准。E2E-063 的预期是回到原 `taskId`，不新建逻辑任务 |
| 问题原因 | 第十六轮为了分开引用标识和内容读取，把“必须相同”写成了校验要求，但没有写明重复投递带来的不同标识如何继续 |
| 可能影响 | 实现时可能把第 4.2 节允许的重复投递拒绝掉，或者在查询前把标识不一致当成阻断 |
| 修复建议 | 写明：重复投递可以携带另一个引用标识，任务仍回到原 `taskId`。观测身份继续使用已经保存的权威 `rawPayloadRef`，不改用本次报文上的新标识。这一差异本身不新增错误码，也不在查询已有观测之前阻断。内容读取规则保持第 6 步不变 |
| 验收标准 | 第 4 节第 2 步、第 4.2 节和 E2E-063 都允许同一稳定事件以不同 `rawPayloadRef` 回到原任务，并使用第一次保存的权威引用。已有观测仍不依赖原文内容读取。不新增错误码 |
