# 06-02-R-02 金额空值、零值与撤销语义专项核验

本轮只读代码、仓库内接口摘录和已完成的 06-02、06-DB-01-06。没有改代码，没有查生产业务行，没有把设计文档或代码注释写成官方字段定义。

不同金额列没有同一套空值含义。

## 订单头

`DorisCanonicalFactWriter.orderCoreUpdateSql` 5358–5370 行对商品原价、订单原价、计价基数、优惠后金额、实付、优惠总额、包装费、配送费、商家收入、订单退款成功额使用 `COALESCE(新值, 旧值)`。

因此：

- 后续更新传入 `null`，旧金额留着。`null` 在这条 SQL 里不能表示撤销。
- 传入 `0` 会写成 0。0 和 null 不是一回事。
- 负数只要 Mapper 放行，这条 SQL 不拦。
- 较旧写入序号不能改行。条件是 `meta_sink_sequence` 为空或 `<=` 新序号，5390 行附近与营业额更新相同。

营业额是例外。`orderTurnoverUpdateSql` 5336 行直接写 `:turnoverAmount`。5233–5234 行注释写明 `NULL` 是明确撤销，不用 `COALESCE` 留旧值。计算器返回 `null` 时，只要本次序号不旧，会把营业额清空。

相同序号允许再写，因为条件是 `<=`，不是 `<`。序号更小的事件不能把已清空的营业额写回去。序号为空的旧行可以被任意本次序号改写。

## 商品行

首次插入 `ITEM_SQL_TEMPLATE` 234 行：

`COALESCE(:refundSuccessQuantity, 0)`、`COALESCE(:refundSuccessAmount, 0)`。

还没有退款累计时，这两列会被写成 0。0 在这里是占位，不是已经证明“真实退款额为 0”。其他商品金额列按参数原值插入，没有这层 0 填充。

已有商品行的退款累计补丁分两条：

- 京东、淘宝 `writeRefundSuccessPatch` 4128–4132 行直接赋值，条件 `meta_sink_sequence <= :sinkSequence`。相同序号可以再写。
- 富智云 `writeFuiouItemPatch` 4158–4188 行：金额或数量为 `null` 时不加入赋值，所以未就绪不会把旧退款额改掉。条件是 `meta_sink_sequence < :sinkSequence`，相同序号不能更新。

## 重复、乱序、回灌

订单金额的 CORE 更新不会用空值擦掉旧值，所以坏报文变成 `null` 时看起来像“没更新”。营业额相反，未知会清空。

退款实例归并里，更小的 `sourceVersion` 标成过期，不覆盖新值。见 `CanonicalOrderReducer.mergeRefundInstances` 1675–1676 行。这是归并层，不是 Doris `COALESCE`。

回灌同一不可变事件要同时匹配事件号和原文 SHA，1682–1684 行。普通重复事件不能借这条改退款。

结论：空值语义不一致。订单头多数金额的 `null` 是“不改旧值”；营业额的 `null` 是“清空”；商品首次插入的退款额 `null` 会变成 0。等级：代码已确认。生产上是否已经出现占位 0，本轮没有抽样。
