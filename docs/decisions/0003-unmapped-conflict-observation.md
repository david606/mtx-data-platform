# 0003. 未识别金额与冲突金额的观测处理

- 状态：已接受
- 日期：2026-11-24
- 范围：`UNMAPPED` 与 `CONFLICT` 观测的保存、冲突决定的不可变，以及新快照和历史观测的关系。不包含标准化算法、计算规则、表结构或新的执行状态。

## 决策背景

金额匹配会得到未命中和冲突两类执行结果。若把它们当成可覆盖的临时状态，或者在运行时从多个候选里选一个类型，历史报文的匹配结果就无法复现。06-03-03-05 需要一条独立的决策记录，避免这些边界只留在调查文档里。

## 决策内容

1. `UNMAPPED` 和 `CONFLICT` 都保存当次 `ObservedAmount`。未识别观测和冲突观测都保留，不丢弃，也不改写成另一种执行结果。
2. 运行时不从多个冲突候选中选择类型、语义或证据。`CONFLICT` 的 `proposedType` 为空，不写成 `MAPPED`。
3. `MappingConflictDecision` 创建后不可修改。封存后的候选版本也不能追加证据。正文或证据要变化时，另建一条决定。
4. 审核通过只表示 `APPROVED`。它不产生快照，也不让映射生效。
5. 发布新快照不修改旧快照，也不修改已经写下的历史观测。
6. 不按订单号或原文自动重放历史观测。只有另一次任务固定另一份快照时，才可以新建观测。

## 决策约束

- 执行状态仍只有 `MAPPED`、`UNMAPPED`、`CONFLICT`。
- 新决定的窗口沿用 06-03-02-03 已有的左闭右开规则。窗口重叠时发布失败，不另设覆盖规则。
- `CONFLICT` 不生成 `NormalizedAmount`，也不进入 `AmountCalculation`。
- 本决策不激活标准金额类型，不发布生产映射，不新增 Maven 模块。
- 字段赋值和封存后的处理细节以 `docs/investigation/round-01/06-03/06-03-03-05 MTX Data Platform V2 未识别金额与冲突金额处理设计.md` 为准。
