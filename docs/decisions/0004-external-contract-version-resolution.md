# 0004. 外部契约版本解析与金额提取前置规则

- 状态：Accepted（已接受）
- 日期：2026-11-24
- 范围：在已经固定的金额映射快照内，于金额路径提取之前解析外部契约版本。不包含表结构、索引、事务、Java 实现，也不新增执行状态或错误码。

本记录已接受方案 C。本次不修改 06-03-02-03、06-03-03-01、06-03-03-03 和 06-03-03-06。那些文件中的旧条款尚未按本决策修订。

## 背景与问题

同一契约家族里，外部版本号可以重复。官方没有版本号时，外部版本号写“未提供”。内部唯一身份是 `contractVersionId`。金额路径清单属于某一份已封存契约版本正文。

Worker 先把 `snapshotId` 固定在任务上，再在这份快照内定位内部修订。当报文只带外部版本号，而当前快照内对应修订不是恰好一个时，现有文档对结果不一致：一份写成 `UNMAPPED`，一份写成提取阻断，匹配引擎则拒绝在版本未确定时启动。

没有唯一的 `contractVersionId`，就没有一份可校验的路径清单，也不能形成带具体 `fieldPath` 的字段结果。观测身份是 `rawPayloadRef + snapshotId + contractVersionId + fieldPath`。用 `UNMAPPED` 表示“修订没有唯一确定”，会把契约解析失败写成字段映射未命中。

调查依据是 [06-03-R12 外部契约版本解析规则冲突专项分析](../investigation/round-01/06-03/06-03-R12%20外部契约版本解析规则冲突专项分析.md)。该报告的核对基线是 `f8b0ec042a61fee8b271bcdaba28d0f3e20778b0`，报告提交是 `e9228ad2b9ec4cd0c2f7f99c02de01f16a8f62b0`。

## 约束与决策驱动因素

- 原始报文一旦保存就保留。解析失败不删除原文。
- 新任务第一次开始时沿用 06-03-02-03 第 14 节已写的快照选择：读取没有子批次的最新已发布快照，校验通过后才写入 `snapshotId`。本草案不另设选择条件。
- 原任务重试继续使用该任务已经固定的 `snapshotId`。显式重放是另一个任务，不复用原任务的身份和幂等键。
- 不猜测最新修订，也不在多个“未提供”中挑选一个。
- 金额路径清单只有在唯一契约版本确定并且正文校验通过后才能读取。`CONTRACT_PATHS_EMPTY` 是已确定版本上的空清单，不是版本未解析。
- 观测身份保持 `rawPayloadRef + snapshotId + contractVersionId + fieldPath`。解析器版本不进入观测身份。
- 执行状态仍只有 `MAPPED`、`UNMAPPED`、`CONFLICT`。不新增状态。
- ADR-0003 继续规定已经形成的 `UNMAPPED` 与 `CONFLICT` 观测如何保存。本草案不改变那些已形成观测的保存、不可变和重放规则。
- ADR-0002 的模块边界不变。不新增模块。Pipeline 不因此依赖 Connector、Transform、Quality 或 Writer 的实现。
- 不新增错误码。

## 候选方案

### 方案 A：不能唯一解析就阻断

零个和多个对应修订都使用已有的 `CONTRACT_VERSION_UNRESOLVED`。不产生字段结果，不产生观测。原文和已固定的 `snapshotId` 保留。

历史重放稳定，因为失败没有观测身份可供以后的新修订改写。不会生成错误的 `ObservedAmount`。错误留在任务级。并发 Worker 不会各自按不同修订写观测。提取尚未开始，解析器版本管理不受影响。

代价是必须改 06-03-02-03 里把该结果写成 `UNMAPPED` 的条款。方案 A 没有单独写明解析发生在匹配之前。

### 方案 B：不能唯一解析就 UNMAPPED

这是 06-03-02-03 第 8 节第 2 步的现有写法。

没有路径清单就没有具体 `fieldPath`。写出观测会缺少契约版本或路径，重放不能稳定命中同一条记录。若先猜一个修订再写观测，会生成错误的 `ObservedAmount`。快照虽然固定，解析失败却被写成字段未命中。多个 Worker 在后来补入新修订后还可能写出不同结果。

方案 B 不能同时满足路径清单、观测身份和重放稳定。

### 方案 C：提取前解析，匹配只接受已确定版本

在快照装载通过之后、金额路径提取之前解析内部版本。恰好一个对应修订才进入提取。不能唯一确定时，提取阻断，码使用已有的 `CONTRACT_VERSION_UNRESOLVED`。匹配保持现有前置条件：没有已确定版本就不启动，不补造 `UNMAPPED`。

业务结果与方案 A 相同。方案 C 额外固定阶段，并让匹配引擎只处理提取成功的输入。06-03-03-01 已有的重放、哈希和空路径规则保持不变。

不采用另外两种做法：不新增“版本未解析”执行状态；不在匹配阶段再做一次外部版本选择。

## 决策

已接受方案 C。三份冻结设计文档本次保持原样，其中的旧句子尚未同步。下列规则是本决策的内容。

### snapshotId 固定规则

本草案沿用 06-03-02-03 第 14 节已经写明的选择，不修改它。新任务第一次开始时，读取没有子批次的最新已发布快照，先做该节的完整性校验，通过后再把 `snapshotId` 写入任务。校验失败停止该任务，不改读另一份快照，不跳过损坏部分，不回写修复。

原任务一旦写下 `snapshotId`，重试只使用这个标识。发布更新的快照不改变原任务的选择。

06-03-02-03 第 8 节把迟到报文写成“固定当时最新的快照”，第 14 节又写成“当时最新且校验通过的快照”。这两句与“没有子批次的最新已发布快照”是否完全同义，以及校验失败时能否跳过该叶子快照，本文不决定，记在文末待决事项。本草案不把其中任何一种改写当作新的选择规则。

### contractVersionId 输入优先级

1. 接入端已经给出 `contractVersionId` 时，直接采用该值作为候选，不再用外部版本号在多个修订中选择。
2. 没有给出时，才在该 `snapshotId` 的契约条目内，按契约家族和外部版本号查找修订。报文写“未提供”时，只与外部版本号同为“未提供”的修订比较。
3. 外部版本号字符串在候选确定后只用于核对版本行。它不负责消解多个内部修订。

### 零个、一个、多个修订

查找发生在当前固定快照内。

- 恰好一个对应修订：确定该 `contractVersionId`。
- 零个对应修订：阻断，码为 `CONTRACT_VERSION_UNRESOLVED`。
- 多个对应修订：阻断，同一错误码。多个“未提供”属于多个，不单独改用另一种结果。
- 任何一种不能唯一确定的情况都不猜最新修订。

### 契约家族身份校验

被采用的 `contractVersionId` 必须属于当前 `snapshotId` 的契约条目。版本表里仍有、但条目里没有的版本不能执行，结果是 `CONTRACT_VERSION_UNRESOLVED`。

候选属于当前快照，但接入来源的契约家族身份或 `contractId` 与该版本行不一致时，结果是 `CONTRACT_IDENTITY_MISMATCH`。该码不在多个修订中做选择。

### 外部版本号一致性校验

候选版本行上的外部版本号必须等于报文给出的外部版本号，包括双方都是“未提供”。不一致时使用 `CONTRACT_IDENTITY_MISMATCH`，不改选另一条修订。

### 正文哈希校验

候选版本的正文哈希必须与封存值一致。不一致时使用 `CONTRACT_VERSION_HASH_MISMATCH`。已经读到的部分路径不得继续使用。哈希校验不能代替“零个或多个修订”的解析。

### 提取阻断边界

`CONTRACT_VERSION_UNRESOLVED`、`CONTRACT_IDENTITY_MISMATCH` 和 `CONTRACT_VERSION_HASH_MISMATCH` 都发生在金额路径提取之前。三者都不产生字段结果，都不产生 `ObservedAmount`。任务阻断。原文保留。

只有候选唯一、条目一致、家族身份一致、外部版本号一致并且正文哈希通过之后，才读取该版本的路径清单。`CONTRACT_PATHS_READY` 才按路径提取。`CONTRACT_PATHS_EMPTY` 仍是成功的空字段结果。

### UNMAPPED 的适用范围

`UNMAPPED` 只用于契约版本已经确定、路径清单已经读出、并且具体路径 `fieldCode = OK` 之后的匹配结果：没有命中窗口，或唯一命中的资格是 `ALLOWED_AS_UNIDENTIFIED`。

版本尚未确定时，不允许产生 `UNMAPPED` 观测。ADR-0003 对已经形成的未识别观测和冲突观测仍然有效。

### 历史重放与重试

原任务重试和显式重放使用不同的任务身份，也使用不同的幂等语义。原任务重试不创建新任务，不更换 `snapshotId`，不生成重放任务。显式重放不复用原任务的任务身份和幂等键，也不把一次重试写成另一次重放。

临时性读取或加载失败是指快照或契约版本的读取没有完成，查找本身还没有得出零个、一个或多个修订。允许在原任务、原 `snapshotId` 下再次读取和解析。再次读取仍不改用最新快照。

确定性解析失败是指查找已经在该固定快照内完成，且对应修订是零个或多个。结果是 `CONTRACT_VERSION_UNRESOLVED`，没有字段结果，也没有观测。已经完成的家族身份不一致和正文哈希不符同样是确定性失败，分别仍用 `CONTRACT_IDENTITY_MISMATCH` 和 `CONTRACT_VERSION_HASH_MISMATCH`。这些失败不得因为反复重试而变成成功，也不得因此切换最新快照。原任务上已经保存的 `contractVersionId` 继续沿用，并在同一快照内重新校验正文。后来新增的修订不回写原任务。

修正配置并发布新快照后，原任务仍不自动恢复。若要按新配置重新处理已保存的原始报文，必须另建显式重放任务。不按订单号或原文自动创建该任务。新任务在第一次开始时按本节的快照选择规则固定快照。新快照已经成为没有子批次的最新已发布快照时，这次新任务固定的就是该新快照。新任务的观测遵守 ADR-0003：观测身份仍是 `rawPayloadRef + snapshotId + contractVersionId + fieldPath`，新快照形成新的观测，不覆盖原任务已经写下的观测，也不修改旧快照。重复提交同一次显式重放不得再创建另一个任务。本草案不规定重放请求号的生成算法。

## 对已有错误码的影响

| 错误码 | 本草案中的使用 | 是否新码 |
| --- | --- | --- |
| `CONTRACT_VERSION_UNRESOLVED` | 零个修订、多个修订，以及 `contractVersionId` 不在当前快照契约条目中 | 否。只明确零个修订与多个修订使用同一已有码 |
| `CONTRACT_IDENTITY_MISMATCH` | 家族身份、`contractId` 或外部版本号字符串与所选版本行不一致 | 否 |
| `CONTRACT_VERSION_HASH_MISMATCH` | 已经定位到一条版本，但正文哈希不符 | 否 |

三个码覆盖本草案的失败场景。不新增错误码。

## 对 Pipeline、Java 实现和存储设计的影响

Pipeline 仍先固定快照，再在该快照内解析契约版本，解析成功后才提取。解析失败停留在快照已固定，不进入提取，不写观测。本决策不改变 06-03-03-06 里已经写明的两阶段上下文、观测身份、阻断身份和终态规则。该文件尚未按本决策删除“尚未统一”的暂缓句，本次也不修改它。

Java 实现和存储设计仍要等到冻结文档完成对应修订之后。存储需要区分原任务和显式重放任务，并让临时性读取失败能按原任务、原 `snapshotId` 再读。确定性解析失败不能靠更换快照或重复调用变成成功，也不能为未解析版本预留没有路径的 `UNMAPPED` 行。本文不规定表、索引、事务或锁。解析器版本在提取开始之后才有意义，不能用来选择契约修订。

## 风险与后果

- 决策已接受，三份设计文档仍未修订，旧句子继续存在。实现不得把尚未同步的旧条款单独当成已经更新的契约。
- 接受后，06-03-02-03 的 `UNMAPPED` 句子必须同步修改，否则运行规则和配置文档继续分叉。
- 把解析失败留在任务级，会使原本可能被写成未识别金额的报文变为任务阻断。这是为了避免错误观测，不是字段级未命中。
- 零个修订在 06-03-03-01 第 9 节尚未成行。后续修订必须补上，避免实现只处理“多个修订”。
- 本草案不决定物理幂等机制。并发 Worker 仍不得为同一次未解析尝试写入不同修订的观测。
- 原任务的确定性解析失败在新快照发布后仍保持失败。若实现把原任务重试自动改到新快照，就会绕过 ADR-0003 的显式重放边界。
- 06-03-02-03 第 8 节和第 14 节对“最新快照”的用词并不完全相同。在该项待决关闭前，不能把其中一句改写成另一句。

## 验收标准

设计文档尚未修订。下列检查尚未执行，不能写成已经通过。

- 外部版本明确且当前快照内恰好一个对应修订：确定该版本，校验通过后才提取。
- 外部版本明确但零个对应修订：`CONTRACT_VERSION_UNRESOLVED`，无字段结果，无观测，原文仍在。
- 外部版本未提供且恰好一个“未提供”修订：确定该版本。
- 外部版本未提供且零个或若干个对应修订：同一阻断码，不猜最新，不写 `UNMAPPED`。
- 接入端给出的 `contractVersionId` 属于当前快照、家族身份和外部版本号一致、哈希通过：按该版本提取。
- 该 ID 不在当前快照条目中：`CONTRACT_VERSION_UNRESOLVED`。
- 家族身份或外部版本号不一致：`CONTRACT_IDENTITY_MISMATCH`。
- 正文哈希不符：`CONTRACT_VERSION_HASH_MISMATCH`，不使用部分路径。
- 原任务遇到临时性读取或加载失败时，仍用原任务和原 `snapshotId` 重试，不改读最新快照。
- 原任务在固定快照中得到零个或多个修订时，结果保持 `CONTRACT_VERSION_UNRESOLVED`。反复重试不变为成功，也不切换快照。
- 修正配置并发布新快照后，原任务不自动恢复。重新处理必须创建显式重放任务。新任务固定当时没有子批次的最新已发布快照，并按 ADR-0003 另建观测，不覆盖原观测。
- 原任务重试与显式重放的任务身份和幂等键不相同。同一次显式重放的重复提交不创建第二个任务。
- 观测身份仍是原来的四段。没有新增执行状态或错误码。

## 待决事项

- 06-03-02-03 第 14 节要求新任务读取没有子批次的最新已发布快照，校验失败后不得改用另一份。同文件第 8 节写“当时最新的快照”，第 14 节的迟到报文句写“当时最新且校验通过的快照”。本草案只沿用第 14 节新任务那一句，不把这三句的差异收成一条新规则。校验失败时是停止任务，还是可以改选另一份已经通过校验的快照，仍待单独决定。
- 显式重放请求号如何生成，不在本草案中决定。决定前不得把它写成观测身份的新字段。
